# 联机传输审阅

日期：2026-10-23

检查从房主生成数据到客户端实际显示的完整流程，包含建卡、公开输入、个人叙述、现场状态、图片、分发材料、战斗与追逐选择，以及断线重连。使用本地真实 WebSocket、终端界面操作和故障注入，未调用付费模型。

## 已确认并修复

| 问题 | 实际影响 | 处理 |
| --- | --- | --- |
| 建卡生成背景问题后没有回传更新后的图片列表 | 房主搜到图片，玩家仍显示无照片 | 同步人物资料、候选图片和搜索错误；界面重新读取最新结果，已随 0.0.5.4 发布 |
| 建卡并发取图与房主逐步接口冲突 | 后几张预览被拒绝；换人可能沿用旧缓存 | 顺序下载，按图片来源区分缓存，替换上传图片时清理旧预览，已随 0.0.5.4 发布 |
| 客户端收到状态或模组更新后没有刷新场景 | 位置已经改变，画面仍在原地；天气、在场头像和现场改写滞后 | 状态与模组更新都刷新当前场景；保持显式镜头选择，地点变化时更新镜头 |
| 天气、在场人物等事件没有附随后续状态更新 | 客户端处理事件时仍使用旧状态 | 在相关事件后发送按座位生成的状态快照 |
| 图片是否已发送只比较路径 | 同一路径重新绘制后，其他玩家继续看到旧图 | 比较实际传输图片的摘要；内容变化重新发送，内容相同仍去重 |
| 消息处理异常会静默结束接收任务 | 连接界面看似正常，后续消息不再出现 | 记录错误、关闭失效连接并明确提示重新加入；服务器保留已接收的行动和待答选择 |
| 断线后的发送被直接忽略 | 输入框清空，却没有真正发出；建卡可能一直等待回复 | 明确返回未发送状态，保留原文；恢复私信时保留 `/sc` 或 `/w` 前缀，建卡不再无限等待 |
| 新地点资料与状态分别抵达 | 在两份数据配齐前读取未知地点可能使接收任务中断 | 客户端暂存未配齐的数据，地点资料与状态能够相互对应时再显示；两种抵达顺序都测试 |
| 结局后的命令仍沿用旧的个人回显路径 | 与普通输入默认公开的约定不一致 | 统一使用公开玩家消息流程；私信继续走独立通道 |

## 保持的接收范围

普通玩家输入向全桌公开；公开交流记录单独保存，不自动成为异地角色的知识。KP 私信、同伴私语、个人叙述、材料及个人战斗选择继续按实际接收者发送。状态同步使用每个座位自己的视图，保留角色数值共享。

回归检查覆盖队列保存与撤回、断线重新入座、待答检定恢复、战斗与追逐个人视图、私信与附件交错发送、图片传输及重新连接后的材料恢复。旧测试中“普通声明仅本人可见”的预期已按新的产品约定修正。

## 验证范围与后续

主要回归入口是 `tests/test_net_snapshot_refresh.py`、`tests/test_link_failures.py`、`tests/test_multiplayer_transport.py`，并运行现有联机、个人视图、分场、材料、建卡和房间测试。

最终结果：260 项联机相关测试通过；Windows 原生 PowerShell 5.1 与 Bash 的 23 项安装脚本测试通过。游玩传输修复发布在 0.0.5.5。

本轮没有进行真实跨公网、无线弱网或电脑休眠后的长时间验收。发送失败会明确提示；对于已写入本机网络缓冲、但尚未收到房主确认的输入，不自动重发。重连后应以房主恢复的行动队列和待答选择为准，避免重复提交已经受理的操作。

另修复 Windows 安装入口：GitHub 发行接口不可用时，默认安装流程改从 PyPI 查询明确的正式版本，并保留原始失败原因；显式指定 GitHub 来源时不会擅自更换来源。该修改位于安装脚本，无需等待 Python 包升级。
