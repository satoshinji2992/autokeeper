## 安装

新版安装包正在准备中，暂时无法安装；发布后这里会给出 Windows、macOS 和 Linux 的安装命令。只加入朋友的房间时，用浏览器打开房间网址即可，不用安装。

### 东西放在哪

| | Linux、macOS | Windows |
|---|---|---|
| 设置和 API Key（`config.toml`、`.env`，只有你能读） | `~/.config/autokeeper/` | `%APPDATA%\autokeeper\` |
| 存档、角色卡、导入的模组 | `~/.local/share/autokeeper/` | `%LOCALAPPDATA%\autokeeper\` |
| 缓存（本地模型、知识库、图片，可以删） | `~/.cache/autokeeper/` | `%LOCALAPPDATA%\autokeeper\Cache\` |
| 导出的角色卡 | `~/Documents/AutoKeeper/角色卡导出/` | 「文档」里的 `AutoKeeper\角色卡导出\` |

Linux 和 macOS 上设置了 `XDG_CONFIG_HOME`、`XDG_DATA_HOME`、`XDG_CACHE_HOME` 的话，按它们来。`autokeeper doctor` 会列出存档和设置的位置。想把所有东西放在一个文件夹里，设置 `AUTOKEEPER_HOME`。

## 模型与花费

默认使用本机的 Claude Code 登录，也可以设置 `ANTHROPIC_API_KEY`。DeepSeek 需要 `DEEPSEEK_API_KEY`。不同终端设置环境变量的写法如下，把示例内容换成自己的密钥：

```bash
# bash / zsh
export DEEPSEEK_API_KEY="你的密钥"
```

```fish
# fish
set -gx DEEPSEEK_API_KEY "你的密钥"
```

```powershell
# PowerShell
$env:DEEPSEEK_API_KEY = "你的密钥"
```

使用 Anthropic API 时，变量名改成 `ANTHROPIC_API_KEY`。`autokeeper login` 会把密钥存进设置文件夹里的 `.env`；也可以放进当前目录的 `.env`，不要提交到 Git。

```bash
autokeeper --preset deepseek
autokeeper --model codex:default
autokeeper --model ollama:qwen3:14b --search none
```

Codex 使用本机已登录的 CLI；Ollama 需要提前下载指定模型。标题页的「设置」和游戏中的 F9 可以换模型、备用模型、思考模式；导入界面还能为本次导入单独指定模型与读图模型。设置会保存。更细的分工写在 `~/.config/autokeeper/config.toml`，写法见 [autokeeper.toml.example](../autokeeper.toml.example)。

费用和订阅额度由所选服务计算。Ctrl+B 查看本局用量和估算花费，分别列出含缓存的总输入、缓存读取与未命中缓存输入；总输入不能直接当作新增计费量。未标价模型可能没有金额估算，这里的数字也不是服务商账单。上下文、回合数、模型和配图都会影响消耗。

```bash
# 主模型不可用时，尝试本地备用模型
autokeeper --preset deepseek --fallback ollama:qwen3:14b

# 给模型调用设置 5 美元的估算预算
autokeeper --preset deepseek --budget 5
```

`--mode 高级剧情` 提高叙事相关角色的思考强度，`--mode 经济` 降低思考强度；效果和速度取决于模型。叙事已经开始输出时不会中途换到备用模型，避免重讲一遍；出错后用 `/retry` 继续。

### 离线游玩

提前安装依赖、下载 Ollama 模型；把所有使用的模型角色都设为本地模型，关闭搜索（`--search none`）和设置中的「AI 画图」。已有图片与字符画仍可显示，联网找照片和云端模型不可用。

## 操作

叙述和 NPC 台词右下角的圆形加号（㊉）悬停时变色并显示「加入笔记」。点击后可修改名称，默认「笔记1、笔记2……」，原文保留人物称呼与换行；流式叙述完成后才显示该按钮。联机时沿用个人笔记的保存方式，内容不向队友发送。

启动终端界面用 `autokeeper`；浏览器界面用 `autokeeper serve`。在标题页选「新的调查」，选模组、调查员和同伴即可开局。开局先播放一小段开局演出，介绍故事背景，按任意键看下一幕、Esc 跳过；演出结束后守秘人开始讲开场。用自然语言描述行动或直接说话，不必先记指令。需要检定时，界面会请你掷骰；守秘人讲的时候也能先输入行动，讲完自动交上。

网页端可在「设置 → 字体大小」选择字号，保存后即时生效，仅保存在当前浏览器。原生终端的字号由终端设置控制；Windows Terminal 可使用 Ctrl+滚轮。

| 按键 | 作用 |
|---|---|
| F1 | 玩法说明 |
| F2 / F3 / F4 | 笔记与资料 / 地图 / 人物卡 |
| F5 | 提供三个可修改的行动思路 |
| F6 | 重讲最新一段，保留已经结算的骰子和结果 |
| F7 或 Ctrl+R | 前情回顾 |
| F8 | 手绘 |
| F9 | 模型设置：「模型方案」页选用哪家、填 API Key、思考强度；「各分工模型」页给守秘人、裁定、导演等单独指定模型（标题页也是 F9） |
| F10 | 结局后复盘 |
| F12 | 开发者模式：顶栏变色，叙述下方显示本轮调用、检定、人物实际位置和接下来的日程；再按一次退出。也可在 Esc 菜单 → 设置里开关。联机时只有房主可用 |
| Ctrl+S | 存档 |
| Ctrl+A / Ctrl+T | 换画法 / 换配色 |
| Ctrl+O | 叙事偏好：篇幅、节奏、恐怖程度与略去的细节 |
| Ctrl+B | 用量与估算花费 |
| Ctrl+G / Ctrl+Y | 整页打开「经过 / 进展 / 背景」 / 现在整理进展 |
| Ctrl+L | 灵感检定（也可输入 `/灵感`） |
| Ctrl+N | 收起或展开画面，留出读故事的地方；战斗与追逐中第二次收起选单，第三次全部展开 |
| Tab | 补全输入框里的技能名；战斗与追逐中切换被攻击时的应对 |
| Esc | 菜单：继续、存档、读档、玩法说明（含按键说明）、回到标题、退出游戏、设置。换模型、叙事偏好和开发者模式在「设置」里 |

| 输入 | 作用 |
|---|---|
| `.ra 侦查`、`.rab 恐吓` | 提议使用技能，守秘人仍会按情境决定是否检定与难度；失败的同一次尝试不能随意重掷 |
| `.r 1d6+1`、`.coc`、`.st` | 掷骰 / 掷一组属性 / 查看人物卡 |
| `.en` | 结局后做成长检定，每局一次 |
| `/kp 问题` | 直接对守秘人说，用于提问或澄清；不作为角色发言、不检定、不推进时间。其余输入由守秘人判断是行动还是场外提问 |
| `/sc`、`/sc 正文` | 私密交互：单独输入打开收件人和正文窗口；带正文时正常处理，只隐藏输入与专属回复 |
| `“话”`、`（动作）“话”`、`对某某说……`、`对大家说……` | 有同伴时对同伴说话，某某是调查员的名字：直接显示并记入记录，守秘人不回应，不占行动、不推进时间。对 NPC 说话写成 `对守钟人说……` 或直接描述 |
| `//话`、`((话))`、`（（话））` | 场外聊天，不记入游戏。单个括号开头的话仍是角色的行动 |
| `/记 内容` | 把这一行记到笔记末尾，不占行动、不推进时间，守秘人讲述时也能用 |
| `/灵感` | 灵感检定，见下文 |
| `/retry` | 从中断的阶段继续，保留已结算的结果和 NPC 回答 |

浏览器会占用部分功能键，例如 F5 刷新。可点击底栏、Esc 菜单，或输入 `/suggest`、`/sheet`、`/notes`、`/map`、`/help`。刷新网页后，联机玩家需要重新入座。

### 孤注一掷与灵感检定

检定失败后可以孤注一掷、花幸运或放弃。选择孤注一掷时要写明调查员如何行动（多花时间、加倍努力或冒更大的险）。裁定员据此复核：这样做达不到目标时不掷骰，按放弃处理；做法要花的时间先过去，再掷第二次。普通的失败通常只是没做成，更严重的后果留给孤注一掷再失败。

调查陷入僵局时可以做灵感检定（Ctrl+L 或 `/灵感`）。引擎选出调查员遗漏的最关键线索，由智力最高的调查员掷智力；线索此前没出现过是常规难度，提到过是困难，反复提起或玩家讨论过是极难。成功时守秘人把调查员想到的内容写进叙述；失败时同样会想到，但时间流逝，调查员被直接带进他们能意识到的最糟局面。每个游戏日限一次；长时间没有进展时，守秘人会主动提议，这一次不受限制。没有遗漏的线索时会直接说明。

### 线索与笔记

找到的线索不会以卡片或清单显示。查到的东西由守秘人在叙述里讲出，NPC 知道的事由 NPC 在台词里亲口说出；检定结果下只写「有所发现」或谁松了口。信件、日记、地图这类手稿照常弹出原文，之后在笔记的「资料」页重看。引擎仍然记录找到了哪些线索，前置条件、灵感检定、导演安排和结局照常判断；结局后的复盘会列出找到和遗漏的线索。

按 F2 打开笔记：「笔记」页自由书写，Esc 或再按 F2 保存并关闭，Tab 翻到「资料」页。在输入框输入 `/记 内容` 可把一行记到笔记末尾。右栏显示笔记的开头几行，读档列表的预览里也有。本地游戏的笔记随存档保存；联机时每位玩家的笔记只保存在自己的电脑上，见[联机](#联机)。观战时没有笔记。

### 人物、记录和画面

向上翻阅叙述时，新消息不会把画面拉到底部。底部出现「有新内容」后，点击提示或按 `Ctrl+End` 回到最新；停在底部时会继续跟随更新。右侧「经过」也保留手动滚动的位置。

标题页「角色卡」只管理自己创建或主动导入的人物卡，支持 AI 协助车卡、导入、导出和删除。已有卡片可编辑名字与背景等文字，不能直接修改数值。存档中的调查员留在各自游戏中，可在游戏内查看人物卡与本局经历；模组预设仍可在开局时选择。

「继续调查」列出模组、调查员、时间、地点与回合数，可以预览、改名、复制或删除。删除的存档和角色卡放进 `data/games/trash/`。

右栏显示「经过」，按行动列出记录，点一下可以跳到对应叙述。点「经过」的标题或按 Ctrl+G，整页打开经过、进展和背景：「进展」在有新发现时后台整理，两次至少隔六轮，有新内容时标题上写「进展·新」；「背景」保留开场时知道的事。手稿按种类排版：信件、日记与病历、报纸与告示、电报、典籍各有纸色和格式；有原件扫描的，点「查看原件」在游戏里全屏看，或用系统程序打开（网页版下载）。地图只画已知地点和道路，可展开内部地点；选中地点按 G，会在输入框里写好前往那里的行动。有平面图的建筑里打开地图时直接显示室内平面图：房间、门和楼梯，以及每间里的人；在全局地图上选中这样的建筑，按回车、再点一下它或点「进入平面图」进入；地图下方的按钮可以返回全局地图、换楼层、前往选中处，也可以按 P 切换，`[` `]` 或 PageUp / PageDown 换楼层。只显示到过的房间和从门口看得见的房间，没进去过的标“？”，未发现的暗室不会出现。地图同时标注队友位置和 NPC 的目击记录，`※` 表示最后目击或已离开，选中地点可查看详情。联机时打开的地图会随房间同步更新；未知地点不因队友到访而自动揭示。

有头像的 NPC，其对白前附字符头像，旧对白与重连后的记录也保留当时的头像。没有头像或仅通过电话交谈时，正常显示姓名和台词。

默认用块字符画显示照片，Ctrl+A 或设置里的「画面风格」可切换点阵、速写、轮廓线、细块字符和纯 ASCII。点阵和速写用盲文点字符，细块字符用六分块字符，字体不支持时会显示成方框。终端窄于 96 列时，右栏自动隐藏；不支持真彩的终端会降为 256 色。使用支持真彩和中文等宽显示的终端，画面会更清楚。

即兴配图在后台准备，先显示简图或已有画面，完成后更新。开场、危机、关键地点等时刻可显示整屏「大场景」，按键、点击或八秒后收起，掷骰时让路；图片没准备好就跳过。两种配图都可以在设置中关闭。

### 配乐

配乐随剧情实时生成：守秘人在叙述氛围变化时给出一个配乐意图（日常、悬疑、不安、恐怖、紧迫、悲伤、震撼、余波，强度三档，可附惊吓、骤停或揭示），战斗和追逐、理智损失由游戏直接处理，室外与夜晚也会改变音色。每局的调性和主题各不相同；同一场景里每隔几个乐句换一次主奏乐器、节奏和变奏，弦乐、合唱、钢琴、竖琴、八音盒、管风琴、玻璃琴、长笛、单簧管、大提琴、圆号、尼龙吉他、马林巴、铜管、风声与各种鼓轮流出现，本局较少用到的乐器优先；震撼和恐怖的段落里会有男声的仪式吟唱与女声应和，悲伤时有女声无词哼唱，不安时偶有耳语。节拍借鉴数学摇滚：除 4/4 外还有 7/8、5/8、5/4、7/4 等，重音按 2+2+3、3+3+2 这样的分组落下，紧张段落里还有跨小节循环的固定音型。舒缓的段落有时带摇摆，每个音的时值和力度都有细微出入，像真人演奏。音乐在下一小节承接变化，不重新开曲；回忆、否定和人物谎言不改变配乐。私密遭遇只影响本人的配乐。这些意图随守秘人原有的叙述一起给出，不额外调用模型。

终端版直接从本机声卡播放，「设置 → 配乐」可选关闭、轻、适中、较响，默认为适中，选择会保存。标题画面有自己的配乐，进入游戏后换成本局的配乐。Windows、macOS 和 64 位 Linux（含 WSL）支持终端配乐，其他系统可用网页版。网页端（`autokeeper serve`、联机房间的网页）在页面里播放，第一次按键或点击后开始发声；音量只保存在当前浏览器，默认为适中。

「AI 画图」需要本机安装并登录 Codex，按参考图或描述生成，并随剧情重画明显变化的地点和人物。上限是每个模组 100 张、每局 12 张；生成也会消耗相应服务的额度。`doctor` 会显示是否可用，故障处理见游戏内玩法说明的「遇到问题」。

## 战斗与追逐

调查员动手攻击，或者对方因为这次行动动手，守秘人判定打起来以后，游戏进入战斗；模组写定的袭击（有人破窗扑进来）到了那一刻也直接打起来，下一步就选这一轮的行动。进入战斗后，面对的对手占满舞台，背后透着血光，心跳一样明暗起伏；被它抓中时爪痕划过画面，整个屏幕溅红摇晃。旁边是行动先后、对手的伤势（只写字样，不给数字）和调查员的生命值。

每一轮按敏捷从高到低结算，拿着能开火的枪的人先动。输入框上方列出可选的行动：攻击（写明武器和伤害）、射击、推倒、缴械、制住、急救、装填、防守、逃跑，回车选定；也可以自己写，守秘人把它读成规则里的一项行动，砸油灯、关门这类事交给裁定员。可以推迟到某人之后再行动；瞄准只用于下一枪。

选单下方一行是被攻击时的应对（闪避、反击，对手有枪时还有扑向掩体），按 Tab 切换，不占用行动。第一次被攻击、设定的应对不适用于这次攻击（对方开枪而设定的是反击）、或者这一击可能造成重伤、击倒或死亡时，游戏停下来询问：窗口写明每种应对掷什么、代价是什么，也可以自己写应对；选的应对沿用到之后。窗口里或设置里勾选「每次被攻击都询问」后，每次都问。

规则按第 7 版：闪避与反击、以多打少的奖励骰；射击按距离、抵近、瞄准、掩体等修正，朝扭打中的人开枪带惩罚骰，子弹会用完、枪会卡壳；推倒、缴械、制住等战技，体格差带来惩罚骰；极难成功的最大伤害与贯穿；重伤的体质检定，濒死每轮的体质检定，急救和医学。怪物的护甲、枪伤减半、每轮自愈照模组资料执行，调查员看得见时写进叙述，不给数字。对手和怪物的行动由守秘人安排，它们只按自己察觉得到的行动：躲在掩体后、躲藏成功或被跟丢的人，它们攻击不到也追不上。第一次看见怪物时，它先占满整个屏幕，再过理智检定。打完以后，伤势、死亡、弹药和掉落的武器记进世界记录，模组里因此成立的剧情标记（比如某人被打倒、调查员逃走）随之触发。

逃跑或追赶时进入追逐，路线就是地图上的路：模组写了追逐路线的照路线跑，没写的沿地点之间的出口跑；跑进另一个地点，人就到了那里。开始时每人过一次体质定速度，比所有追兵都快就直接脱身。每轮按敏捷行动，行动点按速度差计算：跑一处花 1 点；险阻（⚠，边跑边过）可以多花行动点小心通过，失败失去 1D3 行动点，可能受伤；路障（▦）要用某种办法过去，打开的门对后来的人一直开着，有耐久的可以砸开。攻击只能打同一处的人，枪除外；停下射击花 1 行动点，边跑边射多一颗惩罚骰。随时可以躲藏；逃出视线后追兵过追踪或侦查，失败就跟丢了。有人回身迎战、逃离者被制住或倒在追兵面前时转为战斗，之后有人再逃又转回追逐；对手逃跑后的下一轮可以选「追赶」。

追逐时场景变冷变暗、向后掠过，追兵离得越近画得越大。舞台右侧是从最后的追兵到最前的逃离者、再到出口的一条路：每处的名字、上面的险阻或路障、出口（⇡）、谁在哪里和这一轮跑过的痕迹；看不到的前方写「前方：尚未看清」。下方是各人的速度和这一轮的行动点。

战斗与追逐中故事区保留约四成高度；Ctrl+N 收起画面，再按一次收起选单。单人游戏可在 Esc 菜单 → 设置里打开「战斗与追逐限时选择」：战斗20秒、追逐12秒，时间到了战斗中只防守、追逐中选第一项；帮助、人物卡等窗口打开时暂停，手动输入行动时停止。联机不采用此计时。

联机战斗与追逐按回合进行。参与本场遭遇、能够行动的真人玩家提交本轮行动，或在空输入框按回车明确跳过，收齐后再按规则次序结算。阅读和输入没有七秒限制，被攻击时的询问也等待本人回答。断线后的处理取决于开房时的「断线后由 AI 临时接管」选项：默认一分钟后接管；关闭则保留待答选择，等待本人重连。其他地点的调查员不占本场确认名额。突发遭遇前尚未执行的声明会请本人确认、改写或暂缓，不会自动占用新回合。

## 规则书与守秘人卡组

规则书和《克苏鲁的呼唤守秘人卡组》不随游戏提供。手上有的话可以读进游戏，没有时一切照常。它们默认放在数据文件夹里的 `rule/`（Linux、macOS 为 `~/.local/share/autokeeper/rule/`，Windows 为 `%LOCALAPPDATA%\autokeeper\rule\`）。环境变量 `AUTOKEEPER_RULES` 可以换成别的文件夹。读进来的东西都在本机缓存里，不进 Git。

### 规则书检索

```bash
autokeeper rules status           # 查看缺书、未建库、过期或可用状态
autokeeper rules index            # 读入规则书，建本地索引
autokeeper rules search 溺水      # 查看裁定员会拿到哪几段原文
```

也可从标题页或本机主持的游戏「设置 → 规则书与检索索引」选择目录、查看状态并重建。远程加入的玩家不在自己电脑上建立房主的索引。

`rules index` 读取文件夹里的规则书（PDF、Word、Markdown 或文本），在本机建检索索引，不调用语言模型。一般规则按页和章节切分；能识别的法术保留完整条目、名称、英文名、别名和跨页出处。建好以后，裁定员遇到引擎没有实现的规则（溺水、中毒、坠落、火、法术等）时查原文，`/kp` 问规则时也会附上原文，每段注明书名和页码。施法时，裁定员按法术原文把魔法值、POW 与理智值的消耗写进裁定，由引擎扣除（魔法值不足时扣耐久值，魔法值每小时恢复）；学会的法术记在人物卡上。法术的效果仍由守秘人按原文演出。

规则书目录依次取命令的 `--books`、`config.toml` 的 `rulebooks = "规则书文件夹"`、`AUTOKEEPER_RULES`、默认的 `rule/`。装了 `graphrag` 组件时用本地向量检索，否则按字词检索。加了新书再运行一次；`--force` 全部重新读取。建库失败不影响普通游玩；旧索引可用时，不会被没有内容的重建结果覆盖。

### 守秘人卡组

有《克苏鲁的呼唤守秘人卡组》（好事者、恐惧症、惨事、武器四个 PDF，或装着它们的 zip）时，可以读进游戏：

```bash
autokeeper cards import            # 读 rule/ 文件夹里的卡组
autokeeper cards import 卡组.zip   # 也可以写出 zip、PDF 所在目录或单个 PDF
```

每张卡的文字存成结构化数据，卡面存成图片。导入后：

- **恐惧症卡**：调查员陷入不定性疯狂时抽一张恐惧症或躁狂症卡，记进角色卡的「恐惧症和躁狂症」；临时疯狂发作时抽一张发作卡（有同伴在场用即时症状，否则用总结症状；掷到 9、10 改抽恐惧症或躁狂症卡）。卡片弹出显示，可「查看卡面」；守秘人照卡演出，裁定员照卡上的效果给惩罚骰。
- **惨事卡**：孤注一掷再失败、检定失败或过夜休息出了岔子时，裁定员可以选一张。卡上的即时效果（理智检定、损失生命、理智、魔法，幸运减半）由引擎结算，卡片弹出显示，卡面其余内容交给守秘人演出。
- **好事者卡**：导演即兴加人物时可以用一张卡做底子，人物得到卡上的属性、技能与攻击。
- **武器卡**：随其他卡组一起导入，游戏中暂不使用；战斗用规则自带的武器表。

这份卡组的汉化版没有卡图，卡面图片是整张卡的文字面。

## 联机

同一局域网里，房主从标题页「多人游戏 → 开房间」选模组，安排玩家、AI 或不上场的座位；不够就「加一个空座位」。也可以选择联机存档继续。准备房间里有要发给朋友的网址，朋友在浏览器里打开、填名字、挑座位。房主自己也在准备房间入座。

坐下后按 R「选角色」，可用自己的卡、模组预设，或新建、导入。车卡调用房主的模型，朋友不用配置密钥；用终端加入时，车好的卡也会存进自己电脑的「我的角色」。按 Y「准备好了」，全员入座并准备后，由房主点击“开始游戏”；不会自动开局或将未入座玩家交给 AI。开局后只能回到现有座位，不能更换角色；续档沿用原来的调查员。

### 一轮怎么进行

调查与日常中，每位玩家每轮保留一份行动声明。第一人提交后，守秘人开始综合安排；构思期间其他人仍可加入，修改会覆盖自己的原声明，并让守秘人按最新内容重新考虑。输入 `/undo` 撤回未执行的声明，空行回车表示跳过。需要时间填写时，按 `Alt+J`、输入 `/join` 或在命令面板选择「加入本轮」先占位；提交或跳过后才开始讲述。整体安排完成后可以开始结算，但正文或 NPC 台词出现前，尚未提交行动的人仍可加入。此时未展示的草稿会被打断，新行动一起考虑；已结算的动作、骰点不重跑。本人已进入执行的行动不能重复提交或修改。战斗与追逐继续等待参战玩家明确行动或跳过，按规则逐轮处理。

同一现场的守秘人一起考虑行动之间的配合与冲突，再逐项裁定、检定。一份声明可以包含连续意图，由守秘人判断本轮执行到哪里。不同人的独立行动取最长时间。不同地点有各自的构思、时间和待答选择，可以并行调查；同一建筑内共用主持上下文。远处玩家修改声明不会打断本场，影响到本场的人物、物品或事实发生变化时才更新草案。会合时可以略过等待、推进到共同时间。共享人物与物品有争用时，仍按实际记录协调。已显示的 NPC 对话不重复，其他结果在这一轮结束时交代。

普通输入默认公开：提交后全桌玩家与观战者立即看到原文，撤回也会公开标明，不用等守秘人结算。公开消息随存档保存，重连后可查看近期记录。玩家看到异地同伴的声明，不代表自己的调查员或 AI 同伴自动获知异地发生的事；各场叙述和材料仍按接收范围发送。

正文开始发送后，输入框保留行动草稿，叙述结束后由本人提交，不自动排入下一轮。检定回复、队友私语和场外聊天仍可使用。以 `//` 开头或整句用双括号包住是场外聊天，例如 `//我去倒杯水`、`（（我去倒杯水））`，不算行动，观战者也能发；单个括号开头的 `（压低声音）别进那扇门。` 算角色的行动。以引号或「对某某说」「对大家说」开头是对同伴说话：全桌玩家能看到，角色按实际在场情况听见并记入记录，不占行动名额，也不请守秘人回应。点名对某个人说话仍是普通对白。向同伴要东西只是请求，交不交由对方自己行动。

输入 `/sc` 打开独立私信窗口，选择守秘人或同场队友作为收件人；也可从 Ctrl+P 命令面板进入。`/sc 正文` 使用普通主持、裁定和结算流程，输入与专属回复仅本人收到。需要角色行动时照常使用本轮行动资格；实际可观察的移动、交物、损坏与受伤仍向现场玩家交代。私密渠道不会使角色隐身，也不保证行动不被察觉。公开询问 KP 使用 `/kp 内容`，不占行动名额。

用 `/私聊 林秋 别让他看到这封信` 向同场的另一位调查员发送私语，也可用 `/w 角色编号 内容`；姓名含空格时用双引号，例如 `/私聊 "Harold Brennan" 看门外`。收到确认后，双方画面显示发送者、收件人和正文，其他玩家与观战者不显示这条私语；守秘人仍可读取，AI 同伴只知道自己实际听见的内容。私语不会消耗行动，不会自动转交物品，也不能向不在场的人传话。断线后回到原座位，可恢复该角色有权看到的近期记录。

开房页面默认开启「断线后由 AI 临时接管」，也可用 `autokeeper host --no-disconnect-ai` 关闭。断线一分钟内等待重连；超时后，AI 延续原有意图、性格和约定，只依据该角色自己的见闻行动。待掷的骰子继续原检定，应对沿用默认选择；幸运和孤注一掷接受原失败，不额外支出。重连后立即交还控制权，保留已经完成的行动与后果，尚未执行的 AI 提议作废。全员离线时暂停，观战者不会驱动 AI 自行推进。

同一场景的普通叙述和交谈默认广播，调查检定的发现由本人选择是否公布。叙述标为「守秘人·广播」，不会要求队友重复检定；每名玩家的姓名与发言使用固定的不同颜色，分队玩家的发言为灰色。守秘人单独交代给某位调查员的信息标为「守秘人·私密」，例如只有他看见的人影或梦境。这些内容只发给指定角色，不进入大家共用的故事概述。NPC 自报姓名或被明确引见后才显示对应称呼；未通名者以可见特征区分，如「未通名的人（医生）」。NPC 只依据调查员实际自我介绍、原有关系或已获知的消息认识对方，假名按实际说法记录；普通交谈不自动交换姓名。

右上角常驻自己的详细数值及队友简况；点击队友可查看对应人物卡和实时状态。点击输入框上方的「队伍」，或从 Esc 菜单打开「队伍」，也可以集中查看队友的 HP、SAN、MP、幸运、异常状态、所在地点和本轮行动提交情况。面板实时区分在线、离线、AI 临时代管和 AI 队友；自己断线后会注明当前显示的是最后同步的状态。

房主的名字后有「房主」标记，可以 F9 换模型，当前一段讲完后生效。从标题页开房间的房主在自己的游戏画面里也有开发者模式（F12），可查看本局的隐藏状态，并在「规则插件」（Ctrl+K）里暂停规则、添加自定义规则；自定义规则在当前一段讲完后由房主电脑生成并安装。浏览器加入的人是普通玩家，没有开发者模式。每回合自动存档，游戏和模型调用都在房主电脑上；线索的标题与原文、NPC 秘密和模组真相不会发给玩家。每位玩家的笔记只保存在自己的电脑上，按这一局和座位分开，坐回原座后恢复，不会发给房主或其他玩家；浏览器加入的玩家，笔记只保留到关闭或刷新页面为止。

离开准备房间不会关房；标题页「多人游戏 → 回到房间」能返回。要关闭，请在准备房间或游戏的 Esc 菜单里选「关闭房间」，或退出程序。

游戏中按 Ctrl+S 或在 Esc 菜单选择「存档」，可立即将整局进度保存到房主设备，收到保存成功提示后完成。已入座的玩家也可以发起存档请求；存档包含各现场正在处理的行动，继续每回合自动保存。

### 公布发现与回应队友

联机调查检定得到的发现先由检定者掌握，包括模组规定失败仍能取得的材料。点击输入框上方的「发现与协作」，点击「向同场队友公布」即可分享刚才的叙述和已取得的材料，也可暂不公布。公布不会要求队友重掷这次检定，分头行动中的其他现场不会收到。

向队友说「林秋，你去看看外面」时，系统会识别行动请求，让林秋选择「同意并提交」或「拒绝」。只有本人同意才占用自己的行动资格。已经提交行动或本轮已封闭时，请求会保留；不会替换本人原有的行动。点击「队伍」可查看队友的状态、地点和连接情况。

### 命令行开房间

```bash
autokeeper host
autokeeper host mymod --seats 玩家,玩家,AI
autokeeper join 192.168.1.5
```

默认模组是《追书人》，第一位调查员留给玩家，其余交给 AI。开房间的终端不占座，房主自己另开终端 `autokeeper join 127.0.0.1`。如果程序显示了不同端口，请连显示的完整地址。续档用 `host --load 存档名`。

浏览器加入无需安装。应用或终端也可直接填写同一个房间网页地址，例如 `autokeeper join http://192.168.1.5:8000`；原有客户端地址仍可使用。断线后回到原座位，若显示「AI 临时代管」，选中后按「收回控制」。图片由本机渲染组件转成字符画，初始化时会检查并准备组件。

### 连接排查

先打开准备房间「朋友进不来？」或玩法说明里的联机排查页，它会列出本机各网络地址和处理步骤。

- 确认双方在同一个局域网。异地可通过 Radmin VPN 或 ZeroTier 组成虚拟局域网，使用那个网络分配的地址。
- 防火墙允许 Python 联网。默认网页端口 8000、终端联机端口 8765；端口被占会换号，以房间里显示的为准。
- WSL 开房间时，在 Windows 的 `.wslconfig` 的 `[wsl2]` 下配置 `networkingMode=mirrored`，重启 WSL 后再试。
- 双方版本需要一致。更新后重新同步依赖。
- 开不了新房间时，看标题页是否已有「回到房间」。命令行开的房间在原窗口按 Ctrl+C 关闭。

## 导入、生成与观战

标题页可以导入 PDF、Word、Markdown、文本或 ZIP，也可以使用命令行：

```bash
autokeeper import 模组.pdf --id mymod
autokeeper import 模组.pdf --model codex:default --vision-model codex:default
autokeeper generate "1931 年上海，一张没有标签的唱片" --id changpian
autokeeper autoplay mymod --party 2
```

`--model` 和 `--vision-model` 分别选择导入与读图模型。导入中途断了（断网、额度用完、关了窗口），同一个文件再导一次会接着做：原文不再重新提取，导入 Agent 先读自己上次记的笔记和写了一半的草稿，接着往下写；加 `--fresh` 从头来。导入结束会查找 Wikimedia Commons 上有授权的照片，转成字符画；加 `--no-photos` 跳过，之后可用 `autokeeper art fetch 模组目录` 补图。模组原图和手稿尽量保留；`generate` 从设定生成原创模组，`autoplay` 让 AI 调查员自动游玩，标题页「观战」也能看。

**导入成品在 `modules/local/`，原文在对应模组的 `source/`。** 使用云端模型时，导入和游玩所需的正文、图片会发送给所选服务。Git 忽略规则只防止提交文件，不代表内容不会发送给模型。请只导入自己有权使用的材料，不要公开分享受版权保护的原文和图片。

## 常见问题

**想严格按模组玩。** 标题页「设置」把自由度改成「严格按模组已有内容」，或启动时加 `--improv 严格`；配置文件也支持 `improv = "严格"`。

**动画结束后没动静，或回复中断。** 先看输入框和状态提示，确认是否在等掷骰或选择。模型请求失败时用 `/retry`，或菜单里的「接着讲」。如果仍然卡住，保留报错和 `data/logs/` 中相关记录，提 issue 前删掉密钥与私人内容。

**原图怎么看？** 手稿发现后可在窗口中读完整文字，点击「查看／下载原件」打开信件、地图等图片；F2 可以重看。纸面材料不转换为字符画，场景和肖像仍保留字符风格。尚未发现的内容不会提前解锁，联机原件只发给对应接收者。

**数据在哪里？** 见上面的[东西放在哪](#东西放在哪)。备份时连同导入的模组一起保存。缓存包括嵌入模型、知识库、预处理图片和大场景图，可以重建，但重新下载、建库或生成图片可能需要联网和额外额度；有想保留的生成图，清理前先备份。

## 命令索引

以下命令均接在 `autokeeper` 后；参数细节可用 `--help` 查看。

| 命令 | 用途 |
|---|---|
| `play` / `serve` | 终端 / 浏览器游玩 |
| `host [模组] [--seats 玩家,AI]` / `join 地址` | 开房间 / 加入房间 |
| `import FILE --id ID [--pages 8-19]` | 导入模组，可指定页码 |
| `generate "灵感" --id ID` / `research DIR` | 生成模组 / 联网核实考据 |
| `check 模组` / `compile 模组` | 校验模组 / 编译 Skill 包（模组写 id 或目录，如 `zhuishuren`） |
| `upgrade 模组 [--only 步骤] [--dry-run]` | 编译期改编：补上模组缺的人物、关系、打算、伏笔、线索、结局、战斗数值与追逐路线；`--dry-run` 不调用模型、不写文件，只列出每一步要不要补和现在的可玩度 |
| `index DIR` / `ask DIR "问题"` | 建原文知识库 / 提问 |
| `art prepare DIR` | 给缺图的地点、人物、物件和怪物配图：先找照片，没有就让 AI 画，存在本机缓存 |
| `art fetch DIR` / `art color DIR` / `art show DIR NAME` | 补照片 / 字符画上色 / 预览 |
| `showcase 模组` | 提前准备大场景图 |
| `autoplay DIR --party N` | AI 调查员自动跑团 |
| `plugin list DIR` / `plugin test DIR` | 查看规则插件 / 运行插件测试 |
| `rules index [--books DIR]` / `rules search 规则` | 读入规则书建本地索引 / 查看会查到哪几段原文 |
| `cards import [路径]` | 读入守秘人卡组（好事者、恐惧症、惨事、武器） |
| `setup` / `doctor [--ping]` | 准备环境 / 检查环境（可实测连接） |
| `login [deepseek\|claude\|codex] [--key KEY]` | 选模型、存 API Key |
| `trace` | 查看模型用量与花费 |
| `eval rhetoric` / `eval lore` / `eval style` | 运行评测 |

`--preset`、`--model`、`--fallback`、`--search`、`--budget`、`--improv` 等全局选项放在子命令前。例如 `autokeeper --preset deepseek import 模组.pdf`。导入子命令还可以用自己的 `--model` 覆盖本次导入的选择。
