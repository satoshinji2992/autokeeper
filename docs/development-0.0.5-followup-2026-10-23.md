# 0.0.5 试玩后的离线修复

2026-10-23。本批从 `1f17461` 接续，处理三人试玩暴露的执行与信息投递问题。不重新开启已经结束的五小时试玩，不增加付费模型调用，也不修改原试玩的骰点、资源与账本。

## 本轮改动

### 长等待交接同伴行动

接收声明时保存游戏时刻。长等待尚未执行的部分可以暂存，先处理其他玩家已交的行动；恢复时保留原期限，已经随同伴经过的时间不重复结算。普通走路、交谈不要求全桌逐轮确认；全员等待或明确空闲时才允许长等待继续向前跳时。

世界未变时复用原安排；实际记录变化后，同一个 KP 先读最新现场和停止条件，再决定下一段。原话、已完成前缀、未办意图与截止分别提供，完整的执行日志不再重复塞入模型上下文。真正的新选择仍保留暂停，原等待也不能自动当作战斗或追逐的声明。

原批次的第一次保存就同时记录自动续办身份，重启不依赖内存标志；替换与撤回取消未执行部分。具体流程、24 项新增回归及尚未覆盖的普通长行动见[等待交接记录](wait-handoffs-2026-10-23.md)。

### 个人所得不再随同场广播

主检定的 `result_scope` 区分个人发现与共同可见结果。个人所得的正文直接交给本人，公共骰点不扩大知情范围；共同变化可以由同一次 KP 输出的 `asides` 分别交代。NPC 公开对白与独立事件仍按实际受众发送。

结果受众保存在结算记录中，正文、线索、默认图片、重连、历史与摘要沿用这一范围。全局线索清单只表示本局进展，不再阻止其他人独立发现同一线索。已经公开的信息不会因后来一次私人观察重新保密。

全量回归又发现了一个区别：NPC 台词可以建立知情，但不代表对应线索的理智、神话知识和交付已经结算。现在 `GameState.clue_settled` 按调查员保存明确的取得结算记录，成本与记录一并提交，既不因读档后“已经知道”而漏办，也不因历史压缩而再次扣除。这个内部记录不向其他玩家发送。

没有新增信息分类或审稿模型。不同受众的结果可能需要分别叙述，因此部分多人批次会多一次正常 KP 叙述；不能据此宣称 token 一定下降。接口及边界见[运行架构](keeper-runtime-0.0.5.md#个人检定所得与共同现场2026-10-23-修正)。

### 重新声明保留玩家原意

战斗和追逐继续按回合收集行动。原行动的前提变化后，自由文本的重新声明交给同一个 KP 解释，再沿现有裁定、提交和恢复流程执行；按钮选项继续直接使用既有行动。确认过的多人回合也不能静默取消真人的失效行动。

选择者与当前画面焦点分别处理。模型读取实际回应者的人物卡，不在等待模型期间临时切换全桌焦点。自由文本应对无法确认时保留原选择，不擅自替换为默认防守。解释和裁定复用已有恢复记录，断开后不重掷或重复提交。

进一步复审发现，换对人物卡还不够：后续拾取、装备、线索、理智与神话技能也曾按当前焦点结算。现在这些步骤都保留实际行动者和结果受众。追逐结束或转为战斗时，移动名单来自本场遭遇，异地队友保留原位置；会合也以实际行动者所在场景为目的地。

### 被动见闻与正式经历

NPC 仅仅看见、听见一件事，不占用一段需要行动的时间；实际交谈、移动与物理操作仍保留时间约束。补写过去见闻时，核对该时刻是否在场，避免因 NPC 后来移动便拒绝真实的旧观察，也不把未来到场当作已经听见。

明确查询过去时点时，人物资料过滤未来创建的事实、事件与记忆。KP 的简报附带本调查员近期正式遭遇的归档依据，压缩后仍能核对已经发生的伤亡和经过。这不要求向玩家重复叙述，也不使 NPC 自动知情。

## 仍需验证与完成

- 历史知情尚未保存每位人物的完整获知时间；当前人物卡和模型会话也不是任意时刻的历史快照。
- 私下 NPC 证词仍有仅更新知情的分支，带有理智／神话知识后果时尚未完整结算；需要按真实收件人单独核对，不能把个人投递完成等同于所有私人规则后果都已覆盖。
- 独立现场的状态、模型会话和异地同时遭遇仍需统一；本批不是完整的并行现场系统。
- 试玩中的重复登记同一 NPC、地点引用不完整，以及编译资料的全路径核对，尚未系统完成。普通长休息的交接、已开办行动和未掷骰检定的完整取消也不在本批交付范围。
- `respond()`负责结算；正常 Hub／Graph 会将结果交回原行动的叙述。外部直接调用这一接口后再讲述时，仍须选择正确的主持上下文，不能把它当作完整的独立分场接口。
- KP 仍可能错判结果的可见范围、遗漏停止条件或误述旧经历。离线测试验证执行与恢复，不能代替真实模型的小段复核和真人长局。
- 续办格式同时提供继续、需要新决定、确已完成三种示例，避免唯一的挂起示例引导正常等待反复交还玩家；本批没有用真实模型证明提示效果。

原始问题与有期限的试玩证据见[三人试玩记录](playtest-multiplayer-2026-10-23.md)。发布前仍须核对编译资料到运行上下文的通路，并完成真实主持表现验收。
