# 主持执行层实施记录

本批落实[轻量主持架构](harness-slimming-2026-10-24.md)中的执行层撤并，基线为 `102bbb3`。修改在开发工作区，不发布、不替换安装、不读取或修改真实存档。

## 一份行动记录贯穿排队与结算

删除 `queued_actions` 和 `queued_receipts`，改为 `Declaration(id, seat, text, at, batch)`。编号与个人接收时刻在接受该版本时确定；排队、封批、重连、延期和分队合流使用同一条记录。玩家修改声明建立新版本；已封存版本保留，不能覆盖已经开始的行动。

`bind_declarations()` 是封批绑定的唯一入口，`Game.seal_party` 在保存前完成关联，避免批计划已存而声明归属尚未存。步骤引用 `declaration`，等待截止从对应记录读取接收时刻，删除重复的 `step.received`。完成后的清理由游戏的 `end_round` 统一处理，网络不再另管一份完成进度。

批规划的冻结输入仍保留在 `round_plan.input`，用于恢复模型当时采用的安排；这不代表所有原文复制均已消除。单人原话仍在执行 journal，复合请求保留其原始意图与已经完成的片段。

## 执行阶段只归 journal

原先图节点与 `pending_turn` 同时保存进度，还另有内存 `Turn` holder。现在 `Execution` 直接读取 `pending_turn`，保存执行编号、当前阶段、工具回执和等待的选择。图只剩 `execute` 与 `choice` 两个节点，承担事件传递、玩家暂停和完成后的快照。

删除 `talk_done`、`narrated` 两个并行完成标记，以已保存的阶段判断下一步。重建图或进程不要求保留原节点游标；已经完成的模型判断、骰点、对白、世界操作和呈现继续使用原回执。推骰与战斗反应逐次合并进本次结果。

本批仍按原业务次序调用准备、裁定、结算和叙述；固定 Plan／Telling 模型协议尚未改成自由工具循环。这次不据节点减少宣称模型调用或 token 已下降。

## 选择也有明确的恢复边界

等待选择时，记录问题、请求指纹及玩家回答。分队协调改了行动或裁定，旧的手动掷骰确认不能直接确认新检定；重新展示当前问题，尚未掷出的骰保持未掷。

战斗回应先消耗待选项、再结算攻防时，中途可能已经没有 `encounter.pending`。恢复因此优先处理已接受但尚未合并的回应回执，不能把“界面不再待选”当作“伤害已经结算”。独立回归覆盖了这一真实中断点。

## 分队共享资源显式列出

撤掉 `SceneTable.__dict__.update(root.__dict__)`。连接、座位、媒体缓存、权限与房间生命期通过明确属性共享；行动池、准备任务、私信消费者和场景时间工作保留在各自现场。输入与选择队列按当前成员读取房间中的实时映射，既能跟随队列重绑定，也不会清空别的场景输入。

合流时移交未开始的原声明，保留编号与接收时刻。保留现有共享世界、个人时钟及资源协调；没有为了拆状态而复制一份世界。

同时修复临时代管交接：玩家回桌前先恢复人控；若 AI 只有尚未产生效果的提案或等待，可撤回并释放占用。已有对白、骰点、移动、准备提交或正在结算的遭遇继续沿原回执处理。重连测试也使用协议中 `seated.pool` 的当前状态，不再假定后面一定另发一条相同的行动窗口消息。
