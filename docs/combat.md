# 战斗与追逐

战斗和追逐按 CoC 第 7 版规则一轮一轮结算。规则的数字在代码里，模型只决定"谁想做什么"和"怎么讲"。

## 分层

| 层 | 文件 | 做什么 |
| --- | --- | --- |
| 规则 | `rules/combat.py`、`rules/chase.py`、`rules/weapons.py` | 行动先后、近战的闪避与反击、射击（卡壳、弹药、扑向掩体、朝扭打中的人开枪）、战技（体格差）、伤害与贯穿、重伤与濒死、怪物的护甲与自愈；追逐的速度检定、移动次数、险阻与路障、躲藏、甩开与追上。纯函数，骰子由调用方给。 |
| 局面 | `engine/combat.py` | 由调查员人物卡、模组 NPC 和怪物建出参战者；把玩家的话读成一条行动（`Order`）；模型不可用时的经验规则；给屏幕和守秘人的视图与报告。 |
| 回合 | `engine/fighting.py`（`Game` 的混入） | 开打与开追、按敏捷顺序结算一整轮、结束时写回世界记录并判定剧情标记。每次检定和每处伤都在回合日志的步骤里落地（`Game._resolution_step`），中断后从原处接着结算，不会掷两次骰、受两次伤。 |
| 界面 | `tui/widgets/fight.py` | 舞台（画面与右栏）、全屏泛红、故事里的战斗卡片；画面合成在 `imagery.staged`；屏幕的摇晃、心跳和限时选择在 `tui/screens/game.py`。 |

## 怎么开始

- 裁定员判定这次行动打起来了：`Ruling.combat` 写动手的一方，`Ruling.surprise` 写谁被偷袭。追逐写 `Ruling.chase` 和 `chase_party`（调查员是逃还是追）。裁定员的提示里有【可能动手的】，列出在场 NPC 和模组的怪物。
- 战斗中调查员全部逃走，对手里有会追的（战术分工的 `pursue`，没有就按怪物本性：会追，除非资料写了不追），就转成追逐。
- 追逐中被追上（追兵到了同一段），或调查员回身迎战，就转成战斗。

开打时 `GameState.fight`（追逐是 `GameState.chase`）有值，此后每次输入都是这一轮的行动，直到结束。

## 一轮

1. **宣告**：本轮调查员的行动记进 `fight.orders`。屏幕给的选项是写好的文字（`攻击 老守钟人（徒手）｜被攻击时闪避`），引擎直接读；读不出来时交给 `Cast.order`（解析行动分工）。攻击、射击、战技、急救由引擎给出检定，不经过裁定员；别的事（砸油灯、关门）照常交给裁定员，成功时可以有伤害（`Ruling.harm`）。
2. **其他人**：NPC、怪物和 AI 调查员的行动由一次 `Cast.tactics` 调用安排（「战术」分工，默认用裁定员的模型、思考调低），可以附一句喊话。模型出错或超时就用 `combat.rule_of_thumb`。在座但这一轮没出手的玩家只防守。
3. **结算**：每个人这一轮被攻击时的应对先定好，再按敏捷顺序（拿着能开火的枪 +50）一个个行动。每次交锋发一个 `fight_act` 事件给屏幕，调查员自己的那颗骰子送去骰盘。
4. **轮末**：濒死的人过体质，会自愈的怪物回血（可能又站起来），偷袭只管第一轮。
5. **讲述**：守秘人照这一轮结算出来的经过讲一段（`Turn.fight` 进报告），不新添伤口和动作，不替调查员决定下一轮。

联机时一轮同样是 7 秒窗口：每个人的行动是一个宣告回合（`Game.holding`，`Turn.declared`），最后一个宣告的人结算整轮。客户端只拿到桌上看得见的部分（`net/hub.py` 的 `public_fighter`、`public_battle`）：对手的名字、伤势字样对应的生命比例、手里武器的名字、位置与速度，不给生命值、技能、护甲、守秘人描述和裁定理由，追逐路线只到最前面的人再往前两段；对手的头像在开打、开追、第一次看见和被追上前单独发送。客户端在状态同步和每轮行动池开放时列出这一轮的选项。AI 座位拿到的情况里附有局面和这一轮选项的原文（`engine/autoplay.battle_now`），照原文回答时引擎直接读懂。

## 结束

- 战斗：对手全部倒下、逃走或投降（调查员占上风），调查员全部倒下（失败），或调查员全部逃走。
- 追逐：被追上（转为战斗）、领先三段以上或跑出路线、躲藏成功。

结束时：

1. 受伤、昏迷、死亡的 NPC 写进世界记录（`Condition`），这场战斗或追逐作为公开事件（`Occur`）记下。
2. 时间往前走。
3. `Cast.outcome` 从模组的剧情标记里选出因此成立的（比如道格拉斯被打倒），交给 `Game._flags` 设置，挂在这些标记上的事件随之发生。

## 在 Claude Code / Codex 里

MCP 服务（`mcp_server.py`）走同一套结算，宿主（担任守秘人的 Claude Code 或 Codex）只说明和谁打、把结果讲出来：

- `start_fight(foes, surprise, reason)`、`start_chase(others, party, reason)`：代替裁定员的 `Ruling.combat`、`Ruling.surprise` 与 `Ruling.chase`、`Ruling.chase_party`，对象只能是在场 NPC 和模组怪物。这次行动只宣告、不结算（`Game.holding`，和联机时一样），所以第一轮也由调查员自己选。初次看见怪物的理智检定、追逐的速度检定在这里完成。
- `battle_round(order, skill, difficulty, harm, target)`：调查员这一轮的行动，文字和屏幕上的选项相同，引擎读不出来的交给 `Cast.order`（`Game._battle_action`）。不是战斗动作的事（砸油灯、关门）由宿主给出检定和伤害，代替屏幕上的裁定员。对手和怪物的行动照常由战术分工安排。
- 返回的 `battle`：`lines` 是 `Turn.fight`；`exchanges` 是每次交锋（来自 `fight_act`，即战斗卡片上的内容）；`seen` 是初次看见的怪物；`over` 是结束的结果（战斗 `won`、`fled`、`lost`，追逐 `escaped`、`caught`）；`now` 是 `combat.view` 或 `combat.chase_view`，加上出手先后和调查员的选项（`combat.choices`、`combat.chase_choices`）。对手的生命值不出现，只有伤势字样。`scene()` 的 `battle` 是同一个局面，`creatures` 列出模组的怪物。
- 和其他工具一样记在 `GameState.pending_mcp`：交锋、开始与结束的事件随所在步骤的回执存下，中断后用原参数重试，从中断处接着结算、不重掷，报告照样完整。战斗与追逐进行中，`move`、`skill_check`、`reveal_clue`、`npc_say`、`advance_time`、`apply_damage` 和 `dice` 都会拒绝执行。

## 画面

战斗和追逐都在舞台上取代场景（`Arena`）：左边一幅画（`Canvas`），右边一栏文字。画由 `imagery.staged` 合成，按舞台本身的宽高比，`render_staged` 转成字符，几种变体（原样、心跳时变暗、被打中时发白、倒下时变灰、扑近时放大）在线程里一次画好。

- **战斗**：画面是正在面对的对手，比舞台还高，背后是一团血光。
  - 血顺着画面往下流（atmosphere 的 `blood`），心跳一样明暗起伏（`pulse`）。
  - 它出手时扑近；打中调查员时爪痕划过画面并溅血（`Canvas.slashed`）。
  - 被打中时白光一闪，伤害数字用血写在上面（`Canvas.struck`）；倒下的变灰并打上十字。
  - 右栏：轮次、行动先后（正在行动的人高亮）、对手的伤势字样和四格伤势条（不给数字）、调查员的生命值。
- **追逐**：画面是所在的地点，按「追逐」的冷色调暗下来、横向抹开，追兵按自己的轮廓合成进去，离得越近越大（`NEAR`：差三段、两段、一段、追上），每追近一段扑近一下；景物向后掠（`rush`）。右栏是跑过的路和看得见的前方（`chase_route`；`in_sight`：最前面的人再往前 `SEEN` 段，遇到险阻或路障为止，更远处只写「前方：尚未看清」，路线在哪里结束也看不见）：前面的路在上、来路在下，每段写名字和上面的险阻（⚠ 技能与失败的伤害）或路障（▦，打开的是 ▢），谁在哪一段，这一轮跑过的段留一道痕迹（┆）；上方写追兵在身后几段、还要领先几段才能脱离（领先 `LOST` 段，只给段数，不指明是哪一段）、能不能躲藏，下方写每个人的速度和每轮能跑几段。面板变窄时各栏随之收窄。
- **怪物肖像**：模组里没有图的怪物，本机有 Codex 时由它各画一张，纯黑背景，每个模组只画一次（`pictures.py`，见[AI 画图](keeper-experience.md#ai-画图)）；画好以前和没有 Codex 时由程序画（`scenery.creature`）：黑暗里的身形，下方的光照亮脸，背后是血光；深陷的眼窝里两点亮光，合不上的嘴里满是针一样的牙，血从下巴往下淌；按描述加长下颌、利爪、触手，或者一张没有脸的空洞。透明通道是它的轮廓，追逐时用它合成进地点。第一次见到时先全屏显示，再让全队过理智检定（`reveal` 事件）。
- **屏幕效果**（`tui/screens/game.py`）：调查员受伤时全屏泛红（`BloodFlash`，按伤势占生命值的比例决定深浅，期间的按键照常传给下面），屏幕摇晃；被追上时追兵的脸占满屏幕。顶栏显示轮次和一颗按生命值快慢跳动的心。
- **限时选择**：默认关闭，设置里的「战斗与追逐限时选择」（`battle_timer`）打开。打开后每轮的行动选单带倒计时（战斗 20 秒、追逐 12 秒，最后 5 秒边框变红），时间到了战斗中只防守、追逐中只全力奔跑；帮助、菜单、人物卡、手稿等窗口盖住画面时暂停，Tab 换防守方式不重新计时，手动输入行动时停止。联机时一轮有自己的 7 秒窗口，不再另计时。

## 测试

- `tests/test_combat_rules.py`：规则逐条。
- `tests/test_fight.py`：开打到打完、按敏捷的先后与应对、追逐的甩开与躲藏、舞台与选项、受伤时的泛红、限时选择；全屏画面与泛红只从最上层关闭、小终端排版、选单的收起、每帧的开销与设置开关、故事不重复。
- `tests/test_mcp_battle.py`：通过 MCP 工具开打、按屏幕上的文字结算一轮、宿主裁定的其他行动、打完、逃跑转成追逐、追逐与躲藏，以及中断后重试不重掷。
- `tests/test_imagery.py`：怪物的轮廓与舞台合成。
- `tests/test_net.py`：联机一轮由所有人宣告、只结算一次；客户端拿到的公开部分与对手头像、每轮的选项、AI 座位的局面与选项。
