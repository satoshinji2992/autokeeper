# 0.0.5-A 实施记录

2026-10-22。从 `f185faf` 推进，修改位于 `/root/code/autokeeper-wt/release`；本批未推送、未发版。版本路线见 [0.0.5 清单](roadmap-0.0.5.md)。

## 主持判断如何落地

KP 的现有安排输出增加 `present` 与 `people`。前者补记已经在眼前、原位置未登记的 NPC，后者为需要继续参与的即兴人物提供最小资料。复用 `world/scene.py` 的操作与既有模组投影，先提交，再计算在场名单、筛选主动参与者和调用裁定员。叙述阶段也可以登记新人物。

程序继续核对身份、死亡／失踪、真实路程与时间。裁定前的这个出口没有交物、伤害或调查员移动字段，不能把“抢钥匙”提前记成得手。未知位置不再自动视作在远处，真实异地仍不能靠补记瞬移。新人物不自动变成谜团，也不创建常驻自主智能体；画像沿用后台准备。

登记失败的具体原因会交回 KP 修正一次。修正仍不成立时，独立可行部分可以落实，未落实原因进入后续报告，不删除正文。安排与操作收据随回合保存。

复审发现，中途安排快照可能重复增加轮号和玩家输入；已补真实 `Game.parse` 重载测试，并复用保存的轮号。另一项成本问题是空安排也会复制世界、两次写盘，现已在无登记时直接略过；正常回合不增加模型调用。

## 战后继续主持

此前遭遇外的全员倒下分支把“没有调查员能行动”当成“没有人能救”，连续结算濒死，并可能直接中断稳定但不能自行醒来的调查。

现在由同一个 KP 根据现场、人物动机、私有资料、关系和日程安排施救、医疗、搬运、等待或中断。急救和医学成败、伤势、濒死与实际耗时由规则结算；有人恢复行动就交还玩家。NPC 在场不保证愿意施救，拒救和伤重死亡仍然成立。

本批修复的执行边界包括：

- 每次急救经过一轮；成功稳定的人免去该轮的濒死检定，其他濒死者仍需检定，失败也不能免费重复尝试。
- 已知失踪、死亡或昏迷的 NPC 不能仅凭旧位置和默认健康数值施救。实际搬运核对位置与路程。
- 等待在已定事件、世界日程、插件计时、伤势变化和苏醒节点处理局势；正常游玩的后台延后模式不能延迟应到的救援。
- 濒死轮次保留秒余量；每小时的稳定检定与恶化落实到身体记录，成功医学治疗解除相应濒死状态。
- 阶段游标、骰值和通知进入既有恢复日志，中断后不重掷、不重复治疗；执行上限耗尽后可继续下一段，不能永久卡在已完成的旧阶段。

当前战后安排只使用已登记人物、地点，尚不能在该次输出里创建新医生或新医院。已从提示中删除不可执行的新增救援指令。日常场景已有的新人物登记可以后续复用，不为此另建救援智能体。

## 节奏与表达

已裁定成立的发现全部落实，不再截为每轮一两条。NPC 主动参与保留在场、身份和去重检查，取消两人的硬截断；场面规模由 KP 结合实际需要安排。

固定回合数只产生内部参考。KP 在正常叙述中通过 `offer_idea` 明确选择是否提议灵感检定；认真讨论、关系发展、日常和有意等待不直接算停滞。灵感失败保留规则要求的启发，由原 KP 会话决定具体耗时和危机；只有需要新内容时才交导演准备。旧版已结算的三小时仅作为历史记录恢复，不重复扣时。

NPC 提示撤除固定句数、频繁反问、必须逼问才透露秘密等要求。人物仍可以主动合作、隐瞒或撒谎，实际表现需要真实模型验收。

使用脚本模型、预设骰和临时目录验证，不调用真实模型，不修改用户存档。新增测试覆盖裁定前现场、待检定结果、临时人物恢复与知识、多人主动参与、发现完整落实、节奏提示、灵感失败耗时、战后救援以及中断恢复。

整合全量回归 **1826 项通过**，Ruff 与差异空白检查通过。三本自带模组和格式样例检查均无错误，保留原有资料提示。测试另有 4 条 Python 多线程进程使用 `fork` 的弃用警告，没有对应失败。

检查中补正了一项新测试未先声明剧情标记的资料问题；另一次原有角色创建界面的异步等待超时在复跑中没有重现，未改动该界面。最终完整回归全部通过。程序测试不能证明意图理解、信息交代和 NPC 扮演已经达到预期，仍需定向真实模型重放和真人试玩。
