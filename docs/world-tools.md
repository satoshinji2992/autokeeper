# 世界工具接口

内部智能体通过 `world.tools.Gateway` 读写世界记录：查询、预演和提交使用同一套记录、权限与校验。工具不会重掷检定或直接推进时钟。

## 查询与预演

- `query(query="", limit=20)`（模型工具 `world_query`）：查实际位置、事实、亲历事件、NPC 目标与计划，返回当前读取版本 `reads`。
- `schema()`：操作字段，例如 `move`、`follow`、`transfer`、`plan`、`step`、`schedule` 和 `rewrite`。
- `preview(ops, reads=None)`（`world_preview`）：在副本中顺序检查整组操作，返回预计位置、事件和计划完成状态。预演结果不会进入实际世界；`reads` 始终是预演前的版本，`post_reads` 另记预计后态。
- `commit(ops, reads=…, request_id=…)`（`world_commit`，只在 `harness_tools(…, writable=True)` 时提供）：版本仍有效且整组校验通过时一次提交，否则整组拒绝。返回实际执行身份、操作、事件、位置与完成状态。

先查或预演，再将相同的操作和返回的 `reads` 交给提交。中断后使用原 `request_id`、操作和版本重试；成功的请求只执行一次。换成另一组内容会返回冲突。查询和预演不调用模型、不保存游戏，成功提交才写入当前存档。

```json
{
  "ops": [{"kind": "move", "entity": "thomas", "to": "mudi"}]
}
```

上述只是示意，实际 id 以当前模组和工具返回内容为准。剧情中说“打算前往”不能替代 `move`；真正同意陪同使用 `follow`，假答应仅记声称和私有意图，计划完成还需实际达成条件。

## 身份与知识

每个 Gateway 绑定一个身份，不提供身份切换参数。NPC 由引擎构造 `Gateway(world, npc_id)`，只能检索自己的已知资料、亲历记录、可见位置和本人计划。嵌套计划、定时操作也会重新绑定身份；模型提供的 `actor` 不能提升权限。

人物的说法与客观事实分开处理。工具保留有意撒谎及误解，不会自动纠正台词，也不把口供登记成客观真相。说谎者可以知道自己编造了什么；听者看到的只是相应来源，不会获得后台真值、其他知情者或带有“谎言”分类的事实路径。NPC 使用稳定、不含语义的 `claim:` 引用；引擎在权限校验后将其映回内部 id。

已向玩家建立的事实、尚待核验的旧公开标记，仍受现有改写规则保护。普通世界工具不接收带图片、插件的新场景包；这些内容必须经过游戏引擎的准备与提交流程。

## 内部智能体

`harness_tools(Gateway(world, npc_id))` 默认只提供查询与预演，参数支持数组和对象。最终操作仍由调度器统一结算，不在模型查询期间改动现场。NPC 只有主动提出查询时才追加工具往返，每次决策最多两轮；无查询时保持一次结构化决策。

NPC 回应里当场做的事（拿出、递出东西，说完就走）先用 `preview` 在副本里试，再由引擎调用 `Gateway.settle` 在同一轮落地：和 `commit` 一样的身份绑定、`vet`、副本试算与整组发布，操作 id 由回合、NPC 和回应序号决定，重试不会落两次；不留客户端回执。

开发者网页保存工具请求与结果，可核对“预演”“被拒绝”“实际提交”，避免将生成计划误认为已经执行。

## 装备与维护

`equip` 维护双方的重要装备：携带、穿戴、手持、藏匿、余量与状况。已有背包物品可以显式登记，不能凭空增加物品。当场出现的日常物件（递过来的手电、壁炉边的拨火棍）用 `bring` 登记在调查员所在地点的人或地点名下，不能借它拿出线索、手稿、重要物件或这一轮行动缺的东西；守秘人、NPC 和裁定员共用 `world/adapters.bring_ops`。`reveal=true` 必须提供当前场景中的发现或出示依据，隐藏装备和他人物品的私有状态不会随普通查询公开。转交仍使用 `transfer`。

内部维护检查只读地核对位置投影、装备归属、计划条件、公开来源和过期依据。问题进入开发者网页及 AI 排查资料，不自动改写剧情。人物撒谎、误解或违约本身不算一致性错误；应检查的是程序有没有把声称当成事实，或把未执行的动作标成完成。
