# 世界工具接口

内部智能体与本机 MCP 共用 `world.tools.Gateway`，查询、预演和提交使用同一套世界记录、权限与校验。工具不会重掷检定或直接推进时钟。

## 查询与预演

- `world_query(query="", limit=30)`：查实际位置、事实、亲历事件、NPC 目标与计划，返回当前读取版本 `reads`。
- `world_schema()`：查看操作字段，例如 `move`、`follow`、`transfer`、`plan`、`step`、`schedule` 和 `rewrite`。
- `world_preview(ops, reads=None)`：在副本中顺序检查整组操作，返回预计位置、事件和计划完成状态。预演结果不会进入实际世界；`reads` 始终是预演前的版本，`post_reads` 另记预计后态。
- `world_commit(request_id, ops, reads)`：版本仍有效且整组校验通过时一次提交，否则整组拒绝。返回实际执行身份、操作、事件、位置与完成状态。

先查或预演，再将相同的操作和返回的 `reads` 交给提交。网络中断后使用原 `request_id`、操作和版本重试；成功的请求只执行一次。换成另一组内容会返回冲突。查询和预演不调用模型、不保存游戏，成功提交才写入当前存档。

```json
{
  "ops": [{"kind": "move", "entity": "thomas", "to": "mudi"}]
}
```

上述只是示意，实际 id 以当前模组和工具返回内容为准。剧情中说“打算前往”不能替代 `move`；真正同意陪同使用 `follow`，假答应仅记声称和私有意图，计划完成还需实际达成条件。

## 身份与知识

MCP 入口固定为运行本局的守秘人，不提供身份切换参数。内部 NPC 由宿主构造 `Gateway(world, npc_id)`，只能检索自己的已知资料、亲历记录、可见位置和本人计划。嵌套计划、定时操作也会重新绑定身份；模型提供的 `actor` 不能提升权限。

人物的说法与客观事实分开处理。工具保留有意撒谎及误解，不会自动纠正台词，也不把口供登记成客观真相。说谎者可以知道自己编造了什么；听者看到的只是相应来源，不会获得后台真值、其他知情者或带有“谎言”分类的事实路径。NPC 使用稳定、不含语义的 `claim:` 引用；宿主在权限校验后将其映回内部 id。

已向玩家建立的事实、尚待核验的旧公开标记，仍受现有改写规则保护。普通世界工具不接收带图片、插件的新场景包；这些内容必须经过游戏引擎的准备与提交流程。

## 内部智能体

`harness_tools(Gateway(world, npc_id))` 默认只提供查询与预演，参数支持数组和对象。最终操作仍由调度器统一结算，不在模型查询期间改动现场。NPC 只有主动提出查询时才追加工具往返，每次决策最多两轮；无查询时保持一次结构化决策。

开发者网页保存工具请求与结果，可核对“预演”“被拒绝”“实际提交”，避免将生成计划误认为已经执行。

## 装备与维护

`equip` 维护双方的重要装备：携带、穿戴、手持、藏匿、余量与状况。已有背包物品可以显式登记，不能凭空增加物品；普通生活杂物无需入账。`reveal=true` 必须提供当前场景中的发现或出示依据，隐藏装备和他人物品的私有状态不会随普通查询公开。转交仍使用 `transfer`。

内部维护检查只读地核对位置投影、装备归属、计划条件、公开来源和过期依据。问题进入开发者网页及 AI 排查资料，不自动改写剧情。人物撒谎、误解或违约本身不算一致性错误；应检查的是程序有没有把声称当成事实，或把未执行的动作标成完成。

## MCP 回合恢复

`move`、`skill_check`、`reveal_clue` 与 `npc_say` 保存当前工具、原参数、原裁定和已结算结果。故障后用原工具及原参数重试；即使线索已经解锁，仍接续原裁定和 NPC 对话，不重新掷骰或重复耗时。每项新操作计为一个游戏回合，重试沿用原回合，存档也保留恢复点。尚有未完成操作时，另一项行动不会覆盖它。

工具恢复记录不发送给联机玩家。已向客户端发送、但因断线未确认收到的通知可能再次送达；这不代表事实再次结算。缺少客户端请求标识时，已经成功返回后再次调用相同参数仍视为新的操作。
