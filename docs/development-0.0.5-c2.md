## 为什么变贵

代码能够确认的变化是输出结构变长：v0.0.3 到本批基线，Plan 原始 schema 从 3,188 增至 5,595 字符，Ruling 从 5,463 增至 8,187，Telling 从 2,199 增至 3,799。现场登记、遭遇效果、待演选择和个人消息都需要结构，但不应再加重复包装。

本机近期《冬雪》14 轮排除视觉后，均摊约 4 次调用、78,300 总输入 token，其中 33,479 未命中缓存。主要消耗来自普通安排、叙述和裁定；后台世界决定四次，摘要不是该段主要开销。配图、缓存、模型和开局占比须分开统计。早期《追书人》与这段模组、模型均不同，不能直接称作版本费用同比。

## 本批改动

### 保留资料，去掉重复

多人整批安排原先先附一次全局经过，又在每条行动里抄一次同样经过。现在共享近况一次，每个地点的场景一次，再逐条附作者、地点、持有物、原话和骰子指令。全局与各参与者先分别按原窗口和预算取记录，再合并去重，保留私密收件人；同条记录优先保留更完整的正文。不能只扩大全局预算，否则长篇私聊仍会挤掉另一人的对话。

NPC 已在完整角色资料或动态知识中获得的同一事实，世界简报只另附知识句柄、出处和引用。亲历事件按事件编号去重，保留记录者姓名、标识、传闻与亲历之别。表演裁定使用行动里已有的完整 speech，不再附第二份。

KP 的模组底牌、本地完整规则、近期原话和既有记忆窗口不因此缩小。原始报告、场面重写与 retell 的匹配机制保持兼容。

### 精简输出结构表示

Claude、LangChain 原生结构、Codex 与 JSON 提示共用紧凑 schema。仅移除嵌套 schema 的自动 title 注解；根 title 用于适配器命名，实际名为 title 的业务字段、描述、约束、引用、default／const 中的原始字面量全部保留。完整示例不省字段，返回值仍按原 schema 校验。输入预算按实际采用的结构表示统计。

### 减少无效调用

KP 已判为 casual 的 talk 与 daily 采用同一闲聊通路：原先 talk 仍额外请求裁定，现在可以直接配音。明确技能、交涉方式、赶路或不在场人物仍走原裁定；未解锁线索不因省略裁定而自动获得。

导演的同一无效方案在初稿与一次修正均失败后停止，不再在 300 秒期限内反复重开修正预算；修稿遭遇临时服务故障时保留问题和已返回草案次数，继续原修稿。服务暂错仍间隔恢复，图片恢复、世界变化后的重新准备另计。保存的准备结果继续复用，失败不计为落实，等待不计游戏时间。这不是“所有导演任务至多两次请求”。

### 让消耗可解释

Ctrl+B 和调用汇总分别标出总输入、缓存读取、未命中缓存输入。总输入仍按服务方上报原值保留，费用没有通过改统计口径“下降”。新 trace 带应用版本，输入分解带 `schema_format = compact-v1`；旧记录缺少这些标记时不补猜。
