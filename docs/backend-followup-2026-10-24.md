# 后端复查：个人见闻、图片版本与格式恢复

本轮接续 `bf48ce1` 的[后端审查](backend-review-2026-10-24.md)。改动保存在开发分支，没有发布、覆盖正在运行的安装或改动真实存档。验证使用本地脚本模型，不调用付费模型。

## 个人见闻保存什么

世界记录继续保存当前真相，KP 仍能读取和修改。玩家资料记录自己最后看到的内容：角色的位置与状态、物品的归属与状况、地点和人物的图片。后台事件可以改变真相，不会自动改写远处调查员的旧见闻。

这一轮没有增加智能体或叙述审批。修复集中在已有世界记录、投递和会话接口。

## 图片不再随原资源一起变化

此前即使保存了头像 ID，后台重绘仍能替换这个 ID 对应的内容。现在实际目击的角色、地点、物品及手稿保存独立图片版本，字符图、颜色和照片都包含在内。照片原路径被覆盖后，旧版本仍能用于读档、历史投递和重连。

尚未画好的内容只订阅这次观察对应的生成任务。图片完成后更新获授权的版本；已经离开现场的人不会因为以前认识这个 NPC 而收到后来的死亡画像。状态结算先于绘图登记、生成中再次变化、退出后恢复也采用同一规则。相同版本复用内容副本，不在每次观察时重拷整张图片。

位置视图、同步状态和图片消息使用同一个个人资源引用，避免图片已收到、界面仍引用另一个 ID。旧画像的版本引用仍接受幻觉和隐藏外观过滤，不能借新别名绕过原图限制。

## 物品存在、实际归属和已知归属分开

NPC 私下把调查员以前经手的皮箱转交别人后，原调查员仍记得皮箱存在，也仍保留上次见到的归属、数量、状况和图片。模组列表、网络归属表、队友可见库存和地图采用同一份见闻；调查员检查自己的现有装备则读取实际状态。

不能用“已知物品 ID”筛选后再发送真实归属；也不能从队友当前库存里筛选旧物品，否则私下移除会让旧知识消失或改变排序。多人共知没有独立的物理视点，不能借房主地点看到另一位玩家才见过的物品。在一处公开发生的事按实际见证者记录，和玩家默认公开发送的聊天内容分别处理。

出示藏着的一件物品不等于公开全部私藏数量；非持有者不会借这次展示获知整份隐藏库存。已收到的手稿在模组资料中也引用同一份冻结正文与图片版本，不能通过原图 ID 再取得后台重绘后的内容。

## 本轮继续查到的边界问题

- 时间衔接的拒绝和失败缓存现在包含世界记录版本。世界未变不反复询问；正式变化后可以重新判断，不继续沿用旧局势下的拒绝。
- 会话在本地输入预算检查之前就标记本次尚无正式回复，防止失败清理误删上一条接受的交流。这是离线接口复现，没有把它说成用户存档已经出现的删记忆事故。
- NPC 模组资料不再发送攻击技能和伤害。此前只清空 `stats`，遗漏了 `attacks`。
- JSON 合法但正文仍夹带工具调用标记时，一次修复失败后整份拒绝，不展示残片、不执行藏在文字中的操作。缺少场面或续办字段的干净草稿仍可按原有方式恢复。
- 空队伍的地图查询不再索引不存在的当前调查员；个人地图投影明确设置对应查看者，避免读到房主的物品见闻。

新增 **43 项回归**，覆盖个人图片版本、同路径换图、迟到图片、存读档和重连、物品暗中转交和耗损、分队观察、库存顺序、格式污染与时间缓存失效。整合边界组 69 项通过，手稿与网络组合组 95 项通过。

冻结业务代码后的全量运行结果为 **3257 通过、2 失败、13 跳过**，耗时 7 分 52 秒。两项失败都在旧图片断言：直接期待原资源 ID、以及更换图片后未登记新的实际观察。仅调整对应测试后，相关整组 **41 项复验通过**；业务代码没有再变更。由全量与这次复验覆盖当前 3259 项有效测试，没有重新重复执行整库，也没有把原全量日志改写成全部成功。13 项跳过均因本机未安装 PowerShell。Ruff 与差异空白检查通过。

日志保存在 `dev/output/backend-followup-2026-10-24/`：`full-suite-final.txt` 是原全量结果，`final-media-regression.txt` 是两项断言调整后的媒体组复验，`final-boundaries.txt` 是整合边界组。首次中断的检查另留在 `full-suite.txt`，不计作最终验收。

房间仍采用朋友局的自由入座机制，没有新增原玩家身份绑定。NPC 工具的冲突校验版本号仍可能让角色察觉某个远处实体曾经变化，这一通路尚未改为与角色知识分离。离线测试也不能替代真人多人长局或真实模型的诱导与叙事质量评测。
