# 模组格式

一个模组是一个目录：

```text
modules/<id>/
  module.yaml        标题、年代、背景、钩子、真相、守秘人须知、开场、标记、起点、插件列表
  places.yaml        地点（locations）
  people.yaml        NPC、怪物、预设调查员（npcs、creatures、pregens）
  clues.yaml         线索、物件、手稿、手绘题（clues、items、handouts、sketches）
  story.yaml         事件、结论、结局、大场景、开局演出（events、conclusions、endings、showcases、prelude）
  situation.yaml     局面：人物关系、各人的打算、伏笔、私人牵连、插件清单、前史（relations、agendas、foreshadow、ties、mechanics、history）
  art/places/<键>.jpg   场景照片和原作场景图（也支持 png、jpeg、webp）
  art/people/<键>.jpg   人物头像
  art/items/<键>.png    手稿、地图、封面和其他图
  art/ascii/<键>.txt    ASCII 图（只用可打印 ASCII；场景 ≤56×14，头像 ≤18×7）
  art/ascii/<键>.color  同形状的配色蒙版，每个字符一个颜色键，“.”为默认色
  art/credits.yaml      每张图的来源与授权，按图片键记；Codex 生成的写“AI 生成（Codex image_gen）”和所依据的原图
  plugins/<id>/manifest.json  插件名称、版本、能力、动作与可执行测试
  plugins/<id>/plugin.py      自定义规则代码，独立进程执行
  source/            导入的原文、逐页扫描和导入时的笔记（只在本机，不进 Git）
```

几个 YAML 文件读进来时合并成一个模组，字段放错文件也能读。只有一个 `module.yaml`、图都平放在 `art/` 下的小模组也能直接读，手写一个小模组不必拆文件。导入 Agent 就是这样写草稿的，校验通过后再整理成上面的结构。

从模组算出来的东西不放在模组目录里：编译结果、知识库、大场景图和照片的预处理副本都在数据文件夹的缓存里，删掉会在用到时重建。

完整字段见 [`module-schema.json`](module-schema.json)；格式样例见 [`examples/module/`](../examples/module/)，演示常用字段的写法（只用于测试和给导入 Agent 参考，不是可玩的模组，也没有用到每一个字段）。



## 主要字段

| 字段 | 说明 |
|---|---|
| `title` / `subtitle` / `era` / `setting` / `players` / `duration` / `source` | 选模组时显示的介绍，照自带模组的写法：`era` 写原作的年代（`1922 年`、`2024 年`、`1890 年代`，不默认 1920 年代；裁定员据此判断什么东西合乎年代），`setting` 写国家、州和地方，`players` 写 `1-2 人`，`duration` 写 `约 2-4 小时`，`source` 写《书名》、作者和译者。标题、副标题、`hook` 和 `setting` 提到的地点开局就算听说过，会出现在地图上；要调查才找得到的地方不要在这几处点名（`check` 会提示） |
| `hook` / `opening` | 玩家已知的来意 / 守秘人开场素材；开场素材融入一次叙述，不重复朗读 |
| `truth` / `keeper_notes` | 只给守秘人看的真相和跑团建议 |
| `cover` | 无剧透的原作封面图片键；选模组时显示 ASCII 预览，不作为开局场景 |
| `plugins` | 已开发并通过测试的插件 id 列表；从 `plugins/<id>/` 加载代码，不能在 YAML 中填运行时 `extensions` |
| `start` / `start_time` | 起始地点 id 和时间（如 `D1 14:00`） |
| `locations` | 地点：`read_aloud`（读给玩家）、`keeper`（幕后资料）、`features`、`art`；`public: true` 表示可问路找到的公共地标；`within` 填外层地点 id，表示确实在它里面（书房在宅子里、陵墓在公墓里），地图上画在外层地点里，可留空，包含不代表连通；`scene_root: true` 是独立主持区域的边界（同一建筑的房间共用一位守秘人）；`entry` 只给没人站得进去的容器（楼层、整栋楼）填，指向进门落脚的房间；`looks` 是剧情变样后的场景图；`views` 是同一个地点的另外几张图（见下文）；`weather` 是画面上的天气与光（最多两种，不写就没有）；`outdoors`（是否露天、雨雪落不落得到）和 `ground`（地图上周围的地面：`graveyard`、`water`、`woods`、`fields`、`street`、`building`）由编译期的「场景呈现」一步按原文判断填上，游戏里不再按名字猜；`chase` 是从这里起跑的追逐沿着跑的路（见[战斗与追逐](#战斗与追逐)） |
| `passages` | 地点之间唯一的连通资料：`a` / `b` 两端（实际地点，不填容器）、`kind`（`road` 道路、`door` 门、`stairs` 楼梯、`corridor` 走廊、`opening` 门洞）、`minutes` 普通经过的分钟数（室内几步写 0）、`one_way`、`gate`（有门才写初始的 `open` / `locked` / `blocked`，开团后的状态只记在本局记录里）、`perception`（隔门能否听见看见的依据）；`secret: true` 是须发现才知道的暗门密道，`found` 写发现条件 `clue:线索id` 或 `flag:标记id`，没写就由守秘人登记或从另一端到过才算发现。见下文[建筑内部与平面图](#建筑内部与平面图) |
| `plans` | 建筑平面图：`building`、`floors`（每层 `name`、`level`、`rooms` 的格子 `place` / `x` / `y` / `w` / `h`，建筑本身那一间可写 `label`）、`basis` 依据。由编译期的“建筑内部”步骤生成和排布，不必手写坐标 |
| `npcs` | NPC：人设、`knows` / `secrets` / `lies`、能说出或交出的 `clues`（他说的、交出的，和他亲身知道、能转述的）和对应的社交门槛 `gates`、`portrait`、变样头像 `looks`；`important: true` 标出重要 NPC（最多 6 个），他们有自己的目标和打算，调查员不在时也会行动；会动手的人在 `stats` 写战斗数值、`attacks` 写攻击；`called` 是调查员还不知道他是谁时的叫法 |
| `creatures` | 怪物：`called`（调查员还不知道它是什么时的叫法，只写看得见的样子）、外观 `description`、照面时的理智检定 `sanity`、战斗数值 `stats`、攻击 `attacks`、规则用得着的特性 `notes`、逃跑时追不追 `pursues`；是某个 NPC 打起来的样子就写 `npc`，写法见[战斗与追逐](#战斗与追逐) |
| `items` | 重要物品：`id`、`name`、外观 `description`、所在地点 `where`、初始人物持有者 `owner`（可空）、配图 `art`；支持后台携带状态 `equipment`、数量 `quantity`、状况 `status` 和隐藏标记 `hidden`，不替代线索或授予隐藏效果 |
| `clues` | 线索：在哪找到（`where` / `feature`）、出自谁（`npc`）、检定（`check`）、支持结论（`points_to`）、关键性（`core`）、理智损失、附带手稿；`requires` 列出必须全部满足的前置线索 id 或 `flag:标记`，引擎会阻止提前发出；`art` 随模组保存，游戏中不单独展示。`title` 与 `text` 只给守秘人及结局复盘，游玩中由叙述、NPC 台词或手稿交代内容。见下文[线索的出处](#线索的出处) |
| `handouts` | 手稿完整 `text`；`paper` 是画成哪种纸（`letter`、`diary`、`news`、`wire`、`book`、`card`），同样在编译期定；`images: [病历图片键, 地图图片键]` 关联原图，仅发现后显示，支持滚动阅读全文和查看／下载原件，纸面材料不转字符画；`originals: [source/source/images/p14_image01.png]` 指向原书里这页手稿的图，相对模组文件夹，不随模组发布：本机有这个文件（模组自己的 `source/`，或安装版玩家模组目录下同名模组的 `source/`）时一并显示 |
| `conclusions` | 玩家需要推出的结论，校验时要求每个结论至少两条线索 |
| `flags` | 剧情标记及其含义；裁定员只会在行动真正达成含义时设置 |
| `events` | 定时（`D1 21:00`）、到达（`visit:地点`）、标记（`flag:x`）或遭遇完成轮数（`after_rounds`）触发；`where` 写实际发生地点，`move_to` 才表示移动队伍；`present` 写实际出场的 NPC，电话或传闻不算出场。`effects` 写原文明定的确定身体后果，`sanity` 是理智检定，`performer` / `performance` 指定 NPC 表演；`art` 是这一刻的图。`fight` / `chase` 开始袭击或追逐，`stakes` 写胜负后果，`sights` 写本次理智检定已覆盖的怪物照面 |
| `endings` | `condition: flag:x` 的结局按顺序判定；`requires` 是还需实际取得的线索或 `flag:` 前置，`sanity_gain: 1D6` 结算理智恢复，`reward` 保留奖励说明 |
| `sketches` | 让玩家手绘的东西：`target` 写真实样子，读图员相似度过 `threshold` 时触发理智检定或线索 |
| `showcases` | 大场景：在重要节点整屏展示一张大图，每个模组 5–15 个，见下文 |
| `prelude` | 开局演出：进入游戏前播放的几幕，图和字介绍故事背景，见下文 |
| `pregens` | 预设调查员（属性用中文名：力量、体质、体型、敏捷、外貌、智力、意志、教育） |

每个 NPC 在导入编译或即兴创建时准备 `called`，作为未通名短称呼，例如“戴灰帽的青年”“白大褂男子”，20 字以内，不加“未通名的人”前缀。只写初见可见特征或当时明确可知的职务，不写姓名、秘密身份和待调查事实。对话、地图与联机统一显示“未通名的人（短称呼）”，战斗的按钮和行列只显示短称呼本身；已经介绍过的名字按各玩家的知情记录显示，电话接触不提供尚未见过的外貌。

调查员的 `known_locations` 是本人背景明确熟悉的地点 id 列表，必须引用 `locations`。根据原文或明确背景填写本人家、工作地点、已知亲友地址；没有依据时留空，不按姓名猜地点。它只说明本人知道地址和路线，不标记本局到访，不解锁现场正文、线索或插图，也不向其他席位公开。

材料图片在 `art/credits.yaml` 中标记 `purpose: document`，预处理会直接使用源文件。导入工具 `use_image(path, name, purpose="document")` 原样复制内嵌图片；只有页图时，用 `use_pdf_material(page, name, region)` 从原始 PDF 以 300 dpi 输出无损 PNG。`region` 是从左上角起算的归一化 `[左, 上, 右, 下]`；周围有守秘人笔记时须限定到材料区域。`source/pages/` 的低清预览不能当原件。

联机原件支持 PNG、JPEG、WebP，单张不超过 16 MiB、6000 万像素，接收端保留原字节与格式。多张材料随同步消息分段传输并校验，单次消息上限为 512 Mi 个字符。不要以有损缩图冒充原件；超限材料应另行提供原始附件。

事件的 `when` 可用 `&`、`|` 和 `!` 组合现有条件，如 `flag:watching & hour:0-6`；`where` 是实际发生地点，异地事件只记录世界变化，不把调查员带到现场。`check` 是触发后仍须通过的检定，每游戏日最多尝试一次。

`advance_to: '20:00'` 表示在场经历事件后，世界时间至少推进到当日 20:00；`'D2 08:00'` 则指定游戏日。已经过了目标时刻就不倒退。用于原文明写的昏迷到夜间、长时间探索等经过，不从正文推测时钟。目标先保存，再按正常时钟流程处理日界、NPC 和日程；断线恢复不会重复加时。异地事件不跳过玩家的时间。原作只给“夜间”而补具体钟点时，应注明补充。

## 建筑内部与平面图

只有会影响玩法的空间才分成房间：分头行动、人物在不在场、上锁或隐藏的通行、私下交谈、不同的调查和明显不同的画面。桌子、药柜、床铺仍写在 `features` 里。原有地点保留为建筑的主厅（进门处），房间写成 `within` 这栋楼的新地点，房间之间用 `passages` 连通。

```yaml
locations:
  - {id: church, name: 埃斯内尔的教堂, scene_root: true, read_aloud: …}
  - {id: church_vestry, name: 圣器室, within: church, read_aloud: …}
  - {id: church_cellar, name: 教堂地下室, within: church, read_aloud: …}
passages:
  - {id: church__church_vestry, a: church, b: church_vestry, kind: door}
  - {id: church_vestry__church_cellar, a: church_vestry, b: church_cellar, kind: stairs, secret: true, found: clue:c_trapdoor}
plans:
  - building: church
    basis: 原文写明圣器室和地下室；楼梯位置为 AutoKeeper 补充
    floors:
      - {name: 一层, level: 0, rooms: [{place: church, label: 礼拜堂, x: 0, y: 0, w: 22, h: 6}, …]}
      - {name: 地下室, level: -1, rooms: [{place: church_cellar, x: 0, y: 0, w: 16, h: 5}]}
```

`autokeeper upgrade --only interiors` 让模型对照原文给出房间、楼层、大小、门和楼梯，以及原文写明在哪一间的人物、物件和线索；坐标按门的连接自动排布，有门相连的房间共用一面墙。原文没写的结构可以为通行和分头行动补上，在 `basis` 和房间的守秘人资料里注明“AutoKeeper 补充”，不添新的案情。`check` 会拒绝不在楼里的房间、重叠的格子、同一层级的两层和引用不存在的发现条件。

游戏中地图（F3）在有平面图的建筑里直接显示平面图，按 P 切换全局地图，`[` `]` 换楼层。每位玩家只看到自己到过的房间和从门口看得见的房间，未发现的暗室既不画出也不留空位；房间里标出本人看到的人。

## 事件的时机与后果

朗读、表演要求和剧情标记不代替身体记录。原文明确“当场击毙，无须掷骰”的事件，填写 `effects: [{kind: die, target: 人物id, why: 原文依据}]`；目前事件身体后果支持确定死亡。普通攻击、可能致死的危险和仍需玩家选择的结果由战斗或检定结算，不预填死亡。

原文写“交锋三轮后”，填写 `after_rounds: {event: 开启遭遇的事件id, completed: 3}`，不换算成任意钟点。没有其他条件时省略 `when`；有 `when` 时两项须同时成立。计数只包含实际结算完的轮次，中断恢复不重计；已归档的同源遭遇仍可满足条件，其他遭遇不算。若原遭遇提前结束且不足指定轮数，此条件不会自动满足，后续如何发展仍需另行准备。

事件发生时先提交确定后果，再展示正文与标记。涉及当前遭遇的死亡会解除控制、取消死者尚未执行的动作，并按实际局面结束遭遇。异地事件不搬运调查员，通知只送给实际见证者。

## 线索的出处

`npc` 写线索出自的人：他说的话、交出的东西、在他身上看到的样子，或要他当场点头才拿得到的（交涉检定写进他的 `gates`）。这样的线索跟着人走：那个人（按本局的世界记录，活着、没有失踪）和调查员在一处时才拿得到，在哪都一样；`where` / `feature` 写平时在哪见到他。东西在别处找到、这个人只是指路、给钥匙或转述的，不写 `npc`，线索就在 `where` 那里。没有 `npc` 的线索在 `where` 找到。

`feature` 应说明取得发现所需接触的对象。观察尸体外表与剖检内脏是不同的行动，不能都只写“棺木”。`text` 只写此次取得的发现；成功、失败各自的结果和操作条件完整放在当地 `keeper`。`sanity` 表示取得该发现时必然进行的理智检定，失败才有的损失应留在失败规则里，避免成功后也结算。

NPC 的 `clues` 只列他能说出或交出的：他说的、交出的，和他亲身知道、能转述的；列着的线索他在场时也能说出。在他身上看到的样子不列：那是调查员看到的，不是他说的（变装被识破、施法的场面）；对他过心理学才看得出的照旧列进 `clues`、`gates` 写心理学，引擎当作调查员看出来的，不等他说。出自他本人（`npc` 是他）、又带 `check` 的线索列进他的 `clues` 时必须在 `gates` 写上门槛，否则他会自己说出来、检定落空，`autokeeper check` 报错。裁定员看到的「本场景可得线索」、引擎认不认一条线索、守秘人幕后简报里「还没被找到的东西」都照这些算（`module/graph.at_hand`）；和他交谈时裁定出的线索，只有他 `clues` 里的才等他自己说出来，其余的当场找到。

线索的 `text` 只写拿到时就成立的事。原文写着被问到才说的话（“如果问及此事，他会说……”）、要检定或某件事发生以后才有的事，写进那个人的 `knows`、`lies`（要交涉才肯说的，交涉检定写进 `gates`），或另写一条带检定、前置条件（`requires`）的线索，不写成无条件的事实。

线索的 `sanity` 在实际发现或 NPC 已经说出要点时结算，`mythos: 3` 表示同时增加 3 个克苏鲁神话百分点。交涉成功只是获准问，尚未说出的线索不算已得到，不能据此终局。需要听完真相的结局在 `requires` 列出对应线索。

事件可以写 `where` 指定实际发生地点；到点发生在别处的事件只进入当地世界记录，不强行移动调查员、不向异地玩家展示现场，也不扣异地调查员的理智或生命。`move_to` 表示实际遭遇导致的移动；定时事件若没有 `where`，其 `move_to` 只按发生地点处理。确实会把在场者带去别处的事故需同时写起点 `where` 与结果 `move_to`，例如楼板塌陷后的坠落。`when` 除时间、`visit:` 外，可复用人物打算的条件：如 `flag:watching & hour:0-6`，`D2 08:00 & !flag:already_met`；`at:players:地点` 可约束玩家在场（任一调查员在那里即成立，分头行动时不看当前是谁在行动），`knows:players:clue:线索` 约束实际获知。条件满足后还需过检定的写 `check: {skill: 幸运}`，每游戏日最多尝试一次，失败保持待定，下个游戏日才可再试；事件发生后不重复播放。

手稿解锁代表玩家已经能阅读材料，不自动转移被观察的原物。KP 在 `scene.holds` / `things` 明确写出已取得手稿的持有场面时，系统把材料登记为证物并保存归属；只知道材料存在、尚未获得的线索，以及无实物的信息，都不能靠这个接口变成随身物品。

`autokeeper check` 会提醒：线索出自的人平时不在 `where`，也没有事件的 `present` 或打算的 `does: at:` 把他带去；事件的朗读写到有人在调查员眼前（点了 NPC 的名字，或写了人影、下车的人），全模组却还没有一个事件写 `present`。

## 剧情变样（looks）

原文写明某个地点或人物会明显变样（被烧毁、被淹、受伤、死去），而且有标记表示这件事发生了，就在那个地点或 NPC 下写：

```yaml
looks:
  - when: flag:church_burned        # 标记成立后换图
    change: 礼拜堂烧成焦黑的空壳，屋顶塌了一半
    art: church_burned              # 可省，默认 <原图键>_<标记>
```

导入时若本机有 Codex，就照原图画出 `art/places/church_burned.jpg`；没画成的，游戏里标记成立时再画。昼夜不用写，画面按时间自动调光。每个地点或人物一般最多两种，全模组最多 6 处（伏笔步骤的变样图也算在内）。挂在伏笔步骤标记上的变样图不在导入时画，故事走到前一步时才画，见[伏笔](#局面situationyaml)那一段。

### 背景差分：时有时无的样子

地点的图还可以有「状态成立时才用」的差分：某人在场时停着的车、摆开的货摊、找到线索以后墙上露出的符号。`when` 写状态而不是单独一个标记，状态成立时场景换成差分，不成立就换回原图：

```yaml
looks:
  - when: at:erie:main_street       # 埃里在主街时
    change: 街角停着一辆卡车，车斗里并排两口盖好的木箱
  - when: knows:players:clue:c_wall_symbol
    on: cardwell_wall               # 可省：哪张图的差分，留空是地点本身的图，也可以是下面 views 里的一张特写
    change: 剥掉墙皮的地方露出一个用火烧在木头上的怪异符号
```

状态用条件语言：`at:人物:地点`、`knows:players:clue:线索`、`hour:22-6`、`flag:标记`，`&` 连接；不写某一刻的时间。差分由 Codex 照原图画，只加上变化，构图不变：自带模组的画进本机缓存，导入的模组导入时画进自己的 `art/`。几种状态同时成立时（卡车和人群）用一张图，从已经画好、最接近的那张往上加缺的部分，画好之前先显示最接近的那张；这一局里地点已经永久变样（烧毁）的，差分照变样后的图重画，只属于这一局。人物的脸由场景角上的小像显示，差分里不画人。`autokeeper upgrade` 的「背景差分」一步按原文补这些。

## 一个地点的几张图（views）

场景区默认放地点自己的图（`art`）。同一个地点还可以有最多 4 张别的图：

```yaml
views:
  - key: shufang_2              # 图片键，art/places/shufang_2.jpg
    label: 书桌与窗              # 拍的是哪儿
    features: [写字台]           # 调查员查看写字台时换成这张；不对着具体东西就不写
    prompt: 窗下一张旧写字台，抽屉半开，散着纸   # 给找照片和画图用，不写人名和剧透
  - key: mudi_3
    label: 夜里的墓地
    time: night                  # 夜里到这里时默认放这张
```

行动对着的东西名字里有 `features` 里的一项，场景就换成那一张；转去对别的东西做事、和人说话时换回来，等待和闲逛不换。只有名字完整出现才算：查看“陵墓”不会换成对着“陵墓内部”的那张。事件的 `art` 和这里一样放在场景区，下一次行动后换回。

可以自己把图放进 `art/places/` 并在这里登记；`autokeeper upgrade` 的「特写」一步也会按原文给值得单独看一眼的东西（地下室里的香炉、剥落墙皮的墙面）补上特写，画面只写走近时一眼看得见的，找图和画图同地点的图一样（`prompt` 给找照片用）。这里有一条线索、找到以后画面会不一样的，同时写一条挂在这张特写上的差分（`on`，见上面的背景差分）。守秘人也能把这些特写当作可呈现的图展示。

## 局面（situation.yaml）

模组写的是局面，不是剧情：谁想要什么、彼此怎样、没人插手时事情会怎么发展。不分幕，也不预设调查员会怎么走。

```yaml
relations:                      # 冲突图：谁怎样看谁，开局就在本局的世界记录里
  - a: jefferson                # NPC id
    b: douglas                  # NPC id，或 players 表示调查员们
    kind: 恐惧
    value: -55                  # -100..100
    why: 深夜在墓碑旁见过人影，认定是老金博尔的鬼魂
agendas:                        # 重要 NPC 的打算：调查员不在时照着做
  - npc: douglas
    goals: [在出口封死前把剩下的书搬走]
    steps:
      - id: take_books
        text: 等屋里人睡熟，从书房松动的窗户翻进去，抱走几本书
        when: D2 23:00          # 到这个时间去做；也可以写条件 flag:标记、at:谁:地点、gone:谁、hour:22-6（几点到几点），& 连接
      - id: seal
        text: 天亮前抱着书回到隧道，和食尸鬼们一起封死出口
        when: D3 05:00
        does: at:douglas:suidao & flag:douglas_escaped   # 做成以后实际成立的事：到时直接照做，不用模型
      - id: greet
        text: 地下撞见调查员时先问好，对方不动手就领他们看自己堆书的角落
        meet: true              # 见面时的反应：调查员在场时由他自己演，不在幕后想；不写 when 和 does
        once: true              # 只做一次（应门、安顿行李），演过就算完成；一贯的态度写 false
        source: c_douglas_truth # 依据：原作哪里写到（地点、线索、NPC 的 id，或 真相、守秘人须知）；推出来的写 补写
  - npc: jefferson
    steps:
      - id: take_bribe
        text: 收下酒，态度松动，说出深夜在墓碑旁见过人影
        when: flag:has_liquor
        only_if: 调查员当面把酒递给他、他收下以后；只是买到了酒不算   # 条件语法写不出的实际依据
        meet: true
        once: true
      - id: help_search
        text: 过来帮忙，在旧书桌里翻出日记
        ruling: true            # 要守秘人先裁定才发生的结果：不给人物当成见面就做的事
        only_if: 调查员在书房侦查失败后孤注一掷成功
foreshadow:                     # 伏笔：到这个地点时交给守秘人，一笔带过
  - id: f_mud
    hint: 书房窗台外沿蹭着一道干了的湿泥
    where: shufang
    pays_off: k_not_burglar     # 最后指向的结论、事件或结局
    stages:                     # 可选：之后再来时端倪的变化，按先后排，每次来到只露一步
      - hint: 窗台外沿的泥印多了一道，还是新的
      - hint: 窗框上多了几道指甲的划痕
        when: D2 18:00          # 最早什么时候露出：时间，或 flag:标记；不写就是下一次来
        where: shufang          # 在别的地点露出时写那个地点；不写就是伏笔原来的地点
        flag: window_scratched  # 可选：露出时设上的标记（要在 flags 里声明），配合地点的 looks 换场景图（那张图前一步露出时才画）
ties:                           # 私人牵连：导演开局改编时按调查员背景挑着用
  - id: t_grave
    hook: 调查员小时候在这片公墓给祖父上过坟
    place: mudi
    fits: [意义非凡之地]
history:                        # 前史：开局以前发生过、至今还在起作用的事，按先后
  - when: 五年前
    text: 道格拉斯在墓地读书时结识了一头食尸鬼
    who: [douglas]
    where: mudi
    known_by: []                # 另外还有谁知道；牵涉的人本来就知道
mechanics:                      # 引擎自己不管、要插件来管的规则
  - name: 最后一夜
    rules: 道格拉斯只剩今晚能回来取书……
    plugin: ""                  # 写好的插件 id；没写就留空，导演看得到这条
    runs: 守秘人                 # 谁执行：核心规则、插件（填 plugin）、守秘人（临场裁定）；留空时有插件算插件，没有算守秘人
```

伏笔在调查员第一次来到 `where` 时交给守秘人，一笔带过，不点破；那一轮查东西失败、一无所获时先不露，留到下一次来。写了 `stages` 的，之后每次再来到（或在那里歇过一觉醒来）露出下一步，守秘人同时拿到上一次的样子，写成变化：旅馆的画第二次看多了一个人影，第三次那人转过了头。`when` 未到的步骤先不露，下一次来再看。步骤写了 `flag` 的，露出时设上这个标记（照常触发挂在它上面的事件和大场景）；地点的 `looks` 写 `when: flag:这个标记`，露出那一轮场景图就换成变样的图。存档记每条伏笔已经露到第几步（`signs`）。

伏笔步骤的变样图不提前画：导入和 `autokeeper art fetch` 跳过挂在步骤标记上的变样图，开局也不画。前一步（或第一次的端倪）露出时，游戏才照这个地点此刻的图在后台画下一步的图，下次来时一般已经画好；画好的图先收着，标记成立时才换上，到时还没画完就先用原来的图，画完再换。每张图一局只画一次（存档的 `looks` 记着），没画成的到标记成立时照常再画。本机没有 Codex、关了 AI 画图或这一局能画的图已经用完时不画，场景照旧用文字交代变化。调查员一直没遇到的伏笔不花一张图。

`autokeeper check` 核对步骤的地点、标记和 `when`，挂在步骤标记上的变样图要写在地点的 `looks` 里，不能写在 NPC 上。`autokeeper upgrade` 的「伏笔」一步写伏笔时一并写步骤：某一步的变化在场景图里看得出来（画里多了一个人影、天花板上的水渍又大了一圈），而那个地点有自己的图（`art`），就给这一步设一个标记 `sign_<伏笔 id>_<第几步>`（写进 `flags`，注明露出时由引擎设置），在那个地点的 `looks` 里挂上这一步的变样图，只写 `change`，不写 `art`；每个地点最多两种，全模组最多 6 处，画面上看不出来的步骤不设。补写同样按原作条件核对，复核拿掉的步骤只去掉那一步，连同它的标记和变样图。

打算的每一步分清三种东西：人物已经知道的事写进 NPC 的 `knows`；见面时可以这样演的写 `meet: true`，是素材不是剧本；要守秘人先裁定（某次检定、孤注一掷的结果，调查员的具体做法）才发生的写 `ruling: true`，它不进人物的打算，只在条件到了、人物在场时出现在守秘人的幕后简报里（「要你裁定以后才可能的」）。条件写实际成立的依据：`has_liquor` 只说明调查员有酒，`learned_telescope` 只说明调查员知道了；要等对方当面递酒、有人报告的，能用条件写的用条件（`owner:物件:他`、`knows:他:事实`，线索找到以后用 `knows:players:clue:线索id`），写不出的写进 `only_if`，人物读到的这一步会带上「只在……时才这样」。`once: true` 的见面反应演过一次（回应里的 `played`）就算完成；`once: false` 是一贯的态度，一直留着，写明碰上了才带出；没标的照旧演过就完成。

写了 `agendas` 的 NPC 自动算重要 NPC（每局最多 6 个）。打算的每一步可以写 `does`：做成以后实际成立的事，用 `&` 连接——`at:他自己:地点`（他去哪）、`owner:物件:持有者`（东西到谁手里）、`flag:标记`（剧情标记，可以是某个结局的标记）、`gone:谁`（死了或不见了）。写了 `does` 的步骤到时直接照做，不用调用模型；发生在调查员眼前的会等守秘人来演，立起的标记照常触发挂在上面的事件和结局。没写的步骤到时由重要 NPC 自己决定怎么做。见面时的反应（应门招呼、领人去看、被问到时怎么说）写 `meet: true`，不写 `when` 和 `does`：它是人物资料，调查员在场时交给 NPC 自己演，不在幕后叫醒人物；要他自己在幕后去做的写 `meet: false` 或不写。`autokeeper upgrade` 的「见面反应」一步会给没标过的步骤补上。`autokeeper upgrade <模组>` 会让导入模型补上模组缺的这几项，并补人物性格和口吻、凑够每个结论三条线索、补一两个玩家很可能走到的结局；只补没有的，原作不改，补完校验不过的那一步整步撤掉。

「出场人物」一步（`--only present`）给事件写 `present`：读事件的朗读、守秘人须知和原文，写出当场在调查员眼前的 NPC，没写名字的对照原文认出是谁；已经有事件写了 `present` 的模组不再跑。

## 战斗与追逐

战斗和追逐由引擎按第 7 版规则一轮一轮结算，数值从模组里读，不用插件。

```yaml
creatures:
  - id: coil
    name: 齿轮背后的藤               # 守秘人的叫法
    called: 缠在齿轮上的东西          # 调查员认出它以前的叫法：只写看得见的样子，不写学名、真名和真相；留空用 name
    description: 缠在齿轮背后、还在动的东西
    sanity: 1/1D6                    # 第一次照面时的理智检定
    stats: {生命: 9, 敏捷: 60, 力量: 70, 体型: 50, 闪避: 30, 移动: 7}
    attacks:
      - 缠绕 45%，伤害 1D4+DB          # 名字 命中率%，伤害 骰子式；DB 是它的伤害加值
      - 每轮 2 次                      # 每轮不止一次攻击时另写一条
    notes: 护甲 2；枪伤减半；每轮恢复 1 点
    pursues: false                    # 调查员逃跑时追不追；看情形就不写
  - id: douglas_ghoul
    name: 食尸鬼道格拉斯·金博尔
    npc: douglas                      # 这张卡是 NPC douglas 打起来的样子：同一个人，一条命、一个位置
npcs:
  - id: warden
    called: 楼梯口打盹的老人           # 调查员还不知道他是谁时的叫法，只写看得见的样子
    stats: {力量: 60, 敏捷: 50, 生命: 11, 闪避: 25, 格斗(斗殴): 45}   # 会动手的人才写；空着按普通人
    attacks:                          # 原文写了他的攻击就照抄，写法同怪物
      - 格斗(斗殴) 45%，伤害 1D3+DB
      - 射击（.38 左轮手枪）40%，伤害 1D10
locations:
  - id: office
    chase:                            # 从这里（和它里面的地方）起跑的追逐沿这条路跑，4–12 段
      - id: office_stairs
        name: 报社的楼梯
        look: 楼梯上也堆着一捆捆旧报
        place: office                 # 这一段在哪个地点里；跑进去就算到了那里
        obstacle:
          kind: hazard                # 险阻：边跑边过，失败耽搁、可能受伤，人还是过去了
          what: 堆着报纸的楼梯
          skill: 敏捷
          harm: 1D3
          methods:
            - {id: run, label: 冲下去, skill: 敏捷}
            - {id: slide, label: 顺着扶手滑下去, skill: 攀爬}
      - id: office_door
        name: 报社大门
        place: office
        obstacle:
          kind: barrier               # 路障：过了检定才过得去
          what: 锁上的大门
          skill: 锁匠
          hp: 15                      # 打得破的写耐久，照规则书
          methods:
            - {id: pick, label: 撬锁, skill: 锁匠, opens: true}   # 成功后门开了，后面的人直接过
            - {id: shove, label: 撞开, skill: 力量, opens: true}
      - id: lamp_street
        name: 去广场的街
        links: [back_alley]           # 岔路：从这一段还能去哪几段
      - id: fog_square
        name: 雾里的广场
        place: square
        exit: true                    # 跑到这里就脱身；也是这条岔路的尽头
      - id: back_alley                # 出口后面的段不接着出口，由 links 连过来
        name: 报社后巷
        exit: true
events:
  - id: e_coil
    title: 藤扑了出来
    when: flag:gears_opened
    text: 门一开，藤就扑向离它最近的人。
    sanity: 1/1D6
    sights: [coil]                    # 这次理智检定就是看见 coil 的那一次，照面时不再另扣
    fight: [coil]                     # 当场动手的：调查员在场、还能行动就打起来，下一次输入就是第一轮
    surprise: party                   # party 调查员被偷袭，foe 对方毫无防备
    stakes:                           # 这场打斗的胜负会带来什么
      - when: down:coil | ended:won

        flags: [tower_lost]
```

- **怪物** `stats` 的键用中文：力量、体质、体型、敏捷、意志、生命（`HP` 也认）、移动、闪避，还有追逐里用得着的侦查、潜行、攀爬、跳跃、聆听。生命和敏捷一定要写，没写的按力量、体质、体型各 60、敏捷 50 算。
- `attacks` 一条一种，要有带 % 的命中率：`爪击 50%，伤害 1D6+DB`、`格斗（剥皮爪击）60%，伤害 1D4+2+DB`、`射击（步枪）30%，射程 110，弹夹 5，伤害 2D6+4`。名字里有咬、刺、角、獠牙的算贯穿；`每轮 3 次`、规则书写法的 `每回合攻击次数：3` 定每轮攻击几次。闪避写进 `stats`，写在这里不算攻击。
- `notes` 里引擎认得的特性：`护甲 2`（也认 `2 点护甲`）、`枪伤减半`（也认规则书的“火器和穿刺武器造成的伤害减半”）、`每轮恢复 1 点`、`只被拳头打 6 点就会打晕`、`伤害加值 +1D4`、`体格 1`、`移动 10`。调查员逃跑时追不追写 `pursues`（`true` / `false`，看情形就不写）；旧模组 `notes` 里的“不追”照样认。成群出现、整群当一个对手打的（几十只食尸鬼）不写 `stats`，`notes` 写明成群，`attacks` 可以写规则书里一只的攻击。
- `called` 是给玩家看的叫法：怪物的名字常常就是剧透（《追书人》的食尸鬼就是失踪的叔叔），在调查员认出它以前，屏幕和叙述用 `called`。
- **一个人一条命**：怪物卡就是某个 NPC 变成的样子时（《追书人》的 `douglas_ghoul` 就是 `douglas`，《冬雪之下》的 `erie_entity` 就是 `erie`），写 `npc: <NPC id>`。打起来是同一个人：生命、位置、伤势只有一份，事件和安排里写哪个 id 都指他；怪物卡上写了的数值（攻击、闪避、生命）照怪物卡，没写的（跳跃、攀爬、侦查、智力）用这个 NPC 自己的。一个 NPC 只能有一张这样的卡。
- **NPC** 的 `stats` 只给会动手、或剧情里会被卷进打斗的人写：力量、体质、体型、敏捷、生命、移动、闪避、格斗(斗殴)，会用的武器技能（射击(手枪)、射击(步枪/霰弹枪)、格斗(刀剑)、投掷）。原文写了他的攻击（命中率和伤害）就写进 `attacks`，写法同怪物。以爪击、撕咬为名的一项是他天生的攻击（伤害 1D6+DB）。带着的武器写进 `look`，或在 `items` 里交给他（`owner`）；只有技能、身上没有枪，打起来只用拳脚。调查员可能在不知道他是谁时先碰上的（夜里的人影、街上的老妇人），`called` 写那时的叫法，不带名字。
- **追逐路线** 只给最可能发生追逐的地方写：怪物的巢穴、它够得着的户外、原文写到有人逃跑或追赶的地方。没写路线的地方，追逐沿世界地图上的地点和出口跑。
  - 每段写 `id`（英文小写加下划线，别和地点 id 重名）、`name`、一句 `look`，`place` 写它在哪个地点里：追逐跑进这一段，人就到了那个地点。
  - 段与段连成一张图：一段接着列表里的下一段；`links` 写从这一段还能岔去的段（段的 id 或名字）；`exit: true` 的段跑到就脱身，它也是一条岔路的尽头，列在它后面的段不接着它，要由别的段的 `links` 连过来。
  - 附近地点的路线经过同一处时用同一个 `id`、同样的写法，引擎把起跑地点和两个出口以内的地点的路线按 id 合成一张图（《追书人》的金博尔家、公墓、陵墓和隧道就是一张图：从屋后的小路一直能跑进地底的岔路）。
  - 大约一半的段有一处 `obstacle`，照规则书分清两种：`hazard` 险阻边跑边过，失败耽搁、可能受伤，人还是到了下一段（矮墙、矮栅栏、灌木丛、泥地、湿滑的台阶）；`barrier` 路障不过检定就过不去（高墙、锁着的门、深沟、钉死的窗）。
  - `methods` 写过它的几种办法（最多 4 种），各有 `id`、给玩家的按钮 `label`、用的 `skill`（跳跃、攀爬、敏捷、力量、闪避、锁匠、游泳这类技能或属性）和难度；路障的办法成功后就打开了、后面的人直接过的写 `opens: true`。`skill` 写最常用的那一种；不写 `methods` 就只有它一种。
  - `harm` 是失败时受的伤，骰子式（`1D3`、`1D6`），照规则书的其他伤害表：摔一跤、撞一下 1D3，火、狗咬、摔到草地 1D6；只耽搁不受伤就不写。
  - 打得破的路障写 `hp`，照规则书的耐久表：室内门或薄围栏 5，普通后门 10，坚固的外门 15，9 寸砖墙 25，大树 50；打不破的和险阻不写。
  - 只写那里和周围真有的东西；追逐时玩家会看到跑过和看得见的路段，不写线索和秘密。
- **事件里写定的袭击** 只写原文明说这件事发生时就扑上来、开枪、动手的；要看调查员怎么做才动手的不写，由裁定员临场判。正在打的战斗里，新来的对手加入进去；追逐中不另开打斗。一开始就是追逐的写 `chase`（追或逃的人或怪物）和 `chase_party`（调查员是逃还是追，留空算逃）；写了 `fight` 就不写 `chase`，打起来以后调查员逃跑，会追的对手自己会追。
- **胜负后果**（`stakes`，最多 4 条）：写了 `fight` 或 `chase` 的事件，原文写明的每种收场一条。`when` 用条件写：世界的 `flag:标记`、`at:谁:地点`、`gone:谁`，加上遭遇的 `down:谁`（倒下）、`dead:谁`、`escaped:谁`（脱身）、`caught:谁`（被抓住）、`surrendered:谁`，谁写 NPC、怪物、预设调查员的 id 或 `players`（调查员一方）；`ended:` 写整场怎么收场：`won` 赢、`lost` 输、`fled` 逃了、`escaped` 脱身、`caught` 被抓、`parley` 谈和、`surrender` 投降、`dispersed` 散了。`&` 表示且，`|` 表示或。遭遇收场时条件成立，就设上 `flags`（已声明的标记），挂在标记上的事件和结局照常触发。
- **照面理智**（`sights`）：怪物第一次照面要过 `sanity`。事件自己的理智检定就是看见某个怪物的那一次时（《追书人》看清倒地人影的脸、几十只食尸鬼现身），把怪物 id 写进那个事件的 `sights`，照面时就不再另扣一次；没有 `fight` 的事件也可以写。`check` 会提醒事件有理智检定、打起来的怪物又有照面理智、却没写 `sights` 的。

`autokeeper check` 会提醒引擎读不出的：没有命中率或伤害的攻击、缺生命或敏捷的怪物、没写 `called` 或 `called` 带着名字的怪物和 NPC、会开枪却没带枪的 NPC、不是 4–12 段的路线、从起点跑不到的段、同一个 id 写法不一样的段、用了不存在的技能的障碍和办法、不是骰子式的伤害、没写耐久也打不开的门和墙、险阻上的 `hp` 和 `opens`、可能扣两次的照面理智。算错误的是指向模组里没有的东西：`fight` / `chase` 点了不存在的人或怪物、`npc` 不是 NPC、一个 NPC 两张怪物卡、段的 `place` 或 `links` 找不到、一条路线里两段同一个 id、`stakes` 的条件或标记不对、`sights` 不是怪物。`autokeeper upgrade` 的「战斗与追逐」一步（`--only combat`）会给已经导入的模组补上这些：数值照原文，原文没写的按规则书里同类怪物的数值，不新添能力和设定；没有 id 的旧路线会重画一遍。

## 开局演出（prelude）

新开一局时，先整屏播放几幕开局演出，再进入游戏界面：每幕一张图缓慢移动，配一两句逐字出现的字幕，只介绍故事背景（时代、地方、气氛、事情是怎么找上门的）。演出播放时，导演在后台为这几位调查员改编模组；两样都完成后进入游戏，守秘人马上开讲，不让玩家对着空的游戏界面等。按任意键看下一幕，Esc 跳过；看完了后台还没准备好，会停在最后一幕显示「开场准备中」。联机时所有人一起看，准备好后一起进入游戏。

```yaml
prelude:
  - art: huochezhan
    text: 火车驶进阿诺兹堡。木站台被行李车磨出两道白痕，蒸汽散开，站外小食铺窗上蒙着热气。
  - art: jinboer_jia
    text: 托马斯请你住进空置的房间，付 10 美元，找回书，也查清叔叔道格拉斯的下落。
```

- 2–6 幕，每幕字幕不超过 80 字；`art` 可以留空。
- 图只能用开局就能公开的：封面、开场地点、钩子或背景里点名的地点、标为 `public` 的地点。
- 字幕只写玩家开局就知道的事，不能和真相、守秘人须知、NPC 秘密、线索原文有重合（检查方式同 NPC 泄密检查）。
- 编译时自动写（改编步骤「开局演出」，只给模型看玩家知道的内容，不合规的幕会去掉）；没有写的模组用模组名、时代与背景、钩子拼一段默认演出。

## 大场景（showcases）

开局的氛围、突发事件、生死关头、关键地点、怪物现身、最终 boss 和每个结局，各可以写一个大场景。到了那一刻，屏幕上只剩一张大图和一行短标题；叙述在后面照常进行，按任意键、点一下或约 8 秒后自动收起，要掷骰时让路。每局每个最多出现一次。

```yaml
showcases:
  - id: sc_horde
    kind: 最终boss                  # 开场 / 突发 / 危机 / 重要场景 / 怪物 / 最终boss / 结局
    when: event:e_horde             # opening / visit:地点 / event:事件 / creature:怪物 / flag:标记 / ending:结局
    title: 细碎的脚步声              # 玩家此刻看得见的短标题，不剧透
    prompt: 月光下的墓地，几十张犬一样的脸从墓碑后面探出来……   # 画面描述，只在房主这边
    base: mudi                      # 可省：照这张原图重画；默认用触发的地点的图
    art: ""                         # 可省：模组自带的、正好合适的图
```

图按这个顺序来：模组自带的 `art`；本机有 Codex 时照参考图（`base`、触发的地点，或联网搜到的照片）重画，没有参考就照描述画；没有 Codex 就不生成，只把模组里那个地点的图或搜到的照片原样放大（联网搜索关掉时不搜）。生成的图放在 `data/cache/showcases/<模组>/`，不进模组目录，计入每个模组 100 张的额度。游戏开始后在后台一张一张提前准备，开场优先；到点还没准备好就跳过，不等。`autokeeper showcase <模组>` 可以在开局前全部准备好。`creature:` 在怪物的名字第一次出现在事件或叙述里时触发，要精确控制就用 `event:` 或 `flag:`。导演即兴时也可以加，每局最多三个，图跟着存档。

## 开局与日常

`start` 是玩家第一次能行动的位置。可以从车站、街口或旅店引入，再由玩家决定怎么赴约；不要在 `opening` 里提前替玩家见完委托人、安顿完行李、选好调查方向。开局地点必须在 `locations` 中，并用 `exits` 接入地图。

《追书人》从火车站开始，经过镇中心与艾尔斯伯里大街到金博尔家。玩家可以沿途问路、吃早饭、闲聊，也可以直接赶路；直接前往远处时，守秘人会收到沿途地点的公开描述。路过不等于进门调查或取得线索。

生活场景可以没有线索、检定或恐怖事件。NPC 要有自己的营生和牵挂，按玩家兴趣展开；已有的剧情时钟仍会走。导入时补的抵达场景和普通人物，在 `keeper_notes` 中注明“AutoKeeper 补充”，不改原作案情与必需事件。

路段默认 10 分钟；例如 `travel_minutes: {town: 15}` 把去相邻 `town` 的时间设为 15 分钟，反向未写时沿用这一数值。双向都写时必须一致。路线选择按累计耗时计算；普通一句问答可以不推进时钟，吃饭、搜索和休息才按实际耗时推进。不要把秘密入口标成 `public`。

## 原作图片与信息完整性

导入 PDF 时保留逐页原文、页面预览和去重后的内嵌原图（`source/images/index.json`）。导入时原样复制图片，并保存 ASCII 图与配色。场景原图的键要与 `locations.art` 对应；完整病历、地图、信件另用 `handouts.images` 绑定，不能只写进被运行时覆盖的 `pictures` 字段。

默认用彩色 ASCII 显示，原图仍保存；文字转录必须可独立阅读，字迹无法辨认时注明不确定，不猜写。完整版地图、怪物真容和带幕后文字的整页不能提前展示。联机只传已公开的场景图和已发现的手稿图；手稿传送较大尺寸供放大阅读，房主仍保留完整原文件。原作特有但引擎未实现的规则须在 `keeper_notes` 明确记录，不能改成无条件伤害或虚构固定时间线。

## 校验与编译

改完模组后先检查，再补全和配图：

```bash
autokeeper check modules/<id>      # 检查引用、可达性、线索冗余、字符画尺寸与蒙版，并推演一遍
autokeeper upgrade modules/<id>    # 补上缺的人物、建筑内部、场景呈现、关系、打算、伏笔、战斗数值与追逐路线（调用导入模型），再给没有图的地方配图（--no-photos 不配）
autokeeper art fetch modules/<id>  # 只做配图那一步
```

`check` 的推演不调用模型：从起点出发，把模组里能走的路都走一遍，报告走不到的地点、拿不到的线索、不会发生的事件、到不了的结局、少于三条线索的结论，以及离不开某一处或某一个人的结论；再按模组自己的日程把没人插手时的三天走一遍，指出哪一步之后某个结论再也拿不到。

疾病、计数器和自定义行动这类特殊机制用规则插件实现，见[插件开发](plugins.md)。
