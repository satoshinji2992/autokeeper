## 确认仍存在的问题

### F4-01 / P2：放回、留置物件仍未成为实际归属变化

T4 玩家明确“将原日记放回抽屉”，KP 结尾明确“抽屉合上，日记回到原处”。T9 玩家与 KP 都说纸条压在陵墓门外、用小石块防风。T15 和最终物品栏却仍列出“道格拉斯·金博尔的日记”“小石块”“空白留言纸条”。这会影响后续查看、交付与遗失的规则可信度，不能仅用正文说已放回作为通过证据。

封存后核对 T4/T9 全调用，确认本次主要缺口与 fix3 的同名影子不同：

- T4 裁定正确引用 `document:c_diary`，却把“原样放回书房书桌抽屉”填进 `equipment.status`，没有实际 Transfer。普通 fact 同时写已放回，不能代替归属。
- T4 scene 用 `things.holder=道格拉斯的书房` 表示桌上便条，被拒绝，因为 things 表示由现场人物拿出的东西；第二稿改用 holds，却引用未登记便条及未登记的细部位置。
- T9 首稿 holds 把纸条与石块放到“陵墓门外避雨的凹处”等未登记目的地，且纸条尚未登记；第二稿退为由调查员拿出这两样东西，再留“已经在门外”的痕迹，实际实体仍归调查员。

这是结构化物理操作的入口与上下文交接问题。应让模型看见可用的本地物件真实 ID、现有地点与持有状态，清楚区分“拿出日常物件”“把已有物件放置/归还”“改变余量/状态”；不能靠 fact、status 或 trace 自动推断转交，也不需要为日记、纸条、石块分别加规则。

Root 后续的新物件引用提示与两个独立短探针属于**本局封存后的验证**，没有加载到 T0–22。本报告不据此声称本问题已在完整复测中消失。

### F4-02 / P2：场面结构反复拒绝与降级，增加等待并延后实际事实

本局没有需要玩家 `/retry` 的剧情回合异常，格式失败也没有作为隐藏 JSON 显示。但私有 scene 日志中仍有 **18 次 rejected、7 次 settled 降级记录**，不是 18 次玩家失败：包括重复登记现有 NPC、把人名/细部地点填错字段、未登记物件、未知剧情标记、路程时间不足、遗漏原有在场人物等。

T17 两次都漏掉系统仍认为在书房的莉拉，最后按能成立部分降级；本次守候完整轮耗时 88.41 秒、首段文字约 86.75 秒。T18 完整轮 70.29 秒，T20 为 54.50 秒。不能把这些时间全部归为 JSON 修复：其中有安排、NPC 主动参与、后台世界推进、场面重写与最终正文等不同职责。原始 call metadata 另有 18 条 `repairs=1`，与 scene 拒绝是两类记录，不能相加当独立故障数。

T20/21 的批注本没有已登记物件身份，scene 因此无法完整落地，T21 实际告别仍未结束程序。T22 的有效场面才提交离开并自然结局。校验确实阻止了无效场面的标记生效，但需要更充分的引用上下文，使合法的取书和告别可以一次完成。不能通过删掉检验、从正文抽取事实或自动赋予隐藏物件来追求少调用。

### F4-03 / P2：通关后复盘的驱动输出异常，与引擎结局分开

T22 已保存 `ended=true`、SAN 56、神话 3 后，`op=debrief` 将完整复盘写入 `player.jsonl`，随后在驱动 `play.py::emit_row` 的 TTY `print` 抛出 `BlockingIOError: [Errno 11] write could not complete without blocking`。未重新付费调用复盘；只用同 slot `--load` 核对并 close，仍保留同一结局与角色状态。

这是试玩驱动的大段输出管道问题，不算剧情失败或存档丢失。字符长度阈值与实际 UTF-8 写入大小、非阻塞 TTY 行为并非同一约束，应由驱动输出层处理。
