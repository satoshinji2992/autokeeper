# 智能体分工与约定

一局游戏由一个确定性的引擎和一组模型角色共同完成。这份文档说明它们怎样分工，以及改动时必须守住的约定。依据是一局真人存档（《追书人》118 轮，审计记录在 `dev/output/save-audit/`，不进仓库）和对它的逐轮重放（`autokeeper eval session`）。

## 当前确认的目标架构

本轮用户确认采用“KP、记录库、模组日程”的分工。**KP 读取全部信息，拥有最高主持权限。** 人物动机、连续上下文、相关真相与幕后安排共同参与主持判断；对玩家的输出受当前披露范围约束，NPC 配音仍只知道角色自己的事。记录保存与上下文按需加载，不改变 KP 的访问权限。

| 部分 | 目标职责 |
|---|---|
| KP | 理解完整意图，安排现场及人物行动，输出叙述和配套世界操作；校验失败后按具体问题修正一次 |
| 记录库 | 保存世界状态、事件、知识、约定、说法和改写，作为 KP 的笔记本 |
| 模组日程 | 按时间和条件执行已写明结果的步骤与事件，不调用模型 |
| 导演 | 时间跳过、换场景或关键条件成立时，一次安排重要人物的幕后动向，现场影响交给 KP 决定呈现时机 |
| 裁定员 | 保留独立规则判断，读取结构化行动及确认条件，不看玩家原话 |
| NPC 配音 | 按角色知识扮演，台词与本次实际动作同次输出；有意欺骗与事实操作分别记录 |

撤除每轮 NPC 自主推演、待演与待审两套独立队列，以及运行时叙述语义复核。程序继续负责权限、位置、物品、执行条件、去重和恢复等确定性校验；世界操作通过后再展示，不能从叙述反推事实。原有异步图片或场景准备的过期检查保留，不因撤除人物调度而连带移除。

实施顺序为：关闭当前叙述核对开关；KP 全量知情并增加泄密评测；迁移 NPC 日程和集中幕后安排；接入场面快照、结构化操作与现场主动行为并移除运行时删句；最后才合并意图理解，合并前须通过 `eval rhetoric`。在场 NPC 每轮由 KP 判断是否主动行动；不在场 NPC 按日程或触发点集中处理。统一幕后调用按人区分所知，逐人检查操作，不另设导演待审。

场面快照和操作有错误时给出具体原因，修正一次。仍未落实的事项写入下一轮报告，技术失败不改写成角色退缩；独立操作可分别提交，互相依赖的因果链整体处理。不做程序删句，也不显示宣称未落实动作已完成的稿件；整稿暂存与下一轮接续的发布策略尚需定稿。阶段细节见[分阶段计划](development-notes-2026-10-20.md#分阶段实施与验收)。

以上是目标，尚未完成代码迁移。下文调用图与部分约定记录当前实现，不代表应永久保留。具体差距与审核证据见[开发记录](development-notes-2026-10-20.md#代码复核限制怎样削弱了主持能力)。

## 恐怖、失败与终局

完整的跑团体验包括失败、死亡、疯狂和无法挽回的损失。系统不保证破案、角色生还或精神健全；调查员全灭、永久疯狂或选择撤离，都可以形成完整结局。导演按模组题材、原有危险程度、人物动机和玩家偏好构思恐怖遭遇，允许有动机的敌人实施致命计划，不因结局不利而自动安排救援、补偿或逆转。

这些结果不作为导演追求的目标。《追书人》这类简单模组应重在调查、人物关系和真相揭示，不为增加张力额外加入追杀、大幅提高理智损失，或把原本无恶意的人物改成杀手。玩家实际触发原作危险时照常结算；顺利调查、解决委托和平静收束也应成立。更高的恐怖强度须来自当前模组和局势，不默认向所有故事追加。

后果由已经成立的局势、人物行动、检定和规则共同产生。死亡与疯狂不设配额，不为了指定结局修改骰点、提高难度或否定玩家的成功。角色的伤害、理智损失与疯狂状态由规则结算，KP 如实叙述；前台台词和后台计划都不能绕过结算直接宣布玩家角色死亡或疯狂。日常与缓和仍有价值，让危险和失去有具体依托。

## 一轮里发生什么

这是当前运行链路；完整 KP 主持、按日程集中处理幕后事项的目标尚未接入。

```text
玩家的话 → 守秘人安排(plan) → 裁定(arbiter) ┬→ 引擎结算 → NPC 开口(npc) → 守秘人叙述(keeper) → 记录
                                               └ 模组没写到：导演补内容(director)
回合之后：重要 NPC 自己做决定(world)，整理旧对话(summarizer)，写「故事至今」(progress)
```

- **引擎**掷骰、给线索、推进时间、移动人物，所有改变都落进世界记录（`world/`）。
- **守秘人安排**（`Cast.plan`，单独的 `plan` 会话）看着底牌和幕后简报，把玩家的话变成结构化的行动（填法和原来的解析一样，不加不减；摘要会上屏，只用玩家知道的名字），再决定在场的人这一轮要不要主动开口（`initiative`，宁少勿多，程序只按 id 过滤：此地、活着、模组里有）。主动开口的人照常走 NPC 配音，这一轮幕后推演不再唤醒他。资料不够时它在 `lookup` 里写一句想查的事，程序从世界记录（被点名的人在哪、知道什么，相关事实和事件，含改写）和模组原文索引里找出来，附在同一份输入后再问一次，每轮最多两次；和 NPC 幕后决策的查询一样只靠 JSON 字段，不用哪家的函数调用。安排失败时退回**解析**(intent)。**裁定**只看结构化行动和场景资料，决定要不要检定、成功能得到什么。
- **NPC** 用自己知道的事说话，台词里答应、交出、同意同行的事，经过世界操作才算数。
- **守秘人**看得到全部底牌。每轮先交一份安排：把玩家的话整理成行动，决定在场的人会不会主动参与，资料不够时先查原文和记录；结算以后再讲结果、加上氛围。不掷骰，不替裁定员决定检定结果。
- **world** 替重要 NPC 在幕后做决定（模组给了打算、没标重要的人只跑有时间或条件、有结果的固定步骤，不叫醒他做判断：`Agent.passive`）；**导演**在模组没写到的地方补人物、地点和线索，也可以改写玩家还没接触到的设定。

## 八条约定

以下兼有当前实现与原有设计取舍。涉及 NPC 独立调度和模型复核的部分将随目标架构撤除，不能把其存在本身当成体验改进。

1. **世界记录是唯一的事实。** 谁在哪、谁跟着谁、东西在谁手里、找到了什么、过了多久，都以世界记录和引擎结算为准。叙述、NPC 台词、计划说明都不是事实的来源。
2. **先结算，后讲述。** 会改变世界的事（有人同行、交出东西、出现新物证、时间推进）先变成世界操作结算，叙述只讲结算过的结果。要靠结构做到，不靠给守秘人加提示：在报告里点名「谁不在这里」反而让守秘人把他写了进来（见下文实测）。该动的是前面几步：同意同行走 `follow`，到别的房间找人由解析换成移动，NPC 的转交和约定从台词里结算。最后一道是守秘人的场面快照：守秘人先写这段讲完时的场面（谁在场、谁跟着、东西到了谁手里、拿出来的日常物件、新痕迹、眼下在进行的事），程序把它和记录比出差异，按人和物分组校验后落地，通过了才把叙述流式显示（`world/scene.py`、`Game._narrate`）；不通过就带着原因退回重写一次，再不通过只落能成立的部分，让守秘人照它写，不删句。
3. **所有角色看同一个场面。** 在场的人、同一栋房子别的房间里的人、同行的人，由世界记录统一给出（`world/context.py` 的 `nearby` 等），解析、裁定、NPC 和守秘人读的是同一份，不各自从模组的静态资料里推断。
4. **规则助手使用整理后的行动。** 当前裁定员不看原话，防备由解析写进 `precautions`；历史话术诱导对照为 7/40 对 2/40。新架构保留这项隔离，由全知 KP 掌握原话、意图和方法，并补足规则请求中的遗漏。这组数据未测量复杂意图的漏读率。
5. **后台准备避免阻塞无关行动。** 当前世界任务虽在回合后启动，下一次 `parse` 仍等待整项 `_world_settled`，不能声称玩家无需等待。目标是按日程和关键时机集中处理，由 KP 接管眼前变化，独立资源任务不阻挡无关行动。当前导演方案仍有最多五分钟的等待与首图降级机制，这是恢复上限，不是已验收的延迟目标。
6. **用真人的局来评测。** 改了提示词或流程，就用 `autokeeper eval session <存档>` 重放一局真人存档：每一轮从当时的局面、用玩家原话和当时的骰子跑现在的流程，再由一个核对模型对照世界记录挑出叙述里的矛盾。AI 调查员的自动跑团既费钱，也不像真人，不用来代表游玩体验。
7. **导演可以改世界，但记录不能乱。** 为了让跑团更顺、冲突更有戏，导演应当主动改写世界记录，玩家见过、听过的事也可以改出另一个真相（有人撒谎、记错、伪造、设局），只要自圆其说：旧版本留作玩家当初的所见所闻，改写写清玩家为什么会看到、听到那样，再过一次模型检查。玩家手里线索的原文不变；改写只改真相，不挪人、不改同行和持有。NPC 在正常情况下照约定行事、人的位置和同行准确，这些比戏剧性优先。
8. **幕后放开，台前归 KP。** 调查员不在场的事直接发生；会改变调查员眼前场面的事先排成一段待演的戏，由 KP 挑时机上演，演的时候才结算、马上讲出来，所以不会出现「记录里人走了、叙述里人还在」。对调查员的承诺（同行）只有当面才能结束。会改变故事走向的事（有人死了、重要物件换手、引出结局的标记）校验过就直接落地；过夜、赶路这样的时间跳过以后，导演看一眼局面，可以做幕后调整（`Game._look`）。重要 NPC 的幕后决定按时间段合成一次调用，各人只看自己那一份资料，依据只能引用自己那一段；见面时的反应是人物资料，交给 NPC 自己演，不在幕后叫醒它。规则写在一处（`world/stage.py`），不按每种冲突打补丁。排着队的行动记着当初凭什么决定（看见的人和东西、知道的事、计划这一步的条件），轮到它时这些变了就作废，让人物按眼下的局面重新决定。原作路线中断不构成程序拒绝的理由：证人死了、证据毁了，导演可以在后续即兴里建立新的线索和路线，也可以让调查以失败或代价收束；编译期的推演只用来找模组结构的薄弱处。

## 实测

《追书人》一局 118 轮的真人存档，DeepSeek flash，详见 [评测](eval.md#真人存档重放)。

- **玩家每轮要等的模型时间**：单轮重放里，重要 NPC 的决定在回合里做时约 22 秒，挪到回合讲完之后约 7 秒。这组数偏高：重放每轮都从原存档起跑，同一个 NPC 每轮都被重新叫醒一次（重放里 world 每轮平均 2 次、合计 12.8 秒，多数决定是「再等等」）；真实那局 118 轮里，NPC 的幕后思考一共 26 次。
- **复述台词**：NPC 开口后守秘人复述台词，当时的记录里 68%–78% 的回合有，现在是 0。
- **叙述和记录对不上**：核对模型挑得出大多数（审计列出的 9 轮里挑出 8 轮），但自己也有噪声，同一份叙述核两次能差 4 轮，只适合比较同一次运行里的两边。
- **场面提示没有用**：在守秘人报告里加「谁在别的房间」「谁不在这里」「不要补新物证」三句，85 轮对照里有矛盾的轮数从 8 升到 14，没有留下。
- **修辞诱导**：裁定员看原话 7/40，只看解析结果 2/40（两次都是模组本来允许的）。

## 还没做的

- **核对只在评测里。** 叙述显示前的核对（读两遍、取并集，再删句）已经撤掉：误报会删掉本来没错的句子、留下指代悬空的残句，每轮多等几秒，叙述也不能边写边显示。重放评测还用同一套规则，评测里的零矛盾不等于真的零矛盾，要抽样人工看。
- **场面快照只管人、同行、物件和痕迹。** 叙述里补出的其他细节（伏笔、气氛）仍只在叙述里；场面快照的效果要用 `eval session` 重放真人存档再量。
