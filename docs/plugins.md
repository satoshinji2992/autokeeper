# 自定义规则插件

插件补充通用引擎没有的玩法：持续计数、疾病与感染、特殊法术、资源消耗和有参数的自定义行动。人物、场景、物件仍用模组或即兴方案创建。显示继续使用彩色 ASCII；规则状态由程序保存，不依赖模型记忆。

## 由 LLM 开发

模组编译 Agent 会读 `_example/plugins.md` 与 `plugin-output.schema.json`，用 `write_plugin(content)` 提交完整插件 JSON。工具真正运行测试，只有通过才保存源码、清单并登记 `module.yaml`。错误会指出具体字段、实际效果和测试预期，Agent 可以修改后重试。

即兴导演的 `plugins` 字段接收同样的插件定义，一次最多一个。方案先做结构与代码校验，再执行所有测试，然后加入本局。源码连同即兴方案与已运行版本保存，重新载入时恢复该版本；同名升级必须增加版本号，并兼容已有状态。日常聊天和已有规则不需要重复开发插件。

## 文件与协议

```text
module.yaml                       # plugins: [my_rule]
plugins/my_rule/manifest.json      # 元数据、hooks、能力、动作、初始状态、测试
plugins/my_rule/plugin.py          # handle(event, ctx, api)
```

接口与例子见 [API v1](../src/autokeeper/plugins/API.md)。代码接收本插件状态、时间、位置、调查员与剧情标记；返回新状态和声明式效果。可以调用宿主的骰子、CoC 检定，并提交属性变化、状态、伤害、理智、已声明标记、已解锁线索或公开叙事。HP/SAN、重伤与疯狂继续走现有规则。

自定义动作须在 `actions` 声明名称、适用条件和参数。裁定员只能根据玩家实际行动调用这些动作，不能宣告插件尚未给出的结果。`start` 在首次启用时初始化，`visit` 在到达时执行，`turn` 在行动及时间推进后执行；插件应自行检查时间和重复条件。

## 玩家看到什么

插件代码由模型写成、在玩家的机器上运行，联机时别的玩家的话也会传到写插件的导演那里，所以对玩家公开的只有已经发生的事：

- `Ctrl+K` 的规则插件窗口用玩家能懂的话说明每条规则：它做什么（manifest 描述）、可以尝试的自定义动作及时机（来自 `actions`）、插件自愿公开的一行状态（`status`，如“风寒：第 2 天”，默认不显示私有计数）、本局最近产生的公开效果，以及被暂停时的原因（平实的一句话，不给堆栈）。
- 规则每次产生公开效果，会在故事里出现一行以插件名标注的简短提示；伤害、理智、属性等仍照常走各自的卡片。
- 自定义动作是可发现的：输入框的 → 补全和 F5 出主意都知道这些动作，玩家不必记动作名，照常用大白话描述即可，由裁定员调用。
- 联机玩家通过房主下发的脱敏信息看到同样的公开内容：名称、描述、动作、状态与最近效果；源码、私有计数、错误详情和未公开规则留在房主一侧。

## 从一句话加家规

玩家（联机时也包括房主）可以在 `Ctrl+K` 里用大白话加一条规则，例如“每过一夜要吃一顿饭，不吃 HP 减 1”。作者 Agent（使用配置好的模型；测试里用预设作者）据此写出插件和测试，沙箱实际运行测试，只有通过的插件才装进**本局存档**，绝不写进模组文件。过程会显示进度；失败会说清哪里不对，并可改一句话再试。联机时请求发给房主，由房主一侧撰写、测试并安装，结果同步给全桌。装好的家规随存档保存，重开时由引擎从存档恢复；升级同名规则必须提高版本号并兼容旧状态。

## 执行与恢复（沙箱）

插件代码先做 AST 校验：不许导入、不许 `__xxx__` 私有属性、不许帧/全局/内建把戏（`gi_frame`、`f_globals`、`str.format` 遍历等）、不许 getattr/eval/exec/compile/open，只允许白名单内建。再在独立、隔离（`-I -S`）的 Python 子进程里执行，环境清空、不继承 API 密钥；进程内设 POSIX 资源上限（CPU、内存、禁止写文件；Windows 没有这些时由墙钟强杀兜底），并装一个运行期审计钩子，拒绝文件、网络、子进程和导入事件。代码、输出、状态、执行时间和检定次数都有上限。插件只经宿主 API 提交效果，所有引用与能力先校验再更新人物卡和私有状态。失败只暂停对应插件，其他规则继续运行。

状态、源码版本和执行记录随存档保存，相同回合/事件的恢复不会重复扣数值。后台即兴插件与玩家加的家规都只随本局保存，不修改原始模组。

## 使用与检查

- 标题页“设置”可整体开关规则插件。
- 游戏内 `Ctrl+K` 查看、暂停或重新启用单个插件，并可加家规；不展示幕后状态。
- `uv run autokeeper plugin list <模组>` 列出模组的插件与自定义动作；`uv run autokeeper plugin test <插件目录或模组>` 在沙箱里实际跑测试。
- `uv run autokeeper check modules/<id>` 同时执行插件测试；编译也会检查，失败不会报告成功。
- `uv run pytest tests/test_plugins.py -q` 验证插件协议、沙箱逃逸被拦截、实际宿主掷骰、失败隔离、存档恢复、版本升级和家规安装。
- MCP 主持可用 `list_plugins` 查看动作，`plugin_action` 实际执行；开局与推进时间也会经过插件结算。

编译包保留 `assets/plugins/` 中的代码和测试、`references/plugins.md` 中的接口，以及原文档案。宿主已经结算的效果不能再由叙述模型重复结算。
