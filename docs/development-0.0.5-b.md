## 一份世界，多份见闻

世界状态仍由房主维护，KP 看到全部信息。日志与人物经历增加可选 `audience`：没有标记表示公开，调查员 id 列表表示只有这些角色获知，空列表表示仅后台可读。旧存档按原来的公开语义加载。消息的真假由来源与局势决定，不能因为收到一句话就把其内容确认为世界事实。

联机的 `/私聊 姓名 内容`、`/w id 内容` 向同场同伴发送私语，发送者取真实座位，不能冒用别人的角色。普通点名交谈仍让同场的人听见；场外聊天继续广播。NPC 不因站在附近就自动听见明确私语；察觉、偷听或截获仍需后续场面裁定。

对白在显示前同步写入记录并保存，删除原先下一行动才登记的队列。已送达后有人移动或昏迷，不再让这句话因重新核对位置而丢失或卡住。

KP 的既有结构化回应增加 `asides`，每段填收件人和正文。它与公共 `text` 属于同一次调用；只有被采用的回应才会投递私人部分。场面重写时，废弃回应的私信一起作废。接受后的收据、私人日志与投递范围进入既有回合恢复流程，中断续接不重复生成或登记。

## 过滤覆盖存储、分发与模型输入

房间在服务器端按座位过滤即时消息、人物经历和重连历史；入座前只给公开记录，换座时替换上一角色的私人历史。私人见闻属于角色，接手空座位会继承该角色的知识；没有另建玩家账号认证体系。开发者记录仍保留完整信息。

公共地图解锁、事实公开核验、灵感提及统计、进展、前情和经过摘要均排除私有日志。否则“甲梦见黑池密室”虽未直接发给乙，仍会从乙的地图和图片中泄露。调查员 AI 与行动建议只补自己收到的私人记录；本地 AI 队友也按自己的角色组装上下文。KP 的近期记录保留完整受众标记；规则助手仍是主持侧助手，不声称具有 NPC 那样的角色知情隔离。

公共经过压缩时，只汇总公共内容，私有原文另存于同一存档的 `private_history`，不请另一个模型整理。个人近期上下文可包含其中的旧记录；原文保存不等于所有历史每轮都全文注入。

## 收敛限制，而非增加主持角色

删除 NPC 公开动作与秘密的字符比对否决：自己知道的秘密可以按动机主动透露，同义改写也不再决定操作能否通过。保留真正的身份、位置、持有物和未知事实检查，不恢复叙述删句。

本批没有增加每位玩家的常驻 KP，也没有增加消息审批模型。仍待处理的三项是：独立改写审批、按固定输入数强制候演离场，以及逐人裁定后再汇总多人行动。它们需要分别并入主持安排，不能通过简单删除恢复凭据、既定日程和操作校验解决。详见[架构审阅](architecture-review-0.0.5.md)。
