# 跨场时间衔接

2026-10-23。实现在独立分支 `codex/disconnect-ai-takeover`，尚未合入发布主线。

## 处理原则

各场 KP 可以判断何时略过空白时间，不把普通分头调查绑在同一轮。KP 仍须保留玩家的关键决定；战斗、追逐和未答检定按原回合办理。进展摘要维持原来的后台整理方式，本次没有改动。

之前，某场声明了二十分钟的返程，另一场仍在短交谈或等待输入，前者就只能等对方逐步推进或明确结束输入。发布试玩中的一段返程因此等了约九分半现实时间。

## 当前实现

- 只有实际出现跨场时间阻塞，才询问较慢一场的 KP。使用该场现有的主持模型、备课资料、会话和各人的近期经过，不增加常驻角色。
- KP 只判断能否略过到指定时刻的空白时间，不替玩家行动，不生成调查、交物、发现或抵达结果。有迫切决定、限时机会或必须先落实的日程时，应拒绝跳时。
- 程序只在该场没有进行中的行动、遭遇、待答选择、排队声明、私信或正在续办的等待时接纳建议。尚待意图交给 KP 判断，不作为程序锁；新声明优先，取消尚未落实的时间建议和许可。
- 同意只授予有截止的时间许可；原行动真正提交时才对齐时间，并向该场同步时钟。存档恢复沿用原声明、原截止和已结算结果。
- 同一场面、同一期限被明确拒绝后，不因轮询或无关世界变化反复调用模型。过时的同意不会落实，必要时根据新记录重新判断。

时间建议使用一份临时会话副本，避免取消时改动正在使用的主持会话。任务在新行动、现场关闭和停服时取消并回收；调用记录标为 `scene_time`，理由仅供开发者查看。

## 验证与限制

新增离线回归覆盖实际 WebSocket 时间衔接、拒绝后继续输入、原掷骰确认、声明竞态、世界变化后的重新判断、晚获知的额外耗时、存档恢复和会话隔离。使用脚本模型及预设骰，没有调用付费模型或改写试玩存档。

这条通路消除的是可以略过的空白等待，不承诺任何情境都立即推进。KP 拒绝、玩家有未答决定，或双方确实争用同一人物或物品时，仍保留必要的衔接。模型是否准确识别可跳过的时间，尚需真实游玩验证。
