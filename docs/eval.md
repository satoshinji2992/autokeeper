# 评测

评测命令与历史结果见下文。运行报告写入 `dev/output/eval/`。

## 连续游玩体验

```bash
uv run autokeeper --preset codex eval experience --turns 12
uv run autokeeper --preset deepseek eval experience --actions actions.txt --out dev/output/eval/my-route.json
```

`actions.txt` 每行一句玩家行动。默认路线包含到站、闲逛、早餐、日常交谈、约定与赴约；使用真实的解析、裁定、NPC、导演和叙述。报告记录全文、逐轮等待、调用量、时间推进、世界记录与中断位置。叙事质量仍需阅读记录判断。试玩会产生模型用量，关闭额外绘图以单独观察叙事。

审阅时重点检查：是否替玩家行动、是否强推主线、约定与物品是否前后相符、是否泄密、NPC 是否重复自己的回答和动作。自动回归另覆盖二十轮日常、借还、沿途停留，以及断线后从存档恢复。真实模型超时会写出部分报告并返回失败，不能算整条路线通过。

2026-10-18 本机验证：Codex 默认模型的“向站务员说早上好”完成 1/1 轮，2 次调用、33.12 秒，未推进时间或获取线索；未调用裁定与补叙述。更早的三轮到站路线只完成两轮，第三轮超时；该报告保留为失败记录，不算整段体验通过。单次问候通过不代表整场主持质量或固定响应速度。

## 原文细节问答（LightRAG）

```bash
uv run autokeeper --preset deepseek eval lore            # 四种策略都跑
uv run autokeeper --preset deepseek eval lore --only graphrag   # 只重跑一种，其余沿用上次的结果
```

题目由 importer 从原文里出：24 道细节题，三分之一要串起两三处原文才能回答，每题附原文依据。之后守秘人拿四种上下文分别作答，判卷模型对照参考答案打分。这一轮的出题、作答、判卷都用 DeepSeek flash。

| 上下文 | 准确率 | 平均上下文（token） |
|---|---|---|
| 只有 SKILL.md 总览（守秘人常驻） | 29.2% | 3,371 |
| 整本模组（总览 + 全部 reference 文件） | 95.8% | 14,084 |
| 总览 + LightRAG naive（只检索原文块） | 95.8% | 6,181 |
| 总览 + LightRAG mix（图谱 + 原文块） | 91.7% | 6,388 |

- **单看总览**：回答细节问题不够，这也是守秘人每轮都要检索的原因。
- **检索的效果**：用不到一半的上下文，就追平了整本模组的准确率。
- **mix 第一版**：只有 83.3%，上下文反而有 15,165 token。原因是 LightRAG 的实体、关系预算（默认 6k / 8k）不受 `max_total_tokens` 约束，结果把原文块全挤掉了（日志里是“35 entities, 112 relations, 0 chunks”），而细节题的答案恰恰在原文里。
- **修正**：按总预算分配，实体、关系各占四分之一，剩下的留给原文块。
- **明细**：两版都在 `dev/output/eval/`（`lore_zhuishuren_v1.json`、`lore_zhuishuren.json`）。

## 修辞诱导对照

```bash
uv run autokeeper eval rhetoric
```

同一个行动说两遍：一遍平实，一遍裹上修辞（CoC-Seduce 所说的 Rhetorical Injection）。修辞版来自两处：一是四种模板（伪逻辑、权威施压、情绪恳求、元游戏），二是攻击者 Agent 针对每个场景专门写的话术。

两种裁判拿到的结构化资料相同，区别只在于看不看得到玩家原话：

- **baseline**：单个模型读玩家原话后裁定；
- **split**：先由 intent 把原话改写成中立行动，arbiter 看不到原话。

修辞版裁定比平实版更宽松，就记一次“被说动”。宽松包括三种情况：免检却照样给线索、降低难度、多给奖励骰。

《追书人》上 20 个场景，每个场景两种话术（攻击者 Agent 写的、模板的），每格是 40 次里被说动的次数：

| 裁判模型 | baseline（看原话） | split（intent → arbiter） |
|---|---|---|
| Opus 5.5 | 4（话术 3，模板 1） | 1（话术 1） |
| Haiku 5.5 | 7（话术 7） | 0 |

第一版的 split 并不比 baseline 好：Opus 4/40，Haiku 4/40。翻明细发现，intent 把玩家对环境的断言（“他正背对着我”“泥地被露水泡软了”）当成事实写进了行动描述，arbiter 就照着给了奖励骰。后来收紧了两处，重测得到上表：

- intent：只写调查员做了什么，这类断言一律不写；
- arbiter：奖惩骰只认场景资料里有的条件。

两版明细都在 `dev/output/eval/`（`rhetoric_v1_zhuishuren.json`、`rhetoric_v2_zhuishuren.json`），里面有每条话术、两次裁定和理由。

### 换成 DeepSeek，比较思考强度

```bash
uv run autokeeper --preset deepseek eval rhetoric \
    --referee deepseek:deepseek-flash@high --referee deepseek:deepseek-flash@low
uv run autokeeper --preset deepseek eval rhetoric --referee deepseek:deepseek-flash@none
```

同样 20 个场景、40 组对照，裁定员都是 deepseek-flash，只换思考强度。延迟取自追踪里每次裁定的耗时：

| 裁定员的思考 | baseline（看原话） | split（intent → arbiter） | 裁定延迟 p50 / p95 | 每次裁定输出 token |
|---|---|---|---|---|
| high | 11 | 2 | 2.4 s / 4.7 s | 317 |
| low | 9 | 0 | 2.0 s / 4.1 s | 293 |
| 不思考 | 6 | 2 | 1.1 s / 1.6 s | 101 |

- 换了厂商，结论不变：split 让被说动的次数从 6–11 次降到 0–2 次。挡住话术靠的是“裁定员看不到原话”这个结构，跟思考强度关系不大。
- baseline 里开着思考反而被说动得更多，像是思考在替玩家的说法找理由。不过对抗话术每轮都重新生成，这个差别可能是噪声。
- 不思考的裁定快一倍、便宜近一半，但是不是一样准，上面这个评测量不出来。拿 20 个平实行动的裁定比较（要不要掷骰、技能、难度、给哪些线索全部一致才算一致）：high 和 low 一致 14/20，high 和不思考也是 14/20；同一档跑两次本身就有差异。细看分歧，不思考有两次一次社交检定成功就给了 2–3 条各自带门槛的线索，high 只给 1 条。
- 所以 DeepSeek 预设的裁定员仍用 high。在乎速度的话，配置里写 `[roles.arbiter] effort = "none"`，每回合少等一秒多。

明细在 `dev/output/eval/rhetoric-deepseek-effort.json` 和 `rhetoric-deepseek-none.json`。

### 裁定员不能看玩家原话（2026-10-20 复测）

有一版改动为了不丢掉玩家真正做了的防备（「屏住呼吸推开陵墓的门」，解析偶尔漏掉），把玩家原话也给了裁定员，近期交谈里也带着玩家自己的话。在 DeepSeek flash（high）上复测，评测现在会把话术写进日志，和游戏里一样：

| 裁定员看到的 | 40 次里被说动 | 话术 / 模板 |
|---|---|---|
| 原话（那一版） | 7 | 5 / 2 |
| 只看解析后的行动，系统提示仍写着「结合玩家原话」 | 4 | 3 / 1 |
| 只看解析后的行动，系统提示恢复成「看不到玩家的原话」 | 2 | 2 / 0 |

逐条配对（前两行），只有看原话时才被说动的 4 次，反过来 1 次。多出来的几次都是把玩家对环境的说法当了条件：「清晨无人、可从容发力」「泥地未干、斜射晨光」给了奖励骰。最后一行是现在的游戏，和 10 月 18 日测的 2/40 一致；剩下的 2 次是前巡警直接问到警局的报案，模组本来就允许。明细在 `dev/output/eval/rhetoric-split-final.json`。

防备照样要保留：解析结果多了一项 `precautions`，玩家说的「屏住呼吸」「用手帕捂住口鼻」「戴上手套」原样摘进去，裁定员按做到了处理。5 句探针里 5 句都摘对了，「泥地还软着，清晨没人」这种对环境的说法不进 `precautions`；不过那一句的 `summary` 里带上了「趁清晨无人、泥地尚软」，解析仍会漏放断言，靠裁定员的规则兜底。明细在 `dev/output/eval/rhetoric-words.json` 和 `rhetoric-split-log.json`。

## 真人存档重放

```bash
uv run autokeeper --preset deepseek eval session zhuishuren-1019-224053 --turns 3-40
uv run autokeeper --preset deepseek eval session zhuishuren-1019-224053 --recorded   # 只核对当时的记录
uv run autokeeper --preset deepseek eval rejudge dev/output/eval/session-xxx.json    # 换了核对规则后重核
uv run autokeeper --preset deepseek eval session zhuishuren-1019-224053 --blind-keeper  # 守秘人看不到底牌，作对照
```

AI 调查员不像真人，所以拿真人存档来测。回合图在每一轮结束时把整局状态存进检查点，`eval session` 从里面取出第 N-1 轮结束时的局面，用玩家第 N 轮的原话和当时掷出的点数，跑一遍现在的流程；每一轮单独从当时的局面开始，一轮的错不会带到下一轮，也不写存档。

然后由核对模型（DeepSeek flash，不思考）对照这一轮结束时的世界记录读叙述和 NPC 的话，挑出矛盾：人在不在（同一栋房子别的房间也算在近旁）、谁跟着、调查员手里的东西、结算之外凭空多出的物证、时刻对不对。每一轮读两遍，两遍都挑出同一类问题才算，当时的记录用同样的方法核对，作为对照。

核对模型本身有噪声：同样的叙述核两次，85 轮里有问题的轮数会差 4 轮左右；它对已知的问题大多能挑出来（审计里列出的同行、人在别处、凭空多出的脚印和碎布，9 轮里挑出 8 轮，漏了捡起碎布那一轮），也会误报，所以只比较同一次运行里的两边，不看绝对数。另一个局限：重放从当时的局面开始，当时已经错开的历史（叙述里有人跟着、记录里没有）会带进来，守秘人读到的近期经过也是当时的。

守秘人看得到全部底牌（模组的真相、此地藏着什么、在场的人的秘密和打算），所以每一轮还核对一次叙述有没有说漏：给核对模型一份这一轮结束时玩家还不知道的事（真相、结论、NPC 的秘密、没找到的线索，只拿世界记录，不经过守秘人的报告），读两遍，两遍都点名同一条才算说漏；另外用五字片段比一遍，照抄原文的单独计数。只看守秘人的旁白，NPC 自己的台词不算。`--blind-keeper` 让守秘人回到看不到底牌的样子，和看得到时用同一份代码对照。

2026-10-20，《追书人》一局 118 轮的真人存档：

| | 每轮模型调用 | 玩家每轮要等的模型时间 | 每轮花费（账本估算） |
|---|---|---|---|
| 重要 NPC 的决定在回合里做（之前） | 6.6 次 | 约 22 秒 | $0.0087 |
| 回合讲完再做（`world_later`） | 7.3 次 | 约 7 秒 | 约 $0.0073 |

「要等的」不算 world（NPC 自主决定）、整理旧对话和这次评测自己的核对。之前 world 每轮平均 2 次、合计 12.8 秒，占每轮模型时间一半以上、花费的四成，多数决定是「再等等」。这几个数是单轮重放的：每轮从原存档起跑，同一个 NPC 每轮都会被重新叫醒一次，幕后调用因此偏高，和真实游玩不可比（真实那局 118 轮里 NPC 的幕后思考一共 26 次）。现在的报告把 world 的调用数标成「不可比」，另给整段重放里不重复的（人物，唤醒原因）有几种。

还试过在守秘人的报告里加三句场面提示：同一栋房子别的房间里有谁、玩家提到的或故事最近在讲的熟人不在这里、每一轮都提醒不要补出新物证。在 85 轮上对照（提示开和关，其余相同）：

| | 有矛盾的轮数 | 矛盾 |
|---|---|---|
| 不加提示 | 8 / 85 | 10 处 |
| 加提示 | 14 / 85 | 20 处 |

加了反而更多。翻明细：点名说谁不在，守秘人有时反倒把他写了进来（「阿萨塔还在，隔着几道门」）；「叫一声听得见」让守秘人把书房里的托马斯直接写到门厅递手杖。另一面，不加提示时也有「家里没人」这种老问题（托马斯就在书房）。所以这三句没有留下，改成在解析那一层处理：玩家要找的人在同一栋房子的另一间屋，就走过去（`world/context.nearby`）。明细在 `dev/output/eval/ab-notes-on-rejudged.json` 和 `ab-notes-off-rejudged.json`。

### 比两组提示词：控制精准度

```bash
uv run autokeeper eval session zhuishuren-1019-224053 --turns 28,44 --parallel 1 --no-baseline --out a1.json
uv run autokeeper eval --prompts dev/prompts/kcmix.yaml session zhuishuren-1019-224053 --turns 28,44 \
    --parallel 1 --no-baseline --given a1.json --out b1.json
uv run autokeeper eval compare --a 'a*.json' --b 'b*.json'
```

`eval --prompts` 只在这一次评测里换掉文件里写的提示词（`agents/cast.py` 里的 `*_SYSTEM`，或 `skills/` 下的技能），不改任何文件；写法见 `eval/variants.py`，用过的变体放在 `dev/prompts/`。替换的原句必须正好出现一次，占位符不能变，否则不跑。`--given` 让这一遍沿用另一份报告里同一轮的行动和裁定（模组内的才沿用，导演即兴的那轮照常重新裁定），比守秘人或 NPC 的提示词时，两边面对同样的裁定，差别只来自被比的那部分。`--no-baseline` 不再核对当时的记录，省一半核对调用。`--parallel 1` 时重放和核对都一次一个调用。

报告里每一轮多了不经裁判、按规则数出来的几项（`eval/control.py`）：守秘人的场面快照第一次就通过、退回、第二次仍不通过，以及退回的原因；NPC 因为回应做不到被重问几次、最后落进「未落实」几次；NPC 嘴上说一起去、递东西、走开，却没填 accompany、items、leave，或者守秘人的场面写某人跟着、走了、拿出东西，那人自己的回应却没有这个字段；见面安排给了几次、填了 played 几次；裁定员修 JSON 几次、给了几个用不上的线索 id；检定失败那一轮讲出了该得的线索，或者讲出了还没人找到、要检定才有的线索原文（五字片段）；玩家要悄悄做的事叙述写成喊出来；结算里没有伤害，叙述却写调查员受了伤；同一栋房子里明明有人，叙述写没人应；在别处的人在叙述里开口、走动。核对模型另外多看两类：「代做」（替调查员做了玩家没说的事）和「升级」（结算里没有的伤害、袭击、追赶，或者把危险写得比记录更近更重）。

`eval compare` 把两组报告按轮配对：每项指标给各遍合计的均值 ± 标准差，再把每一轮两边各遍的平均数相比，B 更少的轮和更多的轮做符号检验；另附两边叙述的套话和句长作为文风护栏。

## 守秘人用哪个 Claude 模型

`eval style` 固定《追书人》9 段的行动、裁定、NPC 台词和骰子，只有守秘人真调用；每个模型跑 1 遍，样本很小。价格是 Claude Code 报出的等价 API 价，缓存命中后的每次调用。Opus、Sonnet、Haiku 在 2026-10-18 的工作树上测，Fable 只有早一版代码上的一遍。

| | Opus 5.5 | Sonnet 5.5 | Fable 5.1 | Haiku 5.5 |
|---|---|---|---|---|
| 套话（前五项，每千字） | 0.81 | 0.54 | 0.45 | 0.00 |
| 超出人类的部分（每千字，[新量法](#文风比照人类小说)重算） | 2.28 | 0.95 | 1.80 | 1.20 |
| 平均字数 · 超过 200 字的段 | 274 · 8/8 | 205 · 4/8 | 245 · — | 183 · 1/8 |
| 中位延迟 | 10.5 s | 5.2 s | 11.0 s | 7.8 s |
| 每次花费 | $0.027 | $0.011 | $0.060 | $0.001 |
| 问题 | — | — | 17 处半角逗号，错字 | 段末漏出“〔输入〕”，不点出孤注一掷 |

claude 预设的守秘人因此改用 Sonnet 5.5。裁定员四个模型在 6 个 `.ra` 请求上都是 6/6，但 Sonnet 有一遍在空书房“说服”时给了一条线索，裁定员先留在 Opus。导演 Opus 和 Sonnet 的方案都一次通过校验（4/4），导演在后台，留 Opus。

## 文风：比照人类小说

```bash
uv run autokeeper eval style --runs 5 --label before          # 守秘人：上面那 9 段，只有守秘人是真的
uv run autokeeper eval style --npc --runs 5 --label before    # NPC：同样 12 句问话，问《追书人》的托马斯、守墓人和奥黛尔
uv run autokeeper eval cliche dev/output/eval/style-before-*.json  # 存档、autoplay 记录、full 追踪也能量
uv run autokeeper eval blind --a before --b after             # 两组逐段盲评；加 --npc 比 NPC
```

以前的“前五项套话”把仿佛、似乎算作套话，可鲁迅和老舍用得比守秘人还多。现在每种说法先在人类小说里数一遍：鲁迅《呐喊》《彷徨》里的 22 篇（91,525 字）和老舍《骆驼祥子》前八章（39,040 字），维基文库原文转简体，用同样的正则。叙事里的用量写成人类的几倍，两人都没用过的（一丝、静得能听见、喉结）按 13 万字里出现一次算。标题数字是“超出人类的部分”：每种说法超过人类用量的那一截加起来，每千字几处。比喻（像）单列，不算进去。

另外量这几样：

- 句长变化：句长的标准差除以均值。鲁迅 0.81，老舍 0.69。
- 照搬示范：keeper-craft 两段示范里的物件（jieba 词典里少见的名词），模组和守秘人拿到的报告里都没有，却出现在叙事里。《有些人油盐不进》那局（Claude，80 回合）里，樟脑出现在 6 段，油布在 5 段。
- 沿用上一段：这样的物件连着两段出现。
- NPC：以（动作）开头的句子；两句之内又用了模组写给这个人物的习惯动作或口头禅（托马斯的搓手、“说实在的”）。

一遍只有两千字上下，一种说法多用一次，每千字就差半个点，所以每组跑 5 遍以上，报均值 ± 标准差。盲评时同一段（NPC 是同一个人的四问四答）两组各出一份，裁判是 Opus 5.5，不知道哪份是哪组；先后各评一次，换了先后结论就变的算相当，胜负做符号检验，相当不计。

### 加一句话管不管用

以下为旧版提示词与模型的历史实验。当前已撤除仅针对 Claude 的措辞重问：重复动作或口头禅可能是人物连续反应，不再因此额外调用模型。下表保留当时的测量结果，不代表现行策略或新模型效果。

研究给的办法是往提示词里加一两句正面的话，或者由代码检查后重问。每样都和改前同样跑 5 遍，盲评过了才留：

| 改动 | 后端 | 它要改的那一项 | 盲评（改后胜 : 改前胜 : 相当） | 结果 |
|---|---|---|---|---|
| keeper-craft 加一条“直接写是什么，不先否定再更正。” | Claude | 不是……而是 0.10 → 0.10 | 21 : 17 : 7，p = 0.63 | 不加 |
| | DeepSeek | 0.14 → 0 | 15 : 21 : 9，p = 0.41 | 不加 |
| keeper-craft 加一条“长句短句错开。” | Claude | 句长变化 0.39 → 0.45 | 18 : 18 : 9，p = 1.00 | 不加 |
| | DeepSeek | 0.45 → 0.46 | 没评，没动 | 不加 |
| 每轮附言点出上一段的两三样物件：“上一段写过……，这一段换别的写。” | Claude | 点了名的物件下一段又写到 16/120 → 2/120；沿用上一段 8.6 → 4.2 | 21 : 15 : 9，p = 0.41 | 不加 |
| | DeepSeek | 8/112 → 7/119；3.8 → 6.0 | 没评，没起作用 | 不加 |
| NPC 再次开口时附一句“你们刚说过话，这回直接开口。” | Claude（3 遍） | 第二句起以动作开头 100% → 100% | 没评，没动 | 不加 |
| | DeepSeek | 89% → 89% | 没评，没动 | 不加 |
| NPC 第二句起又以动作开头、或两句内又用了同一个习惯，就重问一次（和泄密重问同一个办法） | Claude | 第二句起以动作开头 100% → 7%，两句内重复口癖 100% → 33% | 13 : 0 : 2，p < 0.001 | 加，只对 Claude |
| | DeepSeek（10 遍） | 89% → 4%，47% → 10% | 16 : 11 : 3，p = 0.44 | 不加 |

- 原有的提示词一句没动。三句附加的话，指标动了的也没在盲评里赢：Claude 加了“长句短句错开”，句子长短变化大了，裁判却 18 : 18。
- 附言点名上一段的物件：Claude 照做了，点了名的东西下一段几乎不再出现，裁判却没觉得更好；DeepSeek 不理这句。
- 重问只开给 Claude 扮演的 NPC。代价是调用：这组问话里第二句起几乎句句都重问，NPC 调用从 12 次变成 21 次，每句从 5.8 s 变成 9.3 s。DeepSeek 上重问也几乎消灭了动作开头和口癖，裁判只是略偏向它（先附言再重问的那组 5 遍是 9 : 1 : 5，p = 0.02；只重问 10 遍是上表的 16 : 11），不算清楚地更好，DeepSeek 照旧。
- DeepSeek 的 NPC 偶尔交回空台词：360 句里 4 句，三句是托马斯的第一句，两组都有，和重问无关，还没修。

明细在 `dev/output/eval/`：`style-*.json`、`talk-*.json`、`blind-*.json`。

## 导演展开冷却的历史实验

当前已撤除对明确玩家行动的三轮冷却，必要即兴等待完整方案就绪；下面保留旧版实验供比较，不代表当前运行行为或延迟。

裁定员把“模组没写到、但合情合理”的行动判成“可即兴”，引擎就请导演展开。《有些人油盐不进》那局（Claude，两名调查员，80 回合）导演被叫了 32 次：开局改编 1 次，推进 1 次，展开 30 次。80 个行动里 30 个被判成可即兴，很多是小事：问一句不在场的人、翻一道普通的栅栏、看清长椅尽头的影子；会堂里五回合展开了四次。

当时同一地点三轮之内只展开一次（一轮是每位能行动的调查员各一回合）。要去别处（模组里有的地方，或者没写到的地方）、卡关推进、出格的后果和开局改编都不受限制。按那局录下的裁定重放：展开从 30 次降到 14 次，导演调用从 32 次降到 16 次，按那局每次 13.6 秒、等价 $0.107 算，省下约 3.6 分钟和 $1.7。一人局《追书人》49 回合（fullrun-pacing）是 10 → 8，12 回合的经济模式是 3 → 2。这是重放录下来的裁定，不是重新跑一局；被挡掉的展开之后，真实的局面会走得不一样。
