# 守秘人体验设计

## 参考资料

- [Chaosium 访谈：Janyce Hill，《疯狂山脉》作者](https://www.chaosium.com/blogwomen-in-tabletop-gaming-month-24-chaosium-interviews-janyce-hill/)：访谈第 7 问解释，开头建立普通生活，能让后来的恐怖形成更强的反差；NPC 也可以拥有独立目标，不只负责引出剧情。
- [Modern Mythos 第 20 期：Jon Hook 与 Seth Skorkowsky 谈节奏](https://modernmythos.libsyn.com/modern-mythos-ep20-patron-games-pacing)：公开节目笔记提醒，调查不必拖沓，交谈可以提炼或略述，不必逐分钟复演。本项目据此按玩家是否主动停留，决定展开还是概述。
- [Chaosium 官方规则：The Game System](https://cthulhuwiki.chaosium.com/rules/game-system.html)：在有戏剧性风险的情境才需要技能检定，普通走路与被追逐时赶路的裁定应当不同。
- [Chaosium 访谈：Mike Mason 谈 Keeper 风格](https://www.chaosium.com/blogchaosium-interviews-finding-your-keeper-style-with-mike-mason/)：可继续观看的访谈入口。该网页没有完整文字稿，未用作上述具体设计的论据。

## 在 AutoKeeper 中的取舍

以下是结合参考资料和玩家反馈做出的项目设计。

本轮新确认的架构以全知 KP、记录库和模组日程为核心，尚未完成代码迁移。KP 负责理解和现场安排，NPC 主动性也由 KP 表现；已写明结果的日程由代码执行，导演在时间跳过、换场景或关键条件成立时集中安排幕后动向。保留裁定员与受知识隔离的 NPC 配音，撤除逐人物回合推演、待演与待审队列及运行时叙述语义复核。下文涉及旧流程的内容属于现状；目标与证据以[开发记录](development-notes-2026-10-20.md#当前架构决策kp记录库与模组日程)为准。

在场的人物每轮由 KP 根据动机和未完成事项决定是否主动协助、反应或推进，需要说话时由 NPC 配音同时提交台词和动作。验收包括“没人请求时是否主动承担合理事项”和“局势改变后是否及时调整行动”，使用定向小测试、3–5 轮连续重放与用户实际游玩。运行时只检查快照与操作，异常修正一次，仍未落实的事项留给下一轮；不删句子，也不把服务或执行失败演成人物犹豫。意图理解合并到最后实施，先通过话术诱导评测。

1. **开场。** 给出有来由的旅途、眼前的生活和一个可接话的时刻。调查员的背景可以成为联系，不能替玩家编造经历或完成拜访。
2. **日常。** 问路、吃饭、投宿、闲聊不必附带线索、怪异或阻力。已有人物由对应 NPC 回应，新补的人和地方进入本局状态，读档后仍然存在。
3. **节奏。** 玩家主动点菜、接话就展开；说直接赴约就概述沿途，不强制逐店停留。生活里的微小意外可以有趣，但不必总是危险。
4. **时间。** `daily` 行动重置卡关计数，不触发导演的主线催促，也不额外检索案情。耗时照常计算，已经设定的时限、事件和危险仍然生效。
5. **状态。** KP 可以安排新线索、痕迹、日常物件及人物行动，并提交配套世界操作；程序确定性校验通过后再呈现，规则结果仍由引擎结算。当前仅接收公开报告的叙述角色尚不具备这些能力，需要重构，不能只增加提示词就宣称完成。

## 恐怖与戏剧

世界的运行服务于故事。NPC 可以残酷、自私、偏执、狂热、背叛或失控，也可以暂时合作、犹豫或试图挽回；他们不承担安抚玩家的职责。人物的动机、所知、资源和当下处境决定其行动，委托人的协助意愿也不等于无条件服从。导演可以组织围猎、离间、勒索、毁证和陷阱，把压力落实为有人执行、能够改变局面的计划。公开的温和态度可以掩盖恶意，维护者核对权限、依据与实际执行，不负责把人物纠正成善良或诚实。

危险可以造成损失，既有敌对计划也会在调查员休息时继续发展。日常与缓和保留反差，不因暂未查案额外加害；成功则应实际改变局势，不能为了预定高潮取消玩家的有效行动。叙述充分呈现已发生的残酷与后果，但不能代替玩家决定恐惧、信任或屈服。伤害、理智和冲突结果遵循裁定，角色声称做了某事、正在尝试与实际完成分别记录。

## 模型与运行约束

架构调整面向更强的模型能力：人物动机、潜台词、情绪转变、行动意图和叙事安排由模型结合完整情境判断。系统负责提供资料、检索原文、隔离知情范围、结算工具操作和保留证据，不逐项编写人物反应表，也不以固定恐惧阈值、恶意频率或每轮冲突指标代替表演。模型是否胜任某项判断需要用本项目的回放与测试评估，不因年份或上下文窗口较大就假定不会遗忘、误读或越权。

紧密相连的判断应保持上下文连续，短任务不为增加角色数量而反复转交。人物身份、记忆、目标与未完成安排持续保存；NPC 的行动由 KP 现场决定，或由导演在合适时机集中安排，不再以每个人物独立唤醒决策作为目标。明确结果的步骤由日程执行。并行留给独立准备与资源任务，过期结果检查和执行恢复继续保留；现有逐人物调度及公开叙述链路仍在，尚未完成这项重构。

## 对话、人物行动与信息显示

以 `/kp` 开头的输入是对 KP 的说明：不进入行动解析与人物对话，不推进时间，也不占用联机行动名额。其余输入由守秘人安排判断是角色行动还是场外提问。

行动解析每轮读取最近经过、已知地点和持有物，依据上文解释省略表达。明确目的地与沿途出口分开处理；只有玩家要求沿路停留时才中途停靠。裁定前不再生成额外动作旁白，愿望、尝试和已结算结果保持区别。

裁定看结构化行动、近期实际经过和本地资料，不看玩家原话：话术和修辞留在解析这一层，玩家真做了的防备由解析摘进 `precautions`（对照见[评测](eval.md)：看原话时 40 次话术被说动 7 次，不看 2 次）。NPC 不因重复动作或口头禅自动重答；措辞质量由离线评测观察，信息权限与实际动作仍单独校验。

邀请同行先由 NPC 回应，同意后写入世界记录；位置随实际行进更新，到约定目的地结束。出发前明确交代的谈话按顺序完成，私下内容只记入参与者的世界记忆。拒绝或前置交谈无法完成时不擅自让玩家独行。准备阶段按每次交谈记录恢复点，重试不重复已完成的交谈。

心理学观察不会自动向 NPC 发起对话或使他交底。引擎拦截用心理学绕过其他社交门槛的线索发放，同时保留模组明确设置的心理学线索。普通交谈延续此前授权，不因“本轮没有新线索”撤回已公开内容。

NPC 回应后，如果没有新事件、环境变化、理智变化或其他待交代的结果，本轮直接结束。检定与线索使用已经展示的卡片，不再追加一段旁白概述交谈。同时发生其他事件时，叙述只补充那些变化，不复述台词。

重要 NPC 根据亲历事件、约定、目标与处境决定是否行动；委托人有协助调查的理由，其他人物仍保留自己的利益和顾虑。人物可主动提出帮助、求助或陪同，也可因可信消息改变心境。系统提供近期互动、消息来源、关系和未履行承诺，不规定每隔几轮插话，也不强制角色慌乱或镇定。对话摘要不是唯一记忆：每次保留近期连续片段，再从该角色可知的事实与亲历记录中检索当前问题、目标或承诺相关的旧事；听说与个人判断保留来源和不确定性，不补造缺失记忆。

新的当面消息可以在零分钟交谈后引出真实行动，无需等调查员离开或再做一件事。普通问候不额外启动自主决策，回应与世界推进共用本轮剩余额度。完整对话原文按参与权限保留，避免长台词末尾的承诺因摘要截断而丢失。

同一时间截面、不同地点的 NPC 可以并行构思，各自只读取自己的资料；执行前按顺序检查依据是否改变。模型延迟不推进游戏时间，过期决定留待重想。计划必须以真实行动完成：移动与交物使用状态操作，`achieved` 指明可验证的结果；整组操作有一项无法执行，就不落地，也不追加已经完成的叙述。角色回复中的物品交付、承诺和同行同样先校验，再展示；失败时修正一次，仍不成立就保留现场供重试。公开行动继续遵守线索权限，不能替玩家决定或泄露秘密。

异地事件即使标为 `public`，也只代表当地可见，不直接进入调查员的旁白或知识。NPC 离开眼前时只交代离开，不透露玩家未能观察到的目的地；到达时同样不自动交代来处。不得用“玩家知道、角色不知道”解释一次越界泄露。

右栏为“经过／进展／背景”保留至少八行高度。窗口较矮时压缩人物卡、骰子与线索预览；人物卡可滚动，完整资料仍可通过 F4 和 F2 查看。窄窗口继续通过 Ctrl+G 打开独立阅读窗口。

NPC 可以为了自保、利益、保护他人或维持体面而说谎，不限于反派。台词中的声称、真实意图与实际行动分别记录；假答应不会自动建立真实同行，也不能把谎报的地点写成角色位置。私有欺骗记录须包含本次原话、具体动机和真实打算，不能事后把一次执行失败解释成角色故意欺骗。听者无法通过后台分类或事实编号识破谎言。

调查员和 NPC 的重要装备都在后台维护，只登记武器、钥匙、证物、关键工具和重要消耗品。携带、穿戴、手持、藏匿、余量与损坏随存档保留，不增加常驻装备面板或普通生活用品账本。取用或消耗依真实持有记录结算；搜身、发现或主动出示有实际依据后才公开相应物品。NPC 不会因站在同一房间就向玩家展示全部装备。

## 即兴世界与后台任务

导演新增的人、地点和物件都是有稳定 ID 的结构化实体，先检查引用和数量，再进入本局世界；本局不再以累计 16 次即兴为由停止展开，单次规模、并发数与 API 预算仍受控。

每个即兴实体拥有独立配图，后台先寻找有授权资料的参考图片，未找到时尝试生成正式图片，再统一转为当前画风的彩色字符画。图片尚未完成时保留名称与文字，不显示通用房屋、人形或盒子占位；同一场景重绘时保留旧图。只有两条图片途径都未取得结果时，才按场景、人物或物件各自的构图要求绘制字符插图。不会拿邻近地点的图冒充新场景，也不会把 NPC 的秘密交给配图提示。参考照片不代表虚构人物或物件的真实照片。

图片和原图署名保存在 `data/games/art/`，字符画、配色、图片路径和处理状态写入存档。绘图、读图与图片查询的用量记入本局账本。当前即兴将出现的新场景、人物或物件，先准备首图再发布内容；未就绪时显示“KP 正在构思…”，失败保留当前行动供重试。同一场景重绘继续保留旧图。缓存同时核对描述，避免重做方案后沿用同 ID 的旧内容图片。离开游戏会取消后台工作；立绘和物件卡可以原地刷新，局域网玩家也能收到字符图。

配图使用固定的公开外观与统一画风提示。叙事回合会暂停启动新的图片请求；已发出的请求可以完成。每个存档默认最多 24 次绘制尝试，另有估算 1 美元的视觉预算（`visual_limit` / `visual_budget_usd`），未标价后端仍受次数限制；进行中的请求可能超出估算额度。失败最多自动尝试两次，参考照片搜索中断后无需重画字符图。联机照片缩小后传到玩家本机缓存，不依赖房主的文件路径。

参考照片取决于搜索结果，离线时使用字符图。

## AI 画图

本机装了 Codex CLI、已经登录、带 image_generation 功能时，图片还可以由 Codex 内置的 image_gen 来画（`imagegen.py`）。不管游戏用哪个预设（Claude、DeepSeek、Codex、Ollama），走的都是这一条路；没有 Codex 就不开，其余照旧。设置里的「AI 画图」可以关掉；用不了时开关是灰的，下面只写一句原因（比如「没装 Codex，AI 画图用不了」），怎么装、怎么登录写在玩法说明的「遇到问题」页，`autokeeper doctor` 也会报告。

- 剧情让地点或人物明显变样时（失火、被淹、被洗劫、受伤、变异、死去），导演在方案的 `looks` 里写下变化；模组也可以在地点和 NPC 上写 `looks`，标记成立时换图。Codex 拿到现在显示的那张图和变化描述，保留构图重画；画好之前旧图不动。
- 即兴的人物、地点、物件和导入时的场景、头像，搜不到合适的照片时，由 Codex 照公开描述画一张，代替手绘字符画。
- 模组自己没有图的地点、人物（路人除外：没有目标、不知道也不藏任何事、不给线索的人）、重要物件和怪物（`pictures.py`）：先找照片（读图模型写搜索词、从候选里挑一张裁好，什么授权都可以，因为只留在本机），处理成和模组原图一样的色调；找不到合适的才由 Codex 照看得见的描述画。怪物不找照片，直接画：正面、上半身占满画面、从下方打光、纯黑背景，画面里没有别的东西，战斗时从黑底里抠出来放上舞台，追逐时合成进地点（`imagery.staged`）。每个模组只找、只画一次，存在 `data/cache/art/<模组>/`，以后每局都用（`pictures.adopt`）；模组文件夹不变，自带模组的图不进仓库。`autokeeper art prepare <模组>` 在开局前全部准备好；没准备的，游戏开始后在后台一张一张补（`Visuals.gaps`），补到哪张，场景和卡片就换哪张。离线又没有 Codex，或者额度用完时，才用程序画的图（`scenery.py`）。
- 每个模组最多 100 张（导入和所有存档一起算，记在 `data/imagegen/<模组>.json`），每局最多 12 张，一次导入最多 40 张补图、6 张变样图。没画成的不算数。
- 本局画的图存在 `data/games/art/` 下这一局的文件夹里，存档记住每个地点、人物现在显示哪张，读档照旧；模组本身不改。导入时画的图进 `modules/local/<id>/art/`，仓库自带的模组只用有授权的照片。每张图在同一文件夹的 `credits.yaml` 里写明“AI 生成（Codex image_gen）”和它照着画的原图来源。联机时和其他图片一样通过 art 事件发给玩家，变化描述留在房主这边。
- 每次调用给 Codex 的是自己的短指令，关掉技能清单、插件和命令行，让它直接调用画图工具：实测一张约 40 秒，输入 7.6k–32.5k token、输出约 250–450 token；以前先读 imagegen 技能要 12.8 万 token。用完删掉这次的 Codex 会话和它的临时图片。

## 大场景

模组在重要节点写 5–15 个大场景（`showcases`，格式见[模组格式](module-format.md)）：开场、突发、危机、关键地点、怪物、最终 boss、结局。到了那一刻整屏只放一张大图，标题压在底部一条细带上，叙述照常在后面流出来；任意键、点击或约 8 秒收起，掷骰提示一出现就让路；关掉动画时不淡入，设置里「大场景」可以单独关。图在后台一张一张提前准备（开场优先），到点没准备好就跳过，从不等图。导入和生成模组时，导入 Agent 会在重要节点写好大场景，导完就把图准备好；自带的三本模组的大场景是手写的，图在本机第一次用到时生成，放在 `data/cache/showcases/`。联机时房主到点才把这一张图发给所有人，标题、画面描述和图都不会提前离开房主的电脑。

## 验证方法

自动测试验证开场只输出一次、玩家实际从车站行动、沿途公开信息进入叙述、日常不触发卡关催促而定时事件照常发生，以及 NPC 闲聊走独立对话通道。它们不能证明某个模型的文笔或临场主持质量。

模型试玩时分别尝试“向站务员问路”“先吃早饭，问他今天忙不忙”“直接去托马斯家”“在镇中心停下来”，检查回应是否尊重停留或赶路、是否乱塞秘密，以及见到托马斯时是否从敲门和寒暄接起。

## 世界记录与回合恢复

生活事实、关系和约定独立于对话摘要保存；未履行的约定每次进入相关 NPC 的上下文。NPC 只能登记自己本轮实际说出的承诺，裁定只提交成功后的变化。已存在的物件和背包用品可以借出、归还、转交，不能凭空获得或隔空拿走。线索本能查看这些记录；完整货币、NPC 日程与分队位置系统仍未实现。

行动、裁定、结算、NPC 对话与叙述按阶段留恢复记录。移动、耗时、检定、孤注一掷、幸运、理智、伤害、线索、手稿及事件的已提交结果分别保留；多骰操作中已返回的骰值也会留存。取消或读档后补齐未完成阶段，人工掷骰确认和选择无需再答。MCP 工具同样保留原参数与裁定。解析失败不消耗回合；存档以临时文件替换，降低写到一半损坏的风险。

断线后通知可能再次送达，不能因此再次结算事实；尚未返回结果的外部请求可以重试。该机制不保证断电发生在任意未保存指令中间都能精确恢复，也不能保证提供方只对重试请求收费一次。旧版未保存的执行结果无法据此自动还原。

叙述模型不再常驻模组真相，也不读取隐藏地点资料或未筛选的原文检索；它读取当前公开外观、已解锁线索和引擎结果。裁定员与导演保留幕后资料。联机发送的是玩家视图，未探索地点只保留已知名称，不发描述、搜查清单、秘密人物或隐藏插图。
