# 持久世界

`src/autokeeper/world/` 让一局游戏有一份自己的世界记录：谁在哪、谁知道什么、谁欠谁、答应过什么、背后有什么计划，以及这些是怎么变成现在这样的。玩家看到的仍然只是守秘人讲故事、NPC 自己行动；记录、调度和改写都在幕后。

第一阶段是新模块和测试；第二阶段把它接进了游玩（见文末「接进游玩」）：每局开局建一份记录，裁定、NPC 对话和导演的改动都走世界操作，时间推进时重要 NPC 在幕后照自己的打算行动，导演可以改写设定（玩家见过、听过的也可以，只要自圆其说）。

## 三层

| 层 | 在哪 | 谁能改 |
|---|---|---|
| 模组底本 | 模组目录里的 YAML，只读 | 谁也不改 |
| 本局事实 | `GameState.record`：即兴内容、变化、改写，每条带版本号 | 只能通过世界操作 |
| 知情 | 每条事实的 `known_by`：NPC id，或 `players`（已经到了玩家面前） | 操作和事件顺带更新 |

开局时模组被“播种”进记录（`knowledge.seed`）：地点、NPC、物件成为实体，真相、结论、NPC 的目标 / 知道的事 / 秘密 / 谎言、线索、地点的守秘人须知、事件说明成为事实。模组事实的 id 就是它在模组里的位置（`truth`、`npc:warden:secrets:0`、`clue:c_diary`），所以改写后可以写回本局的模组副本（`knowledge.project`），现有的 NPC 提示词、泄密检查、裁定员读到的就是新版本，不会新旧混用。导演即兴加进模组的东西，下次播种时带 `origin="improv"` 进来。

## 存在哪

记录放在 `GameState` 里，不另开 SQLite。理由：

- 存档是一个 JSON（`tui/app.write_save` 先写临时文件再替换），记录跟着同一次写入落盘，天然同一个事务。
- LangGraph 每个检查点都快照 `GameState`；回合重试（`pending_turn`）回到的状态里，记录和其他字段是同一时刻的。
- 存档管理（`tui/screens/saves.py`）复制就是复制 JSON，删除就是移进回收站：记录跟着走，不需要额外的文件同步。
- 以前的存档不再兼容（用户确认可以作废），所以不做旧存档迁移；`GameState.world` 只为现在的游戏代码保留，第二阶段改完读写后可以删掉。
- 联机时 `record` 在 `net/hub.py` 的 `PRIVATE` 里，不会发到玩家屏幕。

代价是存档变大。事件流最多留 6000 条、操作日志 4000 条、每个重要 NPC 40 条记忆，几千条事件也就一两 MB。真的嫌大，第二阶段再把旧事件归档。

## 记录（`record.py`）

| 表 | 内容 |
|---|---|
| `entities` | NPC、地点、物件、调查员：在哪（`at`）、状况、状态 |
| `facts` | 事实：文本、关于谁、谁知道、是否已到玩家面前（`revealed`，记的是回合）、公开来源与原文（`reveal_source` / `reveal_excerpt`）、待核验的旧标记（`legacy_revealed`）、能解释哪些线索（`explains`）、是否撤销 |
| `relations` | 有向关系 `a|b|种类`：数值 -100..100、缘由、谁知道 |
| `promises` | 约定：谁答应谁、期限、状态（有效 / 履行 / 违背） |
| `threads` | 线头：疑问、伏笔、约定、冲突、进行中的计划；热度、最后推进的时间和回合 |
| `agents` | 重要 NPC：目标、资源、计划步骤、计划依据的版本（`reads`）、记忆、下次想事情的时间 |
| `events` | 按游戏时间排的事件流。一个事件有多个参与者，就是一条超边，不需要超图库 |
| `scheduled` | 到点才发生的事和到时结算的操作 |
| `revisions` | 改写记录：旧文本、新文本、版本、理由、顺带改了什么 |
| `journal` | 操作日志：id、摘要、内容摘要、撤销补丁 |
| `requests` / `ticks` | 导演请求、已模拟过的时间段 |

实体、事实、关系、约定、线头、重要 NPC 都有 `version`，每次内容变化加一。

## 世界操作（`ops.py`、`store.py`）

所有变化都走 `World.apply(op)`：

1. **重复**：同一个 op id 已经结算过，直接返回原结果，什么都不再改；同 id 不同内容的会被拒绝。id 留空时按内容和回合生成。重试的回合拿着同样的 id 再来，不会结算两次。
2. **校验**：`op.check` 返回问题列表，写成导演能照着改的中文。
3. **结算**：改记录，也改游戏现在还在读的字段（`flags`、`item_owners`、背包、`GameState.world`），并记一条事件。中途出错就整体恢复，要么全落地要么不落地。
4. **日志**：记下摘要和一份反向 JSON Patch（`jsonpatch` 库），最近 64 条可以撤销。
5. **投影**：把记录写回本局的模组副本。

| 操作 | 作用 |
|---|---|
| `move` | NPC 换地方，可以在原地留下痕迹（`trace`），之后到那里的人看得出来 |
| `relate` | 改一方对另一方的看法：设值或增减，附缘由 |
| `transfer` | 物件易手，和 `engine/world.apply` 的记账一致 |
| `condition` | 调查员或 NPC 加减状态；NPC 的总体状况（受伤、失踪、死亡） |
| `flag` | 设置或清除已声明的剧情标记 |
| `fact` | 记一条新事实（即兴内容、发生过的事），指定谁知道 |
| `learn` | 有人得知一条事实；`players` 表示告诉调查员们。NPC 只能说自己知道的 |
| `remember` | 重要 NPC 记住一件事 |
| `occur` | 发生了一件事：幕后的戏、后果、传言，带参与者、地点和它让人知道的事实 |
| `promise` / `fulfil` / `break` | 立约、履约、违约，自动开一条约定线头 |
| `thread_open` / `thread_advance` / `thread_close` | 线头的开、推进、收 |
| `schedule` | 安排一件到点才发生的事，带到时结算的操作和依据的版本 |
| `enlist` | 让一个 NPC 成为重要 NPC（每局最多 6 个） |
| `plan` / `step` | 设定计划；把一步标成做成、受阻、放弃 |
| `rewrite` | 改写事实或事件背后的真相；玩家见过、听过的要写清理由，旧版本留给玩家 |
| `improvise` | 导演的即兴方案：`improv.check` 校验，`improv.apply` 写进模组，再播种进记录。它改模组本身，所以不能撤销 |

撤销（`World.undo`、`undo_to`）只按倒序撤最近的操作，并且拒绝三种情况：玩家在之前的回合已经看到的，不能撤销的（即兴），以及之后状态又被世界接口以外的代码改过的（反向补丁对不上）。被撤的操作留在日志里，标为已撤销，可以追溯。

## 知情和可见

- 事件的可见性默认 `auto`：调查员在场就是公开，否则是幕后。`private` 是暗中进行，只有参与者和点名的人知道。
- 在场的 NPC 是目击者；重要 NPC 把看到的事记进记忆；事件带的事实，目击者都知道了。公开事件带的事实，玩家也知道了。
- `knowledge.sync` 用可追溯的公开证据确认 `revealed`：已经发放的线索、公开事件明确带出的事实，以及某条完整事实在一份公开记录中的原文。只忽略排版和标点差异，不靠人名、地址或短句重合推断整段真相。省略主语或同义转述需要显式 `learn` 确认；未确认的语义关系不能靠字符串相似度替代。每次保留公开来源与原文，日志折叠后仍有效；已揭示事实本身不再充当另一条事实的证据。
- 旧版曾用两个 5 字片段判断公开，可能把一个地址扩展成整段真相。载入后同步时，能够找到来源的标记补全证据；无法核验的转入 `legacy_revealed`，保留原回合和原因，暂停向玩家公开全文，也暂不允许导演改写。日志可能已经裁剪，因此待核验不等于证明玩家从未见过。此步骤只更新当前加载的状态，不直接改写原存档文件。
- 私下谈话的事实可以由参与者得知，其他在场 NPC 不自动成为旁听者。传闻保留未经证实的身份；接收别人谎言的 NPC 不会因此获知系统判定的真伪。
- 谁能看到什么：`director` 全部；`players` 只有已揭示的事实和公开事件；NPC 只有 `known_by` 里有它的事实，以及它参与或目击的事件。

## 改写（`rewrite.py`）

导演可以改写世界记录里的事实和事件，让跑团更顺、冲突更有戏。玩家还没接触到的（秘密、动机、真相、没找到的线索、没人知道的往事、幕后事件）直接改；玩家已经见过、听过的，为了阴谋或剧情也能改出另一个真相（有人撒谎、记错、伪造、设局、假扮），但要自圆其说。条件：

1. 玩家见过、听过的事实（已揭示，或文字在玩家面前出现过），改写要在 `reason` 里写清他们当初为什么会看到、听到那样。旧文字留给玩家，存成一条 `told:` 事实（`knowledge.keep_told`：不属实的说法，带着原来的来源）；被改的事实回到「玩家不知道」，装着新的真相。`knowledge.how_known` 说明玩家是怎么知道的：听谁说的、叙述里说过，还是亲眼见到；
2. 玩家手里线索的原文和 `told:` 事实不能改；公开事件保留原文，改写记成它背后的一条秘密（`behind:` 事实，知情的是事件里的 NPC 和 `memories` 里写到的人），公开事件不能取消；带出过已揭示事实的幕后事件也不能取消；
3. 已经找到的线索，旧版本能解释的，新版本（`explains`）或别的事实还得能解释；
4. 不能借改写让玩家知道什么（那要用 `learn`）；
5. `World.checker` 钩子拿到同一批人和地点的已揭示事实，可以再提问题。导演的改写在落地前另有一次模型检查（`Game._consistent`）：每条已知的事标着玩家是怎么知道的，说不通就退回；改的是玩家见过、听过的事而这次没能核对，也退回。

改写只改真相，不移动人物，不改谁跟着谁、东西在谁手里：那些各有自己的操作，所以位置、同行和持有不会因为改写乱掉。

改写落地时一起更新：重要 NPC 关于它的记忆（给了新说法就换，否则标成过期、不再进它的上下文），给出的新目标，引用旧文字的幕后事件，含这条事实的线头。依据旧版本的计划、安排和导演请求，靠版本号自动变成过期。`revisions` 记下新旧两版，撤销也能恢复。

## 重要 NPC 和调度（`agents.py`、`scheduler.py`）

同行也属于世界状态：`follow` 操作将调查员 id 和目的地写入 NPC 实体的 `following`、`follow_to`。只有 NPC 自己或系统能确认该角色同行，且开始时必须同处一地。角色对话中的确认通过结构化结果提交，未确认的邀请不自动带人走；出发后按实际路线更新位置，到达目的地或玩家明确独行时结束。自主决策若要改变主意，须先结束同行，再另行移动，旧计划不能直接把同行者移走。状态与其他世界操作一样支持存档、重试和撤销。

重要 NPC 每局 3–6 个，由模组标出（NPC 的 `important: true`，`agents.marked` 生成对应的 `enlist`）或导演用 `enlist` 指定。每个有目标、资源、计划步骤（期限、条件、可以预先写好的操作）、记忆和关系。

`scheduler.advance(world, brain, start, end)` 在时间推进时运行（赶路、休息、离开某处）：

1. 按块模拟，默认每块 240 分钟，最多 12 块，更长的跳跃块就更长；
2. 每块里：到点的安排先落地（依据变了就作废，并叫醒安排的人）；到期的约定叫醒当事的重要 NPC；
3. 每个重要 NPC：到期且条件满足的步骤，计划没过期又有预写操作的，整组校验后落地，不调用模型；没有预写操作或计划过期的，叫醒它；条件一直不满足、超过宽限或含无效引用的步骤标为受阻，也叫醒它；它参与或目击的新事件、它自己的闹钟，也会叫醒它；
4. 被叫醒的按急迫程度排序（约定 > 受阻 / 过期 > 到期 > 受影响 > 闹钟），同一地点合成一次调用；不同地点先冻结各自的权限上下文，再并行构思、按顺序校验提交，依据改变则作废重想；预算用完的留到以后；
5. 同一块里，刚被别人的决定牵扯到的 NPC（被告知、被拉进同一场戏）可以接着回应，仍算在预算里。

调查员身边的 NPC 也可因眼前事件或未兑现的约定主动行动；只有当场可感知的部分进入叙述。每个时间段有一个 tick id，记在记录里，同一段不会模拟两次；所有操作的 id 都是确定的。NPC 的已读边界取自构思时的快照，不能把并行期间别人刚执行的新事件误记成读过。

`Step.when` 支持 `&`（且）、`|`（或）及 `!`，例如 `at:players:jinboer_jia | at:players:mudi`。引用必须真实存在；旧存档中的错误 id 会明确受阻并唤醒角色重排。`achieved` 使用相同语法，表示执行后的完成条件，如 `at:thomas:mudi` 或 `owner:flashlight:调查员id`；预备的移动、交物操作会自动补相应条件。只写笔记、说已经出门不能将步骤标为完成，一组操作任一步失败都不会留下部分移动或虚假成功事件。

预算（`Budget`）：玩家的一个回合最多 2 次决定；一次长时间跳跃（≥120 分钟）最多 4 次。不需要模型的步骤不占预算。

有意义的当面消息、亲历变化和传话不必等游戏时间增加：对话结束后可以立即唤醒相关重要 NPC，执行仍受当前回合剩余额度限制。普通问候和道谢保留为记忆，不单独触发自主决策。时间推进和对话共用存档中的调用配额；长跳跃提高本轮上限，重试不会重置已用次数。`minds = 0` 仍能执行已准备的有效计划，不请求新决定。

各组的权限快照、调用预留和已返回结果随检查点保存。中途取消后，已完成的结果先检查版本再提交，不重复请求；尚未完成的调用已占用额度，只能用剩余额度重试。已落地步骤与完成凭据一起保存，模型等待不改变时间或检定。

决定是一次结构化调用，输出 `Scene`：每个 NPC 一个 `Decision`（注意到什么、怎么看、最多 4 个操作、多久后再想），多人时附一两句场面。提示词是新写的 `NPC_MIND_SYSTEM`。每个 NPC 只拿到自己的那一份资料（`context.npc_view`），它的操作还要过 `agents.vet`：只能决定自己去哪、改变自己对别人的看法、交出自己的东西、对身边的人说话和许诺、说自己知道的事。`CastBrain` 使用独立的 `world` 模型角色，与 `npc` 对话角色分开；未配置时继承最终的 `arbiter` 配置。会话无状态（记忆在记录里），会话键保留 `mind:<NPC id>`，用量记在 `mind` 名下、调用追踪标为 `world`；测试用 `Canned`。

## 台前与幕后（`stage.py`）

调查员眼前的场面归 KP 管，别处的世界自己过日子：

- **幕后**：调查员不在场的人照自己的打算行动，到点的安排照常发生，直接记进世界记录。不可预测性和自发的剧情从这里来。
- **台前**：会改变调查员眼前场面的事——有人走进来或离开、同行的人要走、有人对调查员或他们带着的东西动手、就在他们站的地方发生了什么——NPC 的决定、到点的安排和准备好的计划步骤都不直接落地，而是排成一段待演的戏（`Beat`），等 KP 上演：当场的反应马上演；会把调查员正在打交道的人带离现场的（离开、结束同行、死亡失踪）等这段交流结束，最多等 `HOLD_TURNS` 回合。上演时整段一起结算，结算完在这一轮叙述或插曲里讲出来（`Game._play`）。到时已经对不上的戏作废，它的主人重新想。
- **对调查员的承诺优先**：同行中的人只有调查员自己走动时才跟着移动，其他任何写入方（NPC 自己、导演、MCP）要让他离开，都得先当面结束同行（`ops.Move` 拒绝其余情况）；到点的安排缺了同行中的人照常进行，并告诉安排它的人。

一条规则对所有幕后写入方生效，不再为每种冲突单独写特例。

## 线头（`threads.py`）

每条线头有热度和最后推进的回合。`readiness` 给导演一个 0–1 的分数和一句提示：约定到期了；铺垫大多已经露出来，可以收线或翻转；很久没动静；矛盾在升温；还早。

## 检索（`index.py`）

- NPC 上下文另有不依赖模型的轻量词项检索：先按角色权限过滤事实与事件，再优先匹配本次可感知消息，辅以目标、在场人物和未兑现约定。近期片段与少量相关旧事同时保留，工作记忆超过 40 条后的旧事件仍可从完整世界记录找回。来源标签沿用实际学习事件、发言者与个人记录，不把传闻或推测提升成亲见事实。
- 调查员与 NPC 的交流保留完整授权原话，长台词后半的托付与约定也能检索；不写入调查员未说出口的意图。私下交流仍仅对参与者可查，不因保留全文扩大知情范围。
- 结构化查询：某 NPC 知道什么，某地某时以来发生了什么，涉及某人的有效约定，某人的关系，邻居（`networkx` 从关系和共同事件建图，按视角过滤）。
- 模糊回忆：和模组知识库同一个本地模型（fastembed bge-small-zh）嵌入事件和事实文本，不调用模型。向量按文本缓存在内存里，从记录重建，不进存档。没装 fastembed 时退回 jieba 分词重合度。查询前先按视角过滤，NPC 只能回忆起自己知道或见过的。
- LightRAG 只管模组原文（`knowledge.py`，不变）。评测里它的图检索在模组资料上不如普通向量（91.7% 对 95.8%），抽取要花钱、结果不稳定，也没有时间、撤销和“谁知道”。

## 各角色看到什么（`context.py`）

| 角色 | 内容 |
|---|---|
| 导演 | 重要 NPC 的位置、目标、计划；线头和提示；约定；关系；玩家还不知道的事实（带版本，供请求的 `reads` 用）；玩家已经知道的（带版本和怎么知道的，改要自圆其说）；玩家手里线索的原文和当初听到看到的样子（不能动）；安排；最近的事件（带 id，标出玩家亲历的）和改写 |
| 守秘人 | 此刻在场的人；这里看得出来的痕迹；调查员已经知道的；还没兑现的公开约定；调查员亲历的近事。没有秘密，没有计划 |
| 世界推演（`world`） | 每个 NPC 分列的自身处境、目标、知识和约定；每个操作仍按发起 NPC 的权限校验，不把同组其他人的秘密视为自己已知 |
| NPC 对话（`npc`） | 自己的身份和状况、身边的人、目标、心境、计划、知道的事（标出自己编的谎）、记忆、关系、约定、手里的东西、知道的地方 |

## 导演请求（`desk.py`）

导演的幕后方案是一组操作，加上它读到的版本（`reads`）。`submit` 时，内容完全相同的请求只留一个；关于同一批对象（`key`）的新请求取代旧的。`land` 前先检查：超过 `ttl` 回合的作废；读过的版本有变化的退回为过期，并列出变化的引用，由导演决定放弃还是带着新上下文重做。落地时全部成功才算，有一个被拒绝，前面落地的会被撤销。

## 接进游玩

| 地方 | 做了什么 |
|---|---|
| `Game.__init__` | 建 `World`（读档时在 `improv.restore` 之后，所以记录里 NPC 的位置会写回模组副本）；模组标了 `important` 的 NPC 落成 `enlist`；`cast.world` 指向它 |
| 每回合 | `remember` 里 `sync`（在日志折叠之前），开场讲完也 `sync` 一次 |
| 裁定员的 `changes` | `adapters.settle_changes`，旧的 `GameState.world` 账本照样同步 |
| NPC 对话 | `Cast.npc` 把台词里的转交、约定、关系也走 `settle_changes`；每次对话记一条公开事件（`talk:<回合>:<调查员>:<NPC>`），在场的人都看见，重要 NPC 记进记忆 |
| 导演的即兴 | `_land` 走 `improvise` 操作：写进模组、播种进记录、开线头；同一个方案落两次是重复，第二次什么都不做 |
| 时间推进 | `_time` 里 `_live`：把上次模拟到的时间（`WorldRecord.simulated`）到现在这段交给 `scheduler.advance`；在调查员眼前发生的事（NPC 走进来、到点的安排）写进 `Turn.world`，守秘人当回合讲 |
| 到达某处 | 离开一个地点时记下当时的 `seq`（`WorldRecord.left`）；回来时守秘人拿到“此刻在这里的人（以这一条为准）”和离开后留下的痕迹，模组的地点描写里写到、但已经走了的人不会再被讲成还在 |
| NPC 开口 | 系统提示由投影后的模组生成，NPC 新知道的事或被改写的秘密让它变了，就换一个新会话（对话记录还是那一份）；每次开口另附 `npc_brief`：状况、想要的、心境、正打算的、记得的、对别人的看法（-100..100）、和别的 NPC 的约定 |

**幕后的决定**：`CastBrain` 用 `world` 模型，用量记在 `mind` 名下，界面显示为“世界推演”。`[roles.world]` 可独立设置；未设置时跟随裁定模型的最终配置，原有预设无需增加必填项。配置里 `minds`（默认 2）是一个回合最多几次决定，长时间跳过是它的两倍；0 表示只照已经定好的计划走，不调用模型。调用失败就当没想，这些 NPC 留着，之后再问，不耽误这一回合。

**导演的幕后**：`Improv.backstage` 最多 6 条世界操作。`_plan` 先在游戏副本中校验模组补丁和全部幕后操作，有改写时再核对玩家已经知道的相关事实。失败后允许修正一次，不能删掉失败的幕后操作后单独发布模组补丁。当前行动等着的方案（`Game._ready`）两次都不过就重新要一个，首图画两次（`PREPARE_DRAWS`）不成就先上场景、图在后台继续画；最多等 5 分钟（`PREPARE_LIMIT`），仍没有能用的方案就不即兴、照常结算，存档记下这次放弃，读档重试不再等。这一局图像次数或预算用完时，场景不再等图。`_land` 在副本中准备世界操作、插件和必要首图；读取版本或等待期间的完整提交状态变化时，整包拒绝并重新准备。提交时写入恢复凭据后再通知界面，避免通知中断导致重复创建方案。验证、拒绝和提交详情仅写入本地开发者记录，不向联机玩家发送。

世界推演支持按需工具调用：资料不足时用 `world_query` 查询当前人物可知的旧事，或用 `world_preview` 在副本试算行动，再根据真实结果作决定。默认直接返回决定，不固定增加调用；每次最多两轮查询，超限则延后，不能执行中间回复里未完成的行动。工具读取与最初视角处于同一时间截面，追加读到的版本也参与最终过期检查。实际提交仍由调度器统一完成。

还没做的：联机时给玩家屏幕一份公开投影；存档详情页显示公开的近事。

## 风险

- 公开确认仅接受可追溯来源；同义转述须通过显式 `learn` 确认，不能由字符串重合猜测。漏掉确认的转述仍需结合公开记录排查。
- 撤销要求状态没被世界接口以外的代码改过；接进 `game.py` 之前，游戏里还有很多直接改 `flags`、背包的地方，撤销只适合同一次结算里的回滚。
- 每次操作都把记录序列化两次来算补丁，记录很大时会慢；需要时改成只比较改动到的表。
- 调度预算是同一玩家回合的调用上限，不是整局的；长局的总花费见实测。
- 幕后同场戏把几个 NPC 的资料放进同一次调用，模型能看到每个人的资料；靠 `vet` 限制每个人的操作，但台词和场面描写里仍可能串知识。
