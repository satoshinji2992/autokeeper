# 持久世界

`src/autokeeper/world/` 保存本局的事实、人物位置、知情范围、重要物品、关系、约定和日程。KP 读取全部主持资料，决定人物怎样行动、如何承接局势，再通过世界操作落实。记录库负责保存和核验这些变化，不另为每个 NPC 分配一个后台模型。

当前运行方式是 **纯代码日程 + 同一 KP 的幕后判断 + 按需 NPC 配音和导演备场**。独立 NPC 推演、模型调用配额和导演周期复查已撤除；Plan、裁定和 Telling 仍是不同阶段。具体迁移与恢复约定见[后台职责合并记录](harness-backstage-2026-10-24.md)，完整调用链见[模型与 Agent 运行机制](harness.md)。

## 模组、本局与知情

| 层 | 内容 | 修改方式 |
|---|---|---|
| 模组底本 | 目录里的 YAML、原文和原图 | 游玩期间不改原文件 |
| 本局世界 | `GameState.record` 及本局模组副本 | 通过世界操作、正式规则结算和已提交的即兴方案 |
| 角色知情 | 事实的 `known_by`、事件的实际参与者与目击者、个人观察记录 | 随实际学习、交流、观察和披露更新 |

开局由 `knowledge.seed` 建立实体与事实：真相、前史、人物资料、线索、地点须知和事件都有稳定引用，例如 `fact:truth`、`fact:npc:warden:secrets:0`。`knowledge.project` 将当前版本投影到本局模组副本，NPC、KP 和裁定员读取相应资料。导演补充的内容以 `origin="improv"` 保存；运行时改写不会反向修改编译产物或原模组。

世界真相、人物相信的事、人物说出口的话分别保留。NPC 可以知道钥匙在自己口袋里，却对调查员声称没有；台词不因此改变物品归属，也不让听众获得系统判定的真伪。

## 记录与存档

世界记录随 `GameState` 保存到同一份 JSON，回合检查点使用相同时刻的状态。复制、删除和恢复存档会一并处理记录，不另维护一份数据库。当前处于快速迭代期，不保证旧格式兼容。

| 记录 | 作用 |
|---|---|
| `entities` | 人物、地点、物件及实际位置、状态、持有与跟随 |
| `facts` | 事实全文、来源、知情者、公开依据、版本及撤销状态 |
| `relations` / `promises` | 关系、约定、期限和履约情况 |
| `threads` | 尚未解决的疑问、伏笔、冲突与计划线索 |
| `agents` | 重要人物的目标、心境、资源、认知、记忆和计划；它是资料记录，不是常驻工作进程 |
| `events` | 按实际游戏时间记录的事件、参与者、目击者、地点与行动区间 |
| `scheduled` | 到时执行的已写定安排和操作 |
| `backstage` | 待 KP 考虑的变化，附来源、发生时间和版本 |
| `beats` | 需要随当前场面交接的固定日程变化与提交凭据 |
| `sightings` / `item_sightings` / `place_sightings` | 各调查员最后实际观察到的人、物和画面 |
| `revisions` / `journal` | 改写的新旧版本、操作摘要、去重和撤销信息 |
| `requests` / `ticks` / `schedule_work` | 请求提交记录、已执行时间段和中断日程的恢复进度 |

联机客户端不接收整个 `record`，而是按玩家观察与受众生成投影。某位调查员以前见过一个 NPC，不代表他能继续获知对方未被观察到的新位置或死亡。模型后台能读到的资料也不自动投递到客户端。

## 世界操作与 KP 工具

所有正式变化走 `World.apply(op)`：先检查权限、引用和当前状态，再结算、记事件和日志，并更新本局投影。同一操作编号重复提交返回原结果；同编号不同内容拒绝。批量工具在副本中预演后整体提交，失败不留下半次交物或虚假的完成记录。

| 操作 | 作用 |
|---|---|
| `move` / `follow` | 改人物位置或确认、结束同行 |
| `transfer` / `bring` / `equip` | 转交物件、登记合理的现场日常物件、更新重要装备状态 |
| `fact` / `learn` / `remember` | 记录事实、实际获知与人物记忆 |
| `relate` / `promise` / `fulfil` / `break` | 更新关系及约定 |
| `occur` / `flag` | 记下实际事件、设置或清除已声明剧情标记 |
| `thread_open` / `thread_advance` / `thread_close` | 维护尚未解决的线头 |
| `enlist` / `plan` / `step` / `schedule` | 维护重要人物资料、计划与固定日程 |
| `rewrite` | 调整底牌并保留必要的原始证据与改写理由 |
| `improvise` | 正式提交导演准备的模组补丁；由既有备场通路执行 |

KP 使用 `world_query` 查询记录，`world_schema` 按需取得操作格式，`world_preview` 试算，`world_commit` 提交。宿主生成身份、请求编号与读取版本，模型不能自报权限。读取明确记录时可用 `scope=["entity:warden", "agent:warden"]`，避免每次拉取整份世界。

读取版本来自请求前的真实快照及已取得的工具观察。提交只校验相关依赖；查询和预演结果随回合保存，重试不会把一次旧观察悄悄替换成新事实。成功操作的最新版本返回同一 KP，后续不再沿用旧归属或位置。

世界工具不修改时钟、骰点、HP、SAN 或调查员规则状态，不直接分发模组线索。移动须符合已过去的实际时段；未来行为登记为日程。NPC 配音的操作仍以该角色身份检查，不能转交别人的物品或宣称知道自己没获知的秘密。KP 看到全部资料不改变这些人物自身的事实条件。

## 纯代码日程与幕后备忘

模组 `agendas` 和本局 `plan` 都可以保存两类资料：

- **结果已写定**：时间和前提满足时执行 `ops`，再核对实际完成条件 `achieved`。移动、交物、立标记不能只靠一句“做完了”完成。
- **届时需要判断**：保存动机、期限、前提和问题，不预先猜结果。到时生成幕后备忘，由原 KP 一次考虑相关人物。

见面时的招呼、允许搜查或被问起才说的话属于人物演出资料，`meet` 与 `once` 控制何时生效、是否仅演一次，不能当作幕后定时行动。前史保留为实际牵涉者知道的旧事件，也不因此替玩家公开。

`scheduler.advance(world, start, end)` 沿日程与条件边界推进，不调用模型。它执行有效的固定步骤，标明受阻或失效的安排，并将到期约定、需要判断的任务、重要见闻和没有后续安排的目标写入 `backstage`。同一时间段用 `tick` 和恢复进度去重，不依赖已经丢失的内存任务。

备忘只是需要考虑的事情，不是已发生的动作，更不是等待程序批准的剧情。KP 可以让 NPC 主动承担工作、改变目标、制造冲突，也可以判断暂时没有行动；需要实际变化时使用世界工具。主持成功落实本段后，只确认自己收到的那一版备忘，不把原计划标成完成。资料变更会产生新的版本，旧回执不能吞掉新情况。

各场景按自身游戏时间接收相关备忘，未来的事件不能提前进入较早的场景；已经在另一处参与场面的角色也不能由本场景同时安排。详细边界与离线回归见[后台职责合并记录](harness-backstage-2026-10-24.md)。

`conditions.py` 统一按有效时点读取条件：标记、归属、知情、承诺和人物状态保留结构化变更，位置使用实际移动区间。未知对象经否定仍不成立，过去写入不能覆盖已提交的未来变化；条件变化时点也参与日程边界。历史随操作一起撤销和存档，不依赖已裁剪的事件或撤销记录。正式事件立标记和结局门槛沿用这一入口。这不是任意世界查询的完整历史快照，不能据此宣称所有分队时间问题均已解决。

## 眼前场面的交接

固定日程若会改变调查员眼前的人、物或正在进行的交流，仍保留 `Beat` 交接（`stage.py`），在合适时机随场面落实。KP 可以上演、暂缓或撤回，提交前复核原前提和读取版本；不再通过固定输入轮数强制让人物离场。未成立的安排向 KP 保留具体原因，不假装已经发生。

同行记录保存在 `following` / `follow_to`。邀请不等于同意，NPC 的明确回应或 KP 的实际场面操作才确认同行；改变主意也须明确结束原承诺。物品转交使用真实物件，临场发言不能替代归属变化。

KP 主动提交的世界操作直接返回真实结果；这里没有另一位独立 NPC 决策者，也没有导演审批队列。`Beat` 只承接仍需与现场衔接的既定变化，不能把它误当成已移除的后台模型。

## NPC、导演与正式遭遇

NPC 配音保留自身会话和知情范围，在台词的同一次结果里提交当场动作、约定、物品及目标变化。在场 NPC 的主动参与由 KP 随局势决定，不必等调查员点名；远处人物的新判断也交回同一 KP，而非各自循环调用。

需要完整新地点、遭遇、人物或特殊规则时，KP 使用 `director`，用自然语言说明需求。导演沿原准备流程校验模组补丁、世界操作、插件和必要首图，再整包提交；等待期间状态变了就重新准备。当前行动依赖的内容就绪前不提前结算，模型等待本身不增加游戏分钟。原方案及提交凭据保存在工具回执中，恢复不重复创建内容。

正式打斗或追捕由 `encounter_schema` / `encounter` 启动。已有参与者必须在场，尚未实体化的模组生物可在这次正式开局首次现身；既有遭遇不能重置。NPC 首轮意图写在 `npcs`，不替调查员填 `opening`。伤害、应对、速度与理智仍走原规则和回合制，不能用故事文字直接击伤玩家。

## 知情、检索与改写

KP 读取全部底牌和本局记录；NPC 只获得自己的身份、所知、记忆、目标、关系、约定与实际持有物。导演按当前请求读取准备资料。给调查员的正文、个人补充、图像和材料分别列真实受众，公开事件也按发生时的目击者记录。

原文检索与本局记录用途不同：LightRAG 查询模组资料，本局事实通过世界记录和按权限过滤的检索找回。检索、摘要、传闻或计划都不直接等同于世界事实。事件保留时间和出处，个人记忆的压缩不删除正式记录。

公开确认使用可追溯的实际来源，不凭人名、地址或短句重合就认定整段秘密已经公开。私下交流不自动变成旁听者的知识；NPC 撒谎也不将真实答案传给听众。

KP 和导演可以改写尚未披露的真相、动机与幕后安排，也可以为已见现象提供另一种解释，但须保留原始证据：玩家手里的材料和已讲过的原话不被抹去，相关改写要说明当初为何出现这些证据。改写底牌不顺带移动人物、转交物品或制造玩家知情。当前改写附在原文查询后，冲突以本局版本为准。

程序保留事实来源、引用、版本与已取得材料等确定性校验；不为每次改写另调模型审批，不以“模组始终可解”否决损失。证人可以死亡，路线可以中断，调查可以失败；KP 或按需导演仍可创作有来源的新线索和新路线。

## 测试与限制

操作、知情、检索和投影由 `tests/test_world.py`、`tests/test_world_tools.py` 等覆盖。`tests/test_keeper_world_tools.py` 验证同一 KP 的查询、修改和恢复；`tests/test_keeper_backstage_runtime.py` 与调度测试覆盖日程及备忘交接；`tests/test_keeper_director_tools.py`、`tests/test_keeper_encounter_tools.py` 覆盖备场、正式遭遇与受众。编译资料、真人长局和叙事评测仍需单独验收。

本次实现仅使用脚本模型、临时存档和假骰离线验证，没有新增付费模型测试。它验证操作能落实、恢复不重复及信息投递范围，不能证明 NPC 已更有创造力，也不能给出新的费用或延迟结论。长局中 KP 是否及时处理任务、是否保持人物一致性与恐怖节奏，仍需实际模型和多人游玩验证。
