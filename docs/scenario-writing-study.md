# 剧本写法研究：守秘人与导演

本轮以 CoC 剧本为样本，研究开场、调查结构、人物行动和节奏安排，为 AutoKeeper 的守秘人与导演提供设计依据。优先选择民间作者作品与作者实录，官方入门短本作为对照。记录日期：2026-10-19。含结构性剧透。

### 已读作者访谈带来的具体方向

在 [Febri 对まだら牛的访谈](https://febri.jp/topics/nakedpeak2/)中，作者谈到登山经验与宇宙恐怖的联系，也指出推进、退却、生存等反复出现的抉择使玩家与观众产生紧张感。这是作者对创作的回顾，不能代替对模组正文的分析。

由此提出一个可检验的设计方向：让同一种处境随资源、路线和关系变化，持续产生不同的选择，不必每轮增加怪物或异响。对 AutoKeeper，可用自编登山场景对照“继续前进／扎营／撤退”，检查各方案的条件与后果是否来自同一份世界记录；这属于本项目的推论，尚未验证。

### 实录研究方法

每个作品同时记录“原模组安排、KP 当场补充、玩家造成的变化”。剪辑版另标注省略与后期演出，不以成片流畅度推断原团始终流畅。先对《人集市》《竖棺材》各取开局、一次完整日常交流、一次调查受阻及一次关系变化；再用《沼男是谁？》不同版本对照同类情境。每条观察保留集数、起止时间及可复核的行动结果，不只摘录漂亮台词。

新增三组待评估情境：玩家拒绝与预设重要 NPC 亲近时，关系是否仍能自然发展；同一 NPC 被帮助或被背叛后，后续计划是否出现可追溯的差异；玩家提出第三种解决办法时，导演能否按条件裁定，而非强行恢复原定两难。

## 三个样本给出的启发

### The Lightless Beacon：先建立来意，再让准备产生作用

角色有各自的旅行目的，也可与灯塔人员建立联系。修理、求援和调查会影响后续处境，探索因而具有实际价值。其一小时分段表适用于短场，不能当作自由模式的固定事件时刻。参见上列 PDF 第 6–11、21–23 页。

对本项目的启发：开场先让玩家理解自己为何在场、眼前需要处理什么；导演记录行动造成的条件变化，守秘人呈现这些变化。求援与准备必须进入世界状态，随后兑现，不能只成为描写。

### The Dead Boarder：共同现场可以容纳不同利益

预设角色进入同一房间，却有租金、书籍、账目等不同牵挂。怪物也有明确的争夺对象，战斗存在逃离和放弃争夺的处理空间。剧本另以计时和警察到场控制收尾，具有演示场次的用途。参见上列 PDF 第 5–10、16–17 页。

对本项目的启发：把“为什么参与”与“想获得什么”分别记录。借鉴其目标设计，让重要人物选择夺取、隐瞒、撤退或求助；不把“到高潮时间了”作为袭击或救援的充分理由。

### The Haunting：调查提供认识，敌人根据利益作出反应

房东先说明委托与报酬，调查可从不同机构开始。报社一节明确指出：既然取得档案访问权已经经过检定，就不应再以一次检定阻挡其中的线索。屋内威胁则与敌人保护秘密、误导调查的意图相连。参见上列 PDF 第 18–22、26–28 页。

对本项目的启发：保留多种调查方向，避免同一成果被连续检定反复阻挡。导演应解释事件由谁、为达到什么目的而发动；守秘人只呈现调查员能够观察到的部分，不替玩家总结真相。

## 在 AutoKeeper 中如何使用

以下是设计建议，不代表相关能力已全部实现。

| 需要改进的行为 | 实现与审查位置 | 判断依据 |
| --- | --- | --- |
| 开场直接进入主线，缺少来意和环境 | `module/importer.py`、`agents/director.py` 的开局改编 | 玩家能理解来意、所在位置及眼前处境，并保有行动选择；赶路可压缩 |
| 重要人物只有背景，缺少行动 | `world/agents.py`、`world/scheduler.py` | 人物有目标、可用手段、触发条件和退出条件；受阻后重新决策 |
| 世界推进与戏剧安排混在一起 | 世界记录、调度器和导演方案 | 每次变化可追溯到条件、行动者与结果；未被玩家感知的幕后变化无需插播 |
| 调查变成逐项点击和重复掷骰 | 线索结构、裁定及导演补线 | 不重复阻挡已取得的成果；失败后的替代路径具有不同成本或信息，而非凭空发答案 |
| 日常场景总被转成危险或主线提示 | 导演展开、`keeper-craft` | 吃饭、问路、投宿可以自然结束；危机来自已有因果 |
| 结局只宣布成败 | 结局叙述与世界记录 | 回应玩家实际改变的人、关系与处境，不补造未发生的行动 |

本轮提示词调整已处理固定感官清单、强制悬念、NPC 固定口吻、篇幅凑字数，以及系统说明过度口语化的问题。上表涉及的开场结构、人物规划与世界调度，需要另做行为评估，不能仅靠润色提示词宣称完成。

## 下一轮评估用例

使用自编场景重现结构问题，不将出版剧本全文写入提示词。先固定世界、角色目标和公开信息，再改变玩家行动；保存输入、输出与状态差异。以下用例尚未执行：

1. **初到小镇**：玩家先投宿，或直接去委托人家。两条路径都应成立；住宿不强制触发袭击。
2. **取得档案访问权**：访问检定成功后，读取明确存在的资料不再增加同目的检定。
3. **放弃争夺物**：敌人以夺回某物为目标。玩家交出或丢下物品后，敌人须按目标和情境重新选择行动。
4. **提前求援**：对照有无成功求援的两局，检查援助是否按交通、通信和既定安排到达。
5. **玩家离场**：重要人物在幕后继续计划；没有感知途径的调查员不应收到现场描述。
6. **问题已解决**：允许平静收尾，不自动添加反转、异响或新敌人。

评估分别记录因果是否成立、玩家选择是否保留、公开信息是否越界、前后状态是否连续，以及阅读感受。现有 `eval/style.py`、`eval/blind.py` 可辅助比较文风，`eval/experience.py` 可作为体验评估入口；这些检查不能替代真实游玩反馈。
