## 已确认的共用漏洞

### 同一次检定有两份结果

花幸运时，持久检定记录被改成成功，回合里的原始 `Check` 却仍是失败。界面显示扣点、成功，NPC 输入却明确收到“说服失败”，KP 也可能按失败叙述。这解释了几次成功未兑现，不应归咎于角色不肯让步。

修复保留原始掷骰，在同一个结果上登记幸运修正；合并回合时替换旧结果，不追加一次虚构掷骰。存档恢复、NPC 消息和 KP 报告使用同一最终结果。真实复测已确认新的幸运成功正确进入 NPC 输入。

### 状态型 NPC 回复被当成纯台词

旧 `spoken()` 只判断必填字段是否只有 `text`，便关闭 JSON 模式，允许纯文本直接包装成 `{text}`。NPC 其实还要交付物品、登记承诺、标记已透露线索；这些字段变成了可随时丢弃的附件。《追书人》因此已经听完整段自白，记录里却没有取得真相，理智与结局条件也没有结算。

另一条解析路径只取第一个合法 JSON 对象，随后出现的台词或状态字段被直接忽略。现在只接受完整的结构化回应；残缺封套走原有一次格式修复，不能把私有意图或半份结构直接展示为对白。纯文本任务仍可正常使用纯文本。DeepSeek 的 JSON 传输模式也确实出现过连续空白；原有格式修复会改用提示约束的 JSON 传输，输出校验与状态合同不变，不通过降级丢字段恢复。

### 决定提前变成历史，已演内容反而没有交接

裁定员曾在 NPC 回答前，就写入“取来灯绳并交出”“名单已交付”。NPC 读到正式事实后，把本轮首次交付演成上午已经发生。裁定职责现明确限于规则与调查员自身实际完成的后果；NPC 的交付、承诺与履约由本次回应和 KP 场面落实。

反方向的问题也存在：KP 扮演过站务员、写过医生取来地图，独立 NPC 会话却没有获得这些当场见闻。新增可选 `scene.observations`，由 KP 明确提交内容及真正知情的 NPC，复用事件库和记忆。它不抽取正文、不生成物证、不向后来到场的人广播，也不增加模型调用。摘要明确作为压缩索引，当前正式记录优先。

### 行动引用和执行边界不完整

一次完整的“休息后与队友去会堂”已被 KP 正确理解，但队友 ID 拼错，程序把它当成不在场的 NPC，整条行动被阻断。现有计划校验补上人物与地点引用，交回原 KP 修正，不为某个拼写设置特殊别名。真人队友也不再进入 NPC 同意流程。

其他修复包括：预设卡技能在输入边界统一名称；已取得的手稿可以明确登记为持有实物；公开检定目标与私有裁定依据分开；状态操作所需的角色 ID 由宿主明确提供，不让模型猜。借物定向复核已得到实际入账的油灯与绳子，透露真相的回复也保留了 `told`；这些是短探针结果，整局仍在验证。

去重判断还有一次误伤：裁定员已经说明请求改变、有新筹码，允许再掷，引擎仍只按同一个 NPC、同一个技能套用旧失败。现在记录中立的尝试内容，程序不再把不同请求认作原样重掷；近期检定也带上当时尝试，供裁定员判断真正重复的行动。

### 场外事件覆盖玩家行动，时间重复计算

原定时事件会把已经逃走的玩家送回原地点，重复战斗或收尸。事件现在有实际发生地：异地事件进入世界记录，不搬运调查员，也不向远处玩家展示现场或结算在场伤害。

原作要求醒来或离开时已入夜，但只有正文、没有时钟结算；新增的 `advance_to` 用实际时钟、日程与恢复流程落实。复测又发现，抵达事件跳到夜间后，原行动耗时还会再加一次。现保存行动预计结束点，以实际已推进时刻与该结束点合并；失败的额外耗时仍另算。事件本身是否误把“刚到入口”当成“探索全部结束”，属于另一项触发语义问题，不能靠减几分钟掩盖。

## 没有采用的做法

本轮没有新增叙述删句、关键词禁令、在线语义审稿智能体、固定回合催剧情或 NPC 性格阈值。运行时保留身份、位置、归属、掷骰和提交恢复的确定性校验。确需修改自带模组时，只修已核对原文的条件遗漏，例如击倒后的分支误接到礼貌问候、外观检查混入解剖所得；这些不是为了让某局通关而降低难度。

KP 提示允许依据局势增加人物、关系与可追查细节，由记录承接；日常活动不必另请导演备场。空的模组线索清单不再被解释成“成功没有效果”。NPC 可以主动帮助、设局、改变目标，玩家也可以拒绝其新提议。是否形成完整、紧凑而有变化的故事，仍需后续整局结果验证。

## 验证与未解决事项

提交 `afed67f` 的全仓测试 **2156 项通过**，Ruff 与差异检查通过。第二批 `62a24d6` 的最终全仓测试 **2182 项通过**，耗时 369.60 秒，另有 4 项既有的多线程进程 `fork` 弃用警告；该批 Ruff 与差异检查也已通过。真实模型定向检查与完整游玩分开统计，不用短探针代替通关。

`d76e56e` 全量 **2213 项通过**；之后现场职责、主检定引用和提示规范一批的最终全量 **2240 项通过**，耗时372.75秒，仍为4项既有 `fork` 警告，Ruff、技能校验与差异检查通过。中间一次全量的人物照片选择测试等待超时（2227过、1失败），该项单独复跑通过，最终全量也通过；本轮没有修改照片代码或延长其等待参数，暂保留为时序稳定性观察。

目前仍须验证：整段真相、物品及奖励能否完整落地；NPC 台词与随后叙述是否仍相互否定；复合行动是否准确停在需要玩家决定的位置；正文给出的具体姓名、日期、方位能否真正交付；幕后时限是否形成可应对的压力，而不是反复拖延。三局没有固定条件的 0.0.2／0.0.3 对照，不能据此宣称整体已经优于旧版。

其中一项需要继续调整主持分工：目前的 NPC 主动安排产生于检定之前，角色配音却发生在检定之后。孤注一掷失败已经裁定“被当场抓住、逐出”，配音仍可能沿着先前“对方走开”的安排表演，最终旁白再演另一套结果。幸运修复不能覆盖这种分叉。后续应把已结算结果及角色真正可见的后果交接清楚，让 KP 负责统一场面、配音负责演出同一场面；不增加一个逐句审稿角色，也不把所有幕后依据发给 NPC。

### 调用消耗与幕后重复唤醒

《冬雪之下》fix1 截至第 85 轮的累计记录是 602 次调用、约 $1.9641，其中幕后 `mind` 120 次、约 $0.5428；规划 105 次、NPC 配音 118 次、KP 97 次，导演只有 4 次。这包括开场、格式修复和读档后的继续，不是固定输入的性能基准，也没有与旧版同条件对照。

第 82–85 轮的诊断显示，人物观察到同伴在门边或过道口改变站位，会再次唤醒；对方随后作出日常反应，又成为下一次幕后推演的输入。另有过时的执行失败继续作为重试原因。这是因果调度与主持分工的问题，不能仅归因于故事篇幅或导演过于发散。

当时尚未修改这部分调度。后续需要明确当前 KP 已处理的现场变化、尚未处理的新见闻，以及真正需要在换场或跨时间时集中安排的任务。不能简单把所有在场人物冻结，也不能一律推进“已读”指针而吞掉从未交给角色的新事件；没有通过调低调用预算或增加冷却掩盖重复工作。

后续已按现场职责作出调整：有效 KP 安排接管本轮当前现场的全部 NPC，普通站位或旁观不再另起幕后决策；没有有效安排、安排失败或人物已经离场时仍保留后台路径。固定日程照常处理，眼前动作仍沿既有待演路径提交。没有修改 `Agent.seen`、事件反应属性或调用冷却；旧见闻保留，离场后仍能被后台读到。对应简报取消未完成安排的前三项及80字截断，完整交接受阻状态、前置与完成条件、经过及上次执行失败。代价是主 KP 上下文会更长，实际调用与费用变化需要后续真局记录，不能用单测推算节省比例。

没有为同一 `advance` 另加动态参与者容器：现有流程中，焦点人物离场先排成待演，世界推进结束后才落实，下一次推进自然重取实际位置。不为尚未实现的跨场并行增加一层机制。

## fix3 封存后的共用职责修复

这些改动用于后续复测，不倒改上述三局结果。

- KP 的场面输出补上 `scene.flags`，通过既有私有 `SetFlag` 登记已经成立的模组剧情事实。此前场面只能提交人、物与见闻，人物回应后的完成事实只能等下一轮裁定补记。场面被拒、部分降级或实际提交过期时，不提交依赖该场面的标记。引擎仍结算数值与终局奖励。
- 新标记引出的事件保存在当前叙述的后续回合记录中，复用事件表演与叙述流程；表演中断、奖励通知中断后可以恢复，不重掷、不重复原行动。没有新事件时不增加叙述调用。真实 DS 的两个独立合成探针分别确认“已经停钟”会提交事实、“只是请求而遭拒”不提交；它们不算完整游玩通过。
- 日常行动不再因为 NPC 回答一句话就跳过后续 KP 场面。快捷结束限于纯交谈或明确闲聊；没有增加独立意图审查。
- 明确的待演 `play` 仍由 KP 决定，但其公开后果必须在裁定前展示，已不在现场的交谈对象不再被按旧位置掷骰。fix3 T19 是 KP 自己选择先让人物离场，不是后台擅自抢走人物；错误在改变后的场面未被后续裁定贯彻，不能据此冻结所有 NPC。
- 归还与消耗统一解析实际物件的 id／唯一显示名，不能一边保留 `thing:*` 原物、一边新建显示名相同的裸名影子。普通物件被纳入重要装备维护时原地更新；确有同名多件时使用实际编号，不靠模糊猜测或从正文抽取。

### 没有用提示顺序掩盖的分歧

《油盐》fix1 第 62、68 轮的 NPC 输入已经明确包含本次失败和请求范围，仍曾答应同一个请求，随后旁白按失败拒绝。它们与幸运结果漏传不同。为检验是否只是重要结算埋在长背景之前，另用两个已封存的完整输入作了八次 DS 对照：原顺序与“背景在前、当前请求在后”各重复两次，模型与 schema 不变，不修改在玩存档。

原顺序复测也多次正确拒绝，换顺序仍可能提出与已结算后果不一致的送医安排；小样本没有证明调整顺序能消除分叉，未据此修改运行提示或宣称修好。原始对照保存在本地 `npc-order-probes.json`。后续应收敛同一场面的决定权与执行时序，明确已经结算的动作由谁安排、独立配音只负责哪一部分，不能继续给具体角色加“失败时拒绝”的专用规则。

## 第三批：实际操作引用与完整排查记录

《追书人》fix4 的 T4、T9 和《冬雪》fix1 的 T95 不是同名影子的简单复现。裁定把放回物件写成 `equipment.status`，或使用了物件名称的简称；KP 又把抽屉、门外凹处写成未登记的归属地点，把新物件的“拿出者”写成地点。核对失败后，下一稿改成物件仍在手中，已经展示过的放置或交接与状态再次分离。

修复补充的是操作所需的上下文：只给相关角色送达本场面的实际物件编号、完整名称、归属与数量；NPC 的普通物件仍限于自己的清单，不扩大其知情范围。`holds` 明确承接拿起、交出、归还和放置，`things` 指首次拿出新物件的人。地点内的细部位置不能代替地点编号，交出物件也不等于把总数量改为零。不从叙述抽取归属、不扩展模糊匹配、不增加语义审批员。

两个独立 DS 合成探针分别确认“实际放下”将两件物品移到地点、“仅承诺稍后交付”保留在调查员身上，均保持数量1，各调用一次 KP，合计约 $0.0034。探针不修改正在玩的存档，也不能作为真实整局已覆盖的证据；脚本最终保存结果时遇到 `deque` 序列化问题，已从该探针自己的完整诊断恢复调用记录，没有为了补文件重复付费调用。

《冬雪》T91 还暴露了一种无效检定引用：裁定员输出 `needs_roll=false, repeat=true, skill=''`，引擎便匹配了同 NPC 的旧说服失败，尽管本轮只是记录已经同意的实验。现不再把空技能当成任意技能的引用；提示也区分“无需掷骰”和“复用具体检定”。不因此强制新掷骰，也不撤回旧失败。

《油盐》T99 的交接还有另一个通用断点：KP 保留玩家的魅惑方法，裁定员按模组改用说服后，`_social_result` 仍要求骰子技能等于最初的 `Action.approach`，因此漏掉给 NPC 与 KP 的最终社交结果。进一步离线复现发现，只改成取同技能末项仍不可靠：主交涉成功后，同轮事件的说服失败会再次覆盖它。

现用 `Turn.primary` 明确指向主行动的检定，普通行动、幸运修正、孤注一掷及保存恢复沿用同一引用，事件自己的骰子不冒充主行动。社交演出读取最终主检定的实际技能和结果，心理学观察仍不向被观察者透露。只触发事件检定的回合也不再误结算历史主记录或因列表为空报错。这里没有强制裁定员采用玩家指定的技能，也没有更改难度；它只能修复结果交接，不能冒称已经消除所有台词与旁白分歧。

同一交接覆盖孤注一掷更换技能后的实际第二骰，不能仍引用第一次失败。成功的说明不再混入“本次失败”，失败的说明也不再一概要求不得增加敌意，改为保留已裁定后果、不额外追加惩罚；不把完整后台失败剧本或隐秘原因交给 NPC。

《油盐》T106–107 的成功观察只说“完整字母”，追问又被巡查新戏盖过去。此处先收紧原有叙事职责：本轮已经成立的发现须完整交代，可读内容给出实际值，澄清先回答；原文或记录没有预写的细节在获准范围内即兴确定并记入现有场面。没有增加自动线索总结、关键词检测或逐句审稿。此提示尚待后续真实连续游玩检验，不能据新增措辞宣称信息遗漏已消失。

### 开发者日志的轮转遗漏

长局到达200MB后，旧实现反复覆盖唯一的 `.1.jsonl`，而网页的读取入口只读当前文件。早期模型输入会从查看器消失，继续轮转还会实际丢失。现改为递增编号分段，读取与前后翻页共用跨段的连续游标，恢复已有 `.1` 的可见性，分段不再互相覆盖。已经被旧版覆盖的历史不能凭空补回；本次已先备份仍可取得的原始归档，定向提取相关调用保存为忽略的证据文件。

### 即兴准备完成后的行动交接

《油盐》T81 的空检定说明并非模型漏填：裁定员明确输出“不掷骰，只是正常托付；新锯木厂需准备”，导演准备好新地点后，`Game._steer` 从新增线索的门槛自行拼出了说服检定。它没有重新确认此刻行动的对象、公开目标与失败风险。

不能用通用理由补空字段，也不应调低该人物的难度。现在将已准备场景、已经完成的出发前交谈、原始请求交还同一个 KP，只安排尚未执行的部分，再由原裁定接口处理实际的新行动。新条件需要玩家选择时可以只抵达现场，不自动掷新增线索的门槛。已有交谈与同意沿用提交凭据，行动与裁定一起保存；中断恢复不重新准备场景，也不沿用旧 NPC 作为新检定对象。

这条交接只用于即兴产生了新的目的地或带条件的候选线索，不给普通交谈增设调用。三项定向回归覆盖新对象和技能、完整公开风险、出发前步骤不重演、中途恢复，以及只呈现场面而不替玩家接受条件。旧局结果照实保留，尚不能据此宣称真实连续游玩已经覆盖。

独立 DS 合成探针中，KP 最终选择先去新登记处，没有自动掷线索门槛，也没有重演已经完成的托付。第一稿曾把尚未抵达的档案员登记在眼前，并引用不存在的待演编号；既有确定性校验退回一次后得到有效移动。两次规划调用约 $0.0025；这是接口验证，不算整局体验通过，也说明新交接仍可能需要一次纠正。

### 多人分开行动的实际位置

《油盐》T90 的行动已有 `alone=true`，但普通移动仍更改全队共用地点，另一名调查员也被当成已经去了那里。下一轮切换玩家时，又继续使用上一处的交谈背景；这是位置与主持焦点混在一起，不是玩家表达不够清楚。

普通移动现先保留所有人的实际位置，仅移动同行组，独行只移动行动者。换玩家时将主持焦点切到其实际位置，不额外走路、推进时间、触发到访或改写旧见闻。NPC 资料、物件可见性及实际交接使用个人位置；现场事件和怪物目击仅向实际能观察的在场者结算理智。事件引发移动或通知中断后，沿用已保存的目击者，不能把目的地原有玩家补算为旧事件的目击者。终局全队奖励、远程实际阅读材料的理智结算维持原有含义。

本次实现的是普通场面的顺序切换，未实现多条并行时间线或异地同时战斗；尚未完成的遭遇不允许通过切换异地玩家丢弃。定向回归同时覆盖三人分组、同行 NPC、读档、私有见闻和遭遇边界，未用旧局补改位置充当试玩通过。

## 仍需收敛的行动表达

《油盐》T112–113 的“交谈后陪同休息到指定时间”只做了交谈；T114 单独声明等待后，时钟正常推进。这不能归因于 NPC 不愿合作，也不应靠识别时间格式强加等待。现有 `Action` 主要表达一个动作，出发前交谈是少数已有顺序表达；尚不能稳定承接每种复合请求。后续应让 KP 沿原请求继续处理尚未完成的部分，或明确停在需要玩家决定的位置，复用已有步骤记录，不能为每个分句另起一个角色。

另一个不同问题是风险移动：原来的普通 `move` 直接免裁定，而且通常先走到目的地再检定。它适合“去书房查找”，却不足以表达“先避过看守，成功后才走出去”。现由 KP 在既有行动中明确 `arrival_after_success`，先在出发点裁定，真正成功后才消耗路程、移动和到访；普通移动和先抵达再调查的顺序保留。失败、放弃、幸运、孤注一掷与恢复复用现有结算，不新增执行队列或时间账本。22项定向回归覆盖中断、同行、路线不可用、沿途暂歇，以及到访事件再次搬运后的恢复；这一批尚未并入上述2240项验收。

另用三个独立的真实 DeepSeek 规划探针检查“先避开看守再离开”“普通回广场”“去办公室再找登记”。三次均正确选择执行顺序，各调用一次规划，合计约 $0.0027；没有执行掷骰或修改正在玩的存档，不能算作整局通过。未对守卫难度、NPC 性格或关键词调参。

《油盐》T117 出现另一类公开泄露：双胞胎把注明“只有两人听得见”的密谈原话写入 NPC `text`，实际投递却是公开回复。这不是世界给 NPC 看了他不该知道的秘密，而是输出没有遵守读者视角。此次明确 `text` 只承载当前收件调查员可感知的内容，每次调用附实际收件人；私有意图继续使用已有心境、计划及欺骗字段，不另设台词检查员或删句机制。真实后续表现仍需观察。

本批第一次全量为2262过、1失败：严格 schema 的手写测试样例没有为新增布尔字段提供布尔值，校验器按预期拒绝空字符串。更新样例后，最终全量 **2263项通过**，耗时373.94秒，仍为4项既有 `fork` 警告；Ruff、技能与差异检查通过，没有放宽类型校验。共用职责和下一步取舍见[架构决策](harness-playtest-decisions-2026-10-23.md)。
