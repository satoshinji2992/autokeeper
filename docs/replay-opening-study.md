## 对 AutoKeeper 的判断

### 开场需要一个能由玩家接手的处境

这批片段中的可用结构是：角色有来意，眼前有具体需要，玩家有机会决定先处理什么。对《追书人》，可保留信件和赴约目的，让车站、行李、路程与食宿成为可以参与的场景；玩家直接赶路时则概述沿途。不能为了复制样本的等车空档，给所有模组增加班车延误或等待任务。

开场结束时应能回答三个问题：玩家已经知道自己来做什么吗？眼前的人和地方足以支持一次具体行动吗？下一步仍由玩家决定吗？场景可以保留安静，也不必预先展示全部路线。

### NPC 的独立性先体现在眼前的利益与行动

在游戏中，重要人物的长期计划需要世界系统处理；这些片段还提示了更小的单位：一个人这次为什么接话、想促成什么、交谈结束后会继续做什么。新 NPC 的身份、目标和说话方式应互相支持。店主可以关心成交，邻里可以提供自己熟悉的去处，人物也可以无事相求。

拒绝推销、帮助或邀约后，先更新这次交往的结果。后续反应依据人物、风险和已有关系决定，不能自动升级为敌意、追赶或新的委托。这也不意味着任何 NPC 都必须温和接受拒绝。

### 日常信息需要保留来源和立场

给出消息时应区分亲历、转述和个人判断。多个 NPC 提到同一件事，可以帮助玩家寻找来源；重复传播本身不证明传言为真。守秘人不应将人物说法改写成全知叙述，导演也不能以“丰富地方生活”为由绕过线索权限。

对结构化记录，应保留“谁说了什么、从哪里听来、玩家实际确认了什么”的区别。当前 NPC 对话和世界记录是否完整保留这些区别，仍需单独验证。

### 联系已有事物，比不断增加新事物更有用

生活场景可以使用已出现的人、商店、道路和关系。玩家表达预算、职业或兴趣后，优先从既有内容中寻找合适的回应；确有空缺再即兴补充。再次提到一个地方应增加具体角度、来源或交往结果，避免不同 NPC 轮流复述同一段介绍。

### 回顾应帮助玩家整理，不替玩家完成推理

需要确认方向时，可按玩家请求提供已知人物、消息来源和未完成约定。玩家自己形成的判断应与已确认事实分开。主动提出另一个目标、选择休息或讨论方案，都不能仅因没有新线索而被判定为卡关。

## 不直接移植的部分

实录中有熟人桌的调侃、对玩家采购的提示和明显的表演加工。它们不适合作为系统的默认口吻。角色建立阶段由 KP 与玩家商定的背景，也不能变成游戏途中擅自补写调查员经历的理由。本次没有观察到后期高潮及重要人物的完整行动线，对自主 NPC 与长期导演规划暂不作有效性结论。

## 本轮修改及后续验证

本轮将以上判断用于三个位置：

- `agents/director.py`：根据来意与眼前处境展开，优先利用已有联系；区分消息来源；日常拒绝后的反应遵循人物动机。卡关推进先判断缺少信息、入口还是方法，再补必要内容。
- `skills/keeper-craft/SKILL.md`：补充交接行动、人物视角和回访的处理要求，保留系统裁定与信息边界。
- `eval/blind.py`：评判角色是否承接玩家并保有立场；允许问题完整解决和平静收尾，不因多加疑点或动作而加分。

这些是提示词和评估标准的调整，不代表已实现人物自主性或验证了游玩质量。下一轮用自编场景作成对比较，避免将样本人物和剧情搬入模组：

| 对照行动 | 应检查的差异 |
| --- | --- |
| 同一开场先投宿／直接赴约 | 两条路线均成立；后者不被强制拉回日常演出 |
| 同一次推销接受／谢绝 | 记录不同交往结果；无依据的报复、纠缠或自动接受均算问题 |
| 同一请求强调预算／强调赶时间 | 回应确实考虑玩家条件，不只是换词重复推荐 |
| 听到传言／找到原始来源 | 人物说法、传播次数和事实确认分别处理 |
| 回到已见店主／拜访新店主 | 回访利用真实交往记录，初见不假装熟识 |
| 主动休息／反复尝试无效方法 | 前者保留时间推进，后者才判断是否需要补入口或说明限制 |

既有回归测试可验证提示词装配及相关状态行为。成对模型试玩和人工体验评估尚未执行，不能用测试通过替代。
